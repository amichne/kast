Choose the search tool that matches your intent.

<Note>
  Every search uses the session workspace's saved, indexed IntelliJ state.
</Note>

| Intent | Tool |
|---|---|
| Known class-like declaration name | `kast.search_classes` |
| Known function or method name | `kast.search_functions` |
| Unknown/mixed kinds, properties or type aliases | `kast.search_declarations` |
| Compiler diagnostics for a file or directory | `kast.check_diagnostics` |
| Enumeration, returned references or ordered transformations | `kast.query_symbols` (deferred) |

## Find your first declaration

Call `kast.search_classes` with:

```json
{"class_name":"OrderService","name_match":null,"scope":null}
```

The same input works with `kast tool search_classes < request.json`.

Use these request rules:

- Use `function_name` with `search_functions`.
- Keep every control field present.
- Use `null` for exact, case-sensitive matching under recursive directory `.`.
- Expect the default source sets to be exactly `main` and `test`.
- Use a package scope when a simple declaration name needs qualification.
- Set `"name_match":"fuzzy"` explicitly because Kast never retries fuzzily.

Each match retains its name, location, completeness evidence, and opaque
`symbol_ref`. The nullable `signature` field is unprojected by default; retrieve
it explicitly with `query_symbols` using the returned reference.

Matching overloads remain separate.

`symbol_ref` repeats the exact bytes in `ref.token`.

| Identity | Use |
| --- | --- |
| `symbol_ref` | Authorize a later operation within its retained scope |
| `symbol_id` | Compare the same declaration within one saved snapshot |

Different overloads and snapshots have different `symbol_id` values.

### Fuzzy matching

Set `"name_match":"fuzzy"` explicitly.

Fuzzy matching accepts one insertion, deletion, substitution, or adjacent transposition.

Results rank in this order:

1. Exact name
2. Case-insensitive name
3. One-edit match
4. Subsequence match

Scope and declaration-kind filters run before candidate capacity.

A bounded search retains its partial-coverage qualifications.

For a property or an unknown declaration kind, call `search_declarations`:

```json
{
  "declaration_name": "retryCount",
  "name_match": null,
  "scope": null,
  "declaration_kinds": ["property"]
}
```

`declaration_kinds: null` includes `class`, `function`, `property`, and
`type_alias`.

Empty or duplicate selections reject.

Constructor discovery is not advertised.

## Narrow the search

A directory scope uses paths relative to the session workspace root:

```json
{
  "function_name": "submitOrder",
  "name_match": null,
  "scope": {
    "relative_directory_path": "services/orders",
    "include_subdirectories": true,
    "source_set_names": ["main"]
  }
}
```

A package scope instead uses semantic Kotlin package names:

```json
{
  "class_name": "OrderService",
  "name_match": null,
  "scope": {
    "package_name": "com.example.orders",
    "include_subpackages": false,
    "source_set_names": null
  }
}
```

### Scope rules

- Directory and package scopes are exclusive closed shapes.
- `include_subdirectories: false` selects only files in the named directory.
- `include_subdirectories: true` also includes descendant directories.
- `include_subpackages` controls semantic package descendants.
- Kotlin package declarations determine package membership.
- Mixed fields, absolute paths, parent traversal, and non-canonical paths reject.
- `source_set_names: null` means exactly `main` and `test`.
- Explicit names such as `integrationTest` or `commonMain` require imported ownership.
- Empty or duplicate source-set selections reject.
- A known absent source set contributes no declarations.
- Generated and library sources are excluded from live discovery.

Source-set restrictions apply to discovery subjects, not later expansion destinations.

## Check diagnostics separately

Call `kast.check_diagnostics`:

```json
{"relative_path":"src/main/kotlin/orders/OrderService.kt","max_diagnostics":null}
```

A path may name a file or directory.

- Use `.` for the workspace root.
- Use `null` to return at most 100 entries.
- Use a positive limit up to 1000.
- Do not treat this request as a project build.
- Keep the host's diagnostic scope policy separate from logging detail.

## Use the result

1. Read the outer `status`, then the semantic outcome in `document`.
2. Inspect each match's `kind`, `name`, and `location`. Request `signature` when needed to compare overloads; keep overloads separate.
3. Retain `symbol_ref` verbatim for a follow-up query or change plan.
4. Read `failures` and any `qualification` before making a completeness claim.

[Read a response](/reference/responses) explains the result layers.

[Symbol results](/reference/symbols) explains the compiler fields.

Use [Query pipelines](/query-pipelines) for callers, implementations,
enumeration, or returned-reference input.

Query expansion returns declarations.

Use `read_relations` for individual use-site facts.

<Accordion title="Why did a search miss a saved edit?">
  - Save the file.
  - Let IDEA finish indexing.
  - Follow the typed blocker when the host is unready.
  - Repeat discovery when a reference is stale.
</Accordion>

## Retrieve detail without another search

Start a new `query_symbols` request with the returned token and an explicit projection:

```json
{
  "source": {
    "type": "symbol_refs",
    "symbol_refs": ["<copy the returned symbol_ref verbatim>"]
  },
  "steps": null,
  "return_fields": ["signature"],
  "continuation": null
}
```

Replace the placeholder with an actually returned reference. This retrieves the
signature without rediscovery or candidate refinement. The original result shape
is preserved; unrequested name and location fields are null. Do not reuse a
search continuation for this new detail query: continuations retain their original
source, steps and projection. The public schema names exact references and
continuations separately; both remain opaque strings on the wire.

## Reuse exact references

Hosted references use compact handles:

| Reference | Normal prefix |
| --- | --- |
| Exact symbol | 31-character `exact:v5:` handle |
| Candidate | `candidate:v5:` handle |

- Handles retain scope, source sets, snapshot, and compiler evidence.
- One declaration can have different references but the same `symbol_id`.
- Copy `symbol_ref` verbatim for follow-up reads.
- Compare `symbol_id` only for equality.
- A full reference store emits the complete inline selector.
- Existing handles remain valid until their snapshot expires.

The `sym:` identity uses a complete SHA-256 digest in URL-safe Base64.

Compact handles check shorter digests against the full retained selector.

A digest collision falls back to the inline representation.
