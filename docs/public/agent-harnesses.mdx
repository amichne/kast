Kast offers the same compiler backed work through several client connections.
Choose the connection your client supports; the selected IDEA project remains
the source of semantic evidence.

| Connection | Client | How tools appear |
| --- | --- | --- |
| [MCP](/reference/mcp-catalog) | Codex and other compatible MCP clients | The client starts a Kast stdio process and discovers tools with `tools/list`. |
| [Tool RPC](/reference/rpc-catalog) | Copilot CLI, Pi, or another local extension | The extension reads `catalog`, then starts a one shot process for each `call`. |
| Codex App Server | Compatible Codex App Server clients | The installed provider supplies a tool catalog for the connected conversation. |

The installer registers the MCP connection with terminal Codex. The Copilot CLI
and Pi adapters are optional copies from the installed release. Both direct
connections discover the exact Gradle root from the client's working directory.
See [Install and connect](/start) for the first request.

## Use the catalog supplied by the connection

Tool names, descriptions, and input schemas come from the installed release.
Read the live catalog when a client starts or after upgrading Kast. Pass the
selected tool's input as a JSON object and preserve returned `ref` values and
qualifications. The [tool reference](/reference/mcp-catalog#tool-inputs) helps
you explore shared semantic tools; the live catalog is the contract for that
installation.

`change` can write source. Require the client's write permission before calling
it. The Copilot adapter uses its permission prompt; the Pi adapter asks for
interactive approval and refuses the call when no approving UI is available.
Kast checks the exact target and current IDEA state before a write.
[Change source](/change) explains the result and recovery states.

## Interpret the result

A successful transport call may contain qualified or rejected semantic
evidence. Read the outcome and its coverage before making a claim about source.
See [Read a response](/reference/responses) for result layers and
[How Kast runs](/concepts/architecture) for the processes behind a call.
