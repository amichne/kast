---
title: "Troubleshoot Kast"
description: "Act on the reported installation, readiness, or semantic failure."
icon: "life-buoy"
---

Use the failure returned by Kast. An empty partial or rejected query is not
evidence that the symbol is absent.

| Symptom | First check |
| --- | --- |
| No Kast tools | Restart the client, then inspect its [MCP](/reference/mcp-catalog) or [RPC](/reference/rpc-catalog) catalog. |
| Installer reports no matching plugin | Check the IDEA release line in [compatibility](/reference/compatibility). |
| Project trust, import, or indexing blocker | Resolve the reported IDEA state, then repeat the read. |
| Wrong workspace | Start the client from the intended Gradle repository or worktree. |
| Partial query | Keep returned facts and limitations; narrow scope before retrying. |
| Stale `ref` | Search again and use the newly returned reference unchanged. |
| Uncertain change | Keep the plan and recovery evidence; see [change](/change). |

`health_check` reports the bound workspace and IDEA readiness. It does not
prove that every semantic query will succeed. Run a scoped semantic query when
you need evidence for a specific declaration or relation.

For catalog admission failures, compare the reported expected and observed
contract versions and the selected executable. Upgrade the matched payloads and
restart IDEA and the harness. `kast connect codex` requires `mcp` or `app-server`.
The MCP transport records the MCP entry. The App Server transport installs the
owned `kast-codex` launcher; use `kast-codex` or `kast-codex app-server` to start
that route. App Server startup must admit the generated namespace and bind
the thread to its workspace. Preserve the reported failing stage and binding or
schema reason when diagnosing that route.

Use `kast connect codex <mcp|app-server> --force`, or
`kast connect <copilot|pi> --force`, only for deliberate takeover of that
harness's Kast slot. If rollback reports a recovery backup, preserve it and
restore the named destination before retrying. The flag does not repair live
thread ownership or resume sessions across upgrades.

A subprocess timeout, cancellation, output overflow, or nonzero exit is not
proof of rollback. Keep its bounded phase and plan evidence, avoid automatic
write retries, and follow the [change guidance](/change).
