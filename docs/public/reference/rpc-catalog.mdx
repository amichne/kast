Run `kast-tool-rpc-complete` from the Kotlin repository or worktree. Each invocation writes one JSON object to stdout.

## Discover

```shell
"${HOME:?HOME is required}/.local/share/kast/installation/bin/kast-tool-rpc-complete" catalog
```

The reply has `type: "catalog"`, `catalog.schemaVersion: 2`, and `catalog.tools[]`. Each tool carries `name`, `description`, `inputSchema`, and `effect` (`READ` or `WRITE`). Rediscover after upgrades.

## Call

Pass the tool name after `call` and one JSON object on stdin:

```shell
printf '%s\n' '{}' |
  "${HOME:?HOME is required}/.local/share/kast/installation/bin/kast-tool-rpc-complete" call health_check
```

Use [query arguments](/reference/api) for `query_symbols`. Tool RPC exposes direct MCP tool names, including change tools, but excludes `workspace_lifecycle`.

## Decode

| `type` | Required field | Meaning |
| --- | --- | --- |
| `catalog` | `catalog` | Installed inventory. |
| `complete` | `document` | Completed operation. |
| `qualified` | `document` | Facts with limitations. |
| `rejected_document` | `document` | Semantic or hosted rejection. |
| `rejected` | `failure` | Finite process-boundary failure. |

Decode `document` with the tool's response schema. Unknown variants are incompatible. See the [reply union](/reference/models/tool-rpc-reply) and [adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md).
