Use the remote installer for an initial installation, then use `kast upgrade` for updates.
The normal setup path tracks the latest published development build with `--channel main`.

Use the desktop steps on this page for IntelliJ IDEA on an Apple silicon Mac.
For a private Host, go to [workspace containers](#manage-isolated-workspaces).
For an existing `kast-task` workflow, see the [standalone setup archive](#isolated-runtime).

## Desktop prerequisites

<span id="before-you-install" />

Use an Apple silicon Mac and a Kotlin Gradle project.
Use IntelliJ IDEA `262.*` or `263.*` with its bundled Kotlin plugin and Java 25 JBR.
Your project's JDK does not replace the IDEA runtime.

Use Python 3.12 or 3.13, available as `python3` on `PATH`. For upgrades, install uv 0.12.9 or later. The [optional MCP service](/reference/integrations#optional-mcp) uses the same runtime versions.

Save your project work before installation or an update.

## Remote initial install

Run this command from a terminal:

```shell wrap
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh)" -- --developer-latest --skip-codex-plugin
```

This command needs no checkout or existing `kast` installation. `--developer-latest` selects the latest qualified development build from the published channel. It installs matching Control and Host artifacts and resets stale Kast state. `--skip-codex-plugin` skips the optional MCP setup. After installation, use [agent setup](/reference/integrations) for CLI guidance.

The installer replaces Kast-owned installation files, Host files, and bundled agent assets. Replacement can end active Kast sessions. Restart IDEA to load the installed Host. Start a fresh agent session.

The installation directory is `$HOME/.local/share/kast`.
The command path is `$XDG_CONFIG_HOME/kast` when `XDG_CONFIG_HOME` is nonempty, or `$HOME/.local/bin/kast` otherwise.
If the shell cannot find `kast`, add the reported command directory to `PATH`.
The installer does not edit shell profiles.

For another IDEA installation, append `--idea-home "/Applications/IntelliJ IDEA.app"` after the installer options.
Keep Bash's `--` separator before those options.
To preview installation without changes, append `--dry-run`. To inspect structured diagnostics, append `--verbose`.

The installer selects a separate Host archive for each IDEA release line.
Older published builds can lack the `263` archive.
The Host profile uses `dataDirectoryName` from the selected IDEA metadata.
IDEA `263` normally uses `IntelliJIdea2026.3`, independently of the app's name or location.
The Kast installation and command paths stay the same.
If several compatible IDEA apps exist, supply `--idea-home` to select one exact app.

## 1. Install the selected release

List the published builds:

```shell
kast versions
```

The catalog lists up to five selectable main builds. Each entry shows its revision, version, and platform targets.

Preview the latest development build:

```shell
kast upgrade --channel main --dry-run
```

A successful preview returns `PLANNED`.
It admits the selected artifacts without installation changes or an IDEA restart.

Apply the latest development build and permit a normal IDEA restart when necessary:

```shell
kast upgrade --channel main --restart-ide
```

Kast uses a compatible reload when the running Host permits it.
Active Kast sessions can end so that the selected build can replace the prior build.
If you omit `--restart-ide`, a necessary restart returns `RESTART_REQUIRED` before installation changes.
If IDEA is already stopped, Kast can install the selected build without starting IDEA.
Read the [update outcome](/reference/management#lifecycle-result-contract) before you start another session.

### Select another IDEA installation

Supply the exact IDEA app path:

```shell
kast upgrade --channel main --idea-home "/Applications/IntelliJ IDEA.app" --restart-ide
```

The selected IDEA installation and profile determine which Host Kast updates.
An unsupported custom-profile restart rejects before installation changes.

### Pin a published build

Use one selector per command: `--channel`, `--version`, or `--commit`.
A version selector uses an exact published release version.
A commit selector uses a published main revision or its unique displayed 12-character prefix.
Copy the revision from `kast versions`.

Replace `VERSION` or `MAIN_REVISION` with your selected value:

```shell
kast upgrade --version VERSION
kast upgrade --commit MAIN_REVISION
```

Either exact selector records a pin.
An unqualified `kast upgrade` rejects a pin with `PINNED_BUILD` before installation changes.
To track development builds again, use `kast upgrade --channel main`.

## 2. Load the plugin and inspect state

Examine installation and loaded Host evidence separately:

```shell
kast status --json
```

`installedBuild` describes the files on disk. `applicationHost` describes the admitted running IDEA process and its loaded Host.
`updatePolicy` describes future selection. `unresolvedTransaction` reports unfinished installation work.
Status starts no Java process and requests no Host lifecycle action.

Compare `installedBuild` with `applicationHost` to distinguish installed files from the loaded Host. A query supplies separate evidence for project readiness and completion.

Use [agent setup](/reference/integrations) to install the selected agent's guidance.
If an update reports `HARNESS_REFRESH_REQUIRED`, repeat that setup before a fresh agent session.

## Manage isolated workspaces

A workspace container gives a trusted Kotlin Gradle project its own Host profile and Gradle home.
Several containers can share one verified runtime for the same Kast version and platform.
The private Host runs separately from desktop IDEA. It shares the OS permissions of your user account.

### 1. Get a matching Control and runtime

Check your Control version and command support.

```shell
kast --version
kast container --help
```

The developer channel selects the latest qualified build. That build can lag changes on `main`.
If `kast container --help` succeeds, use a runtime ZIP for that exact version and platform.
The runtime format covers macOS and Linux on AArch64 and x86-64.

The stable release workflow qualifies each runtime archive and publishes it with its `.sha256` file.
On a [stable release](https://github.com/amichne/kast/releases) with these files, `create` fetches the matching runtime on first use.
If your release lacks these files, import a matching candidate before you create the container.

For a candidate, open a successful [Isolated runtime candidates run](https://github.com/amichne/kast/actions/workflows/composed-linux.yml).
Download the `kast-composed-TARGET-SHA-RUN_ID-ATTEMPT` artifact for your platform.
Use the `kast-runtime-vVERSION-TARGET.zip` file and the SHA-256 value from its `.sha256` companion.
In the qualification artifact for that run and target, find `qualification.json`.
Look for `"qualification": "COMPLETE"` and compare `containers.runtimeSha256` with the ZIP digest.
Actions artifacts have a retention limit.

If your current Control lacks `container` or has another version, get Control from the same candidate.
Install its `kast-composed-setup-vVERSION-TARGET.tar.gz` through the [standalone setup archive](#isolated-runtime) procedure.
After installation, start a shell that uses the candidate Control.
Run this command in the same terminal so `root` keeps the installation path.

```shell
env -i HOME="$root/state/home" PATH="$root/state/home/.local/bin:/usr/bin:/bin" /bin/bash --noprofile --norc
```

Run the remaining commands in that shell. Use absolute paths for the ZIP and your workspace.

To import a candidate runtime, replace the path and `DIGEST` with the values from the artifact.

```shell
kast container import-runtime --archive /path/to/kast-runtime-vVERSION-TARGET.zip --sha256 DIGEST
```

### 2. Create a container and query your code

Run `create` only for a workspace whose build code you trust. This command grants workspace trust.

```shell
cd /path/to/trusted/workspace
kast container create --name backend
```

`create` uses the current directory unless you supply `--root`. It records the container without starting the Host.
Replace `DECLARATION_NAME` with the exact name of a Kotlin declaration in this workspace.

```shell
kast query --name DECLARATION_NAME --fields name,location --json
```

The first query starts the private Host on demand. Look for `"type": "complete"` and the expected file location in the returned rows.
Use the [CLI reference](/reference/cli) to narrow the query if several declarations share a name.

### 3. Manage the container

```shell
kast container --json
kast container stop backend
kast container resume backend
```

The list reports the enabled or stopped policy. Use a complete query to prove the Host can answer for this workspace.
`stop` disables on-demand start. `resume` enables it and tries to prepare the Host.
A query from the workspace or its subdirectories uses the matching record. An ambiguous or missing selection rejects once the registry exists.

Gradle state stays private unless you supply an existing directory with `--gradle-home`.
That option gives the Host access to the directory's Gradle properties, credentials, and init scripts.

Use `kast container rm <id>` to stop and remove the record and its private state.
Removal preserves the repository, shared runtime, and external Gradle home.
If stop or removal returns `BUSY`, repeat the command after the active operation ends.
For the default Control installation, container state lives under `~/.local/share/kast-workspaces`.
Remove the records before uninstalling Control if you also want to remove their state.

## Isolated runtime

Use this procedure for a standalone `kast-task` installation or to install Control from a matching candidate.
The original standalone procedure covers macOS ARM64 and Linux x86-64.
For a candidate archive, use the platform recorded by its build and qualification run.
The archive includes its own Host and Java runtime.
It keeps its Host, configuration, and Gradle state in one private installation. Your desktop IDEA stays independent.
Use system Python 3.12 or 3.13 and the core OS facilities.
The Host uses its bundled Java runtime. Your project supplies its own build dependencies and Gradle JVM settings.

Choose a new absolute root with an existing parent. Use its canonical path, with no symbolic link components.
For example, use `/private/tmp/ki` on macOS or `/tmp/ki` on Linux for a disposable installation.
The installed root is fixed. Install the archive again if you need a different root.

1. Set `archive` to the downloaded archive path.
2. Set `sha256` to the setup archive digest from its `.sha256` companion.
   Set `version` to the value after `v` in the archive filename.
3. Set `root` to the chosen installation path.
4. Run the following command to authenticate the archive and start its installer.

```shell
python3 -I - "$archive" "$sha256" "$version" "$root" <<'PY'
import hashlib
from pathlib import Path
import subprocess
import sys
import tarfile
import tempfile

archive, expected, version, root = sys.argv[1:]
with open(archive, "rb") as source, tempfile.TemporaryDirectory() as scratch:
    if hashlib.file_digest(source, "sha256").hexdigest() != expected:
        raise SystemExit("Archive digest mismatch")
    source.seek(0)
    name = "setup-kast/bin/setup-kast.pyz"
    installer = Path(scratch) / "setup-kast.pyz"
    with tarfile.open(fileobj=source, mode="r:gz") as bundle:
        matches = [member for member in bundle if member.name == name]
        if len(matches) != 1 or not matches[0].isfile() or matches[0].size > 1_048_576:
            raise SystemExit("Invalid archive installer")
        with bundle.extractfile(matches[0]) as entry:
            installer.write_bytes(entry.read())
    result = subprocess.run(
        [sys.executable, "-I", str(installer), "--archive", archive, "--archive-sha256", expected,
         "--version", version, "--root", root],
        check=False,
    )
    raise SystemExit(result.returncode)
PY
```

If you need Control for a workspace container, return to [Get a matching Control and runtime](#1-get-a-matching-control-and-runtime).
For `kast-task`, the private Host starts with no trusted workspace. Select a workspace only if you trust its build code.
Set `workspace` to the canonical workspace path. Replace `DECLARATION_NAME` with an exact Kotlin declaration name.

```shell
"$root/bin/kast-task" "$workspace" -- kast query --name DECLARATION_NAME --fields name,location --json
```

Repeat the same workspace path to reuse its trust and private state. A different workspace needs its own installation root.
The command runs in the selected workspace and keeps its arguments and exit status.
Use the [CLI reference](/reference/cli) to choose a query for your project and examine its completion evidence.

To stop the private Host, run `"$root/bin/kast" stop --json`.
To resume the private runtime, repeat `kast-task` for the same workspace.
