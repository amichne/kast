# Shared-tool consumer compatibility

Kast now owns glossary parsing and projections under `docs/tooling`.
The current shared prose assessor emits report v2 without glossary fields.
Slopsentral revision `5c2ec0221f839b27a7984984d8e92e11c8f437f2` supplies that assessment contract.

The original reports in the parent directory keep their recorded schema, input hashes, source revisions, and findings.
This directory records separate evidence for the current consumers.

## Recorded evidence

- `glossary-current.json` records the current glossary digest, supplied documents, and terminology findings.
- `text-assessment-v2.json` records the shared assessment with engine, policy, and document digests.
- `vale-current.json` records the repository Vale findings from the same prose inputs.
- `prose-inputs.json` lists the exact input files.
- `kept-findings.tsv` records the rule, location, and reason for each unresolved finding.

The focused suite covers accepted output, malformed data, unknown variants, label collisions, invalid scopes, and missing evidence.
It also covers stale projections, literal paths, markup exclusions, historical scope, and rejected writes to the source file.
The source tests keep citation URLs local and preserve review targets without automatic replacement.

The projection case compares generated bytes with the existing reader view and checked-in Vale rules.
The stale-rule case first failed because the command accepted an extra rule.
The same case passed after the command rejected that extra rule with `STALE_RULES`.

## Evidence limits

`ASSESSED` means that the shared prose procedure ran. Grade advisories remain visible.
The glossary report supplies separate terminology evidence and does not infer meaning from lexical matches.
The focused suite does not prove live IDEA behavior or human comprehension.
The PR checks and review identify their own exact source head.
