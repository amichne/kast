<a id="check-the-target-and-scope" />

<a id="select-the-target-and-scope" />

## 1. Select the target and scope

Find the exact target before the write. Read its source. If several declarations match, select its owner and signature.

```text wrap
Use Kast to find retryLimit under checkout. Show matching signatures and locations. If several functions match, stop so I can choose. Read the selected function's source and check whether it has a supported block body before changing it.
```

When you request a new body, state which source has to stay unchanged.

```text wrap
Use Kast to replace the chosen function's body with { return 3 }. Keep its signature and the source outside the body unchanged. Report verification and the change receipt; if the outcome is uncertain, preserve recovery evidence and stop before retrying the write.
```

The target is a named, non-inline Kotlin function. It needs a block body and no contract. Kast rejects expression bodies and ownership that is not supported.

The tools do not create files, rename symbols, replace arbitrary ranges, or do multi-file refactors.

<a id="read-the-receipt" />

<span id="2-establish-the-source-effect" />

## 2. Prove the source effect

One public call owns the whole sequence. It plans, grants exact internal authority, checks the preimage, changes source, checks the result, and sends a receipt.

Before the write, the source has to match the planned preimage. If a later stage fails, recovery evidence keeps the planned effect and the resulting source effect.

Check the receipt's plan identity, phase, and state. Check its qualification, source location, and fresh reference. Review the resulting diff.

A known rejection before a write can prove that no write took place within that phase. A missing response or uncertain outcome after dispatch cannot prove this.

If the effect is uncertain, keep the receipt. Read current source before another write. Complete the reported recovery before another write.

IDEA diagnostics and checks after a write cover only the receipt's scope. After a verified source effect, run the project's build and tests.

## 3. Use the supported input form

These examples use placeholders for current exact references. Pass issued handles unchanged.

### Add a declaration

```json
{
  "exactTarget": "<exact-ref-returned-by-Kast>",
  "declaration": "fun retryLimit(): Int = 3"
}
```

Select the existing file. Check the insertion location. [The generated schema](/reference/callables/add-declaration) defines the full input.

### Replace a function body

```json
{
  "exactTarget": "<exact-function-ref-returned-by-Kast>",
  "body": "{ return 3 }"
}
```

Supply the full block with braces. [The generated schema](/reference/callables/replace-body) defines target and replacement admission.

### Carry exact identity across a change

After a verified change, use the returned `freshRef` for later calls. Earlier references still need current compiler identity checks.

The token prefix remains part of the opaque handle. Do not substitute one reference version for another.

[Staleness](/reference/staleness) protects read and preimage authority. [Lifecycles](/reference/lifecycles) describes recovery for uncertain writes and workspace state.
