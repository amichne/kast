title: "Troubleshoot Kast"
description: "Recover from missing tools, an IDEA readiness blocker, or an incomplete result."

---

Start with the reported failure:

```shell
kast status
```

Inspect the version, installation path, and connections. After recovery, repeat the [first query](/agent-harnesses#check-that-the-tools-work) to verify loaded tools.

## Choose the symptom

| Symptom | Action |
| --- | --- |
| No Kast tools | Verify the [integration](/agent-harnesses) and restart the agent. |
| No matching plugin | Verify the [IDEA build and JBR](/start#before-you-install), then [compatibility](/reference/compatibility). |
| Trust, import, or indexing blocker | Resolve the reported state in the selected IDEA project. Repeat the read. |
| Wrong workspace | Start the client from the intended Gradle repository or worktree. |
| Qualified query | Resume issued work, or preserve facts with the terminal reason. |
| Stale reference or unavailable state | Search again and pass fresh handles unchanged. |
| Uncertain write | Inspect source and [recovery evidence](/change#read-the-receipt) before retrying. |

`health_check`, where available, reports workspace binding and readiness. A scoped query establishes the declaration or relationship you need.

<AccordionGroup>
  <Accordion title="Connection conflicts and version or catalog failures">
    Compare expected and observed contracts and the selected executable. Install compatible payloads, restart IDEA and the agent, then rediscover tools.

    Codex requires `mcp` or `app-server`. The latter installs `kast-codex`. A fresh thread must admit the generated namespace and bind its workspace. Preserve any failing stage, binding, or schema reason.

    Use `--force` only for deliberate replacement of a harness's Kast slot. If rollback reports a backup, preserve it and restore the named destination. Force connection does not repair live thread ownership or resume sessions across upgrades.
  </Accordion>

  <Accordion title="Continuation failure details">
    Failures distinguish expiration, owner retirement, dependency loss, eviction, stale basis, and incompatible identity. Restart the read when authority or retained state is unavailable.

    Budget failures retain the exhausted dimension and stage. A larger grant cannot recover missing state. Revocation receipts have bounded retention. Reclaimed receipts cannot establish a token's historical eviction or expiry cause.
  </Accordion>
</AccordionGroup>

## A write has an uncertain outcome

Timeout, cancellation, output overflow, and nonzero exit do not prove rollback. Preserve the plan identity and phase evidence. Read the source and follow [change recovery](/change#read-the-receipt) before another write.
