Kast gives coding agents compiler-grounded understanding of Kotlin code. The agent asks the question; Kast uses the selected IntelliJ IDEA project to establish exact declarations and relationships, with explicit coverage and validity.

## From a question to a justified change

**Find the right code.** Start with a declaration name and a useful scope. Inspect the returned identity, signature, and location; carry its exact reference into the next question instead of matching the name again. [Find and trace code](/search) shows the workflow.

**Understand its relationships.** Follow callers, implementations, references, or a bounded traversal. Keep confirmed relationships separate from unvisited work. When a question spans investigations, [combine retained results](/query-pipelines) by semantic identity rather than reconstructing lists from prose.

**Change a known target.** Add a declaration or replace a supported function body using an exact target, then inspect the verification receipt. These are bounded source changes, not arbitrary multi-file refactors. See [Make a targeted change](/change).

## Why the evidence matters

**Kast is the deterministic structure around a probabilistic system.** The model still supplies judgment. Questions the compiler can answer should not remain guesses, and a later operation should preserve what an earlier one established.

An exact result is not necessarily an exhaustive result. An empty incomplete answer does not prove absence, and an old reference does not become current because its name still matches. [What an answer proves](/concepts/evidence-boundaries) explains these boundaries; [How Kast works](/concepts/architecture) explains the mechanism.

## Supported today

The current installation targets Kotlin Gradle projects on Apple silicon macOS with IntelliJ IDEA `262.*`. Connect Codex, Copilot, or Pi. Kast prepares the selected project when semantic work needs it and reports readiness blockers rather than returning a misleading empty answer.

Check [compatibility](/reference/compatibility) before installing. The aim is dependable evidence from discovery through action; a verified bounded edit or a clean diagnostic result is not proof of whole-project behavior.
