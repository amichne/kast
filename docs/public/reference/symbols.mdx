An exact reference carries an admitted declaration identity into another request. `query_symbols` returns these references with Kotlin declarations. Each symbol keeps the coverage of its producing query.

## Public fields

| Field | Meaning |
| --- | --- |
| `ref` | Opaque handle for subsequent identity admission. |
| `location` | Established declaration location. |
| `signature` | Compiler-established identity and callable or property facts. |
| `source` | Bounded committed source, when requested. |

`SOURCE` selects committed source context in symbol output. A name, path, or reconstructed token does not establish exact identity. See the [query item schema](/reference/models/query-item) for fields. The [scoped example](/reference/walkthrough#1-find-a-declaration-and-inspect-its-source) includes source output.

## Local declarations

Local `val` and `var` declarations use `LOCAL_PROPERTY` signatures. Local named functions use `LOCAL_FUNCTION` signatures. Their addresses keep the exact file and declaration range, plus compiler identity and the containing declaration's range. They also keep bounded ranges for lexical ownership.

Function signatures keep callable facts. Property signatures keep type and `VAL` or `VAR` mutability. Declarations with the same name in different scopes keep distinct identities.

Exact reads and relations admit the issued reference unchanged. Kast can reacquire a local reference with fresh compiler evidence only while its owning file content stays unchanged. After you edit or move a local declaration, discover it again.

## Evidence limits

Local variable identity does not establish assignment flow. Local function identity does not establish execution of a deferred body.

## Output selection example

This `SYMBOLS` output requests the four descriptive fields. Identity and kind remain necessary fields.

```json
{"type":"SYMBOLS","fields":["NAME","LOCATION","SIGNATURE","SOURCE"]}
```
