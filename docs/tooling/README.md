# Kast glossary tool

This directory owns the local grammar and projections for `docs/glossary.json`.
It does not depend on a shared glossary service or installed plugin files.
The [documentation policy](../documentation-structure.md#glossary-ownership) defines its consumer commands.

## Inputs and outcomes

The parser admits the existing JSON schema before it creates immutable concepts.
It rejects duplicate keys, unknown fields, unknown variants, missing evidence, label collisions, invalid scopes, and unknown related concepts.
Source citations remain evidence references. The tool never fetches their URLs or proves their meaning.

The reader view and Vale rules derive from the admitted glossary.
`--render` writes the reader view. `--vale-dir` exports rules into a new directory.
`--check-render` rejects a stale reader view. `--check-vale` compares the complete rule set with its generated bytes.
Neither comparison changes its input files.

Exit `0` means that the glossary and requested projections passed, without rejected forms in the supplied prose.
Exit `1` means that scoped prose contains a replacement target or review target.
Exit `2` means that an input, grammar, local effect, or projection failed.
The JSON report keeps the glossary digest, document digests, findings, and source locations.

The lexical procedure excludes frontmatter, code spans, fenced examples, comments, and link destinations.
It applies the declared include and exclude patterns, with the longest label at overlapping locations.
Directory scans omit Git metadata, Gradle state, virtual environments, Python caches, build outputs, and Node dependencies before file selection.
Vale supplies a separate native markup parser. Neither procedure proves semantic equivalence, current source truth, or reader comprehension.

## Development

From this directory, run:

```shell
uv run --locked pytest
uv run --locked pyright
uv run --locked ruff format --check .
uv run --locked ruff check .
```

The root `verifyDocumentationGlossary` task runs the focused suite and examines the repository projections and current prose.
The root `check` and `productBuildGate` tasks include that task.

The shared prose assessor remains a separate consumer.
Its report v2 omits glossary fields and does not accept `--glossary`.
Keep historical reports under `docs/reviews` unchanged at their recorded revision.

## Provenance

The source files were `source/skills/controlled-technical-writing/scripts/glossary_json.py` and `references/glossary.schema.json` under that skill.
The parser import keeps its grammar, immutable concepts, scope rules, and projections.
Kast replaces the shared command adapter with typed reports and adds rule parity rejection.
The schema import keeps its original bytes, examples, and constraints.
