## 1. Choose the client and transport

<Tabs>
<Tab title="Codex">
The bundled plugin supplies MCP tools, a query skill, and examples. If direct MCP already exists, disconnect it before plugin installation.

```shell
kast plugin codex
cd /path/to/kotlin-repository
codex
```

Restart Codex to load the plugin.

<Accordion title="Direct MCP">
Choose an explicit transport for `kast connect codex`.

```shell
kast connect codex mcp
cd /path/to/kotlin-repository
codex
```

Start a new client session to load the registration.
</Accordion>

<Accordion title="Hosted App Server">
Explicit attachment uses the installed `kast-codex` launcher.

```shell
kast connect codex app-server
cd /path/to/kotlin-repository
kast-codex
```

Start a fresh thread to admit its provider catalog and workspace. Custom clients can use `kast-codex app-server` for JSONL stdio.

Persistent installation selects the standard Codex control socket when available. An occupied socket or failed socket inspection selects a private endpoint.

Routine installation preserves the saved endpoint. Standard-socket clients can discover the admitted daemon automatically.

Compatible desktop builds also need a fresh launch with the daemon-selection flag. Private endpoints or client overrides can bypass discovery.

Examine [recorded client compatibility](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md) before desktop integration.
</Accordion>
</Tab>
<Tab title="Copilot">
Connect the extension. Start Copilot in the intended root.

```shell
kast connect copilot
cd /path/to/kotlin-repository
copilot
```

Restart Copilot to load its adapter and installed catalog.
</Tab>
<Tab title="Pi">
Connect the extension. Start Pi in the intended root.

```shell
kast connect pi

pi
```

</Tab>

## 2. Establish tool and workspace admission

Ask the agent for one Kotlin declaration with signature, location, coverage, and the reported readiness or proof blocker.

For a named function, narrow discovery before relation work.

```text wrap
Use Kast to find submitOrder in the production Kotlin sources under checkout. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

After you select the declaration, request its callers through the issued exact reference.

```text wrap
Use the exact reference for the function I selected to find its callers. Show the call sites and searched scope, and report any unfinished work.
```

Queries prepare IDEA automatically. Readiness still needs admission for the exact worktree and loaded Host.

[Find and trace code](/reference/search) supplies investigation steps. [Lifecycles](/reference/lifecycles) distinguishes registration, session, preparation, and semantic execution.

## 3. Set a custom destination when needed

Supply an absolute destination for the selected integration.

```shell
kast connect pi --destination "$HOME/.config/pi/agent"
kast connect copilot --destination "$HOME/.config/copilot"
kast connect codex mcp --destination "$HOME/.config/codex"
kast connect codex app-server --destination "$HOME/bin"
```

| Connection | What the directory contains |
| --- | --- |
| Pi | `extensions/kast.ts` under the Pi agent home |
| Copilot | `extensions/kast/extension.mjs` under the Copilot home |
| Codex MCP | Codex's `config.toml`. The registered executable stays in the Kast installation. |
| Codex App Server | The `kast-codex` launcher |

Kast saves preferences in `~/.config/kast/config.json`. An explicit destination overrides the recorded preference.

Without a preference, Kast reads the selected agent's `PI_CODING_AGENT_DIR`, `COPILOT_HOME`, or `CODEX_HOME`. Otherwise, it uses that agent's default home.

App Server defaults to `~/.local/bin`. A saved destination does not change the agent's own home selection.

If you use a custom home, start the agent with the same home. For Pi, use `PI_CODING_AGENT_DIR="$HOME/.config/pi/agent" pi`.

Destination changes admit the new connection and remove the previous owned slot in one transaction. Other harness settings stay under their existing owner.

## 4. Recover a conflicting connection

Matching registrations stay in place. Default recovery replaces a conflicting Kast slot with the verified release payload and keeps displaced bytes in a private backup.

A failed transaction restores connection, preferences, checkpoint, and receipt. Concurrent changes or filesystem refusal can leave a recovery copy with a necessary action.

Unverified payloads and symbolic-link slots reject before replacement. `--no-recover` rejects conflicts without replacement, while `--force` requests explicit slot replacement.

`config.last-good.json` supplies a configuration checkpoint. If both configurations fail, recorded routing receipts can reconstruct preferences and preserve rejected copies.

If an older receipt lacks routing proof, supply `--destination`. Keep the reported backup until recovery succeeds.

<a id="disconnect-or-upgrade" />

## 5. Reload clients after a lifecycle change

Disconnect an owned registration with its selected agent name.

```shell
kast disconnect copilot
```

`kast disconnect codex` removes recorded App Server and MCP integration. Remove the Codex-owned plugin with `codex plugin remove kast@kast`.

Restart the affected client to unload its adapter. After an upgrade, restart IDEA and connected clients.

For the bundled Codex plugin, repeat `kast plugin codex`. Disconnection does not itself retire IDEA or the shared daemon.

## Install the skill independently

Historical [Control 0.3.1](https://github.com/amichne/kast/releases/tag/control-v0.3.1) supplies skill, plugin, and marketplace archives with SHA-256 checksums.

Examine the selected archive checksum. Extract the skill's `kast/` directory into a personal or repository `.agents/skills/` directory.

For an extracted marketplace, use its absolute path.

```shell
codex plugin marketplace add /absolute/path/to/extracted-marketplace
codex plugin add kast@kast
```

The source marketplace uses `codex plugin marketplace add amichne/kast`. Generated example references still need current workspace handles.

[MCP](/reference/mcp-catalog), [Tool RPC](/reference/rpc-catalog), and hosted App Server support custom clients. Their installed catalogs own each release's contract.
