Use an Apple silicon Mac and a Kotlin Gradle project.
Kast needs IntelliJ IDEA `262.*` with its bundled Kotlin plugin and Java 25 JBR.
Your project's JDK does not replace the IDEA runtime.

## Tool contracts

Use the installed Kast skill and the schema from your current session.
MCP clients get the tool contract from `tools/list`. Tool RPC clients use `catalog`.
Copy issued references unchanged.

Before semantic work, Kast examines the runtime protocol, operation registry, and wire schema.
It also examines supported features and IDEA/Kotlin support.
Equal component versions alone do not establish compatibility.

## Select a development build

The [setup guide](/start) assumes that the `kast` CLI is installed.
Use the main channel for the latest published development build:

```shell
kast versions
kast upgrade --channel main
```

Control supplies the command and agent resources. Host supplies the IDEA plugin and semantic runtime.
Kast admits their contracts and build identities before replacement.
An exact version or commit selector records a pin. Use the [selection reference](/reference/installation#pin-a-published-build) for details.

## Loaded Host identity

```shell
kast status --json
```

Installed build identity describes disk contents. Loaded Host identity describes the admitted running IDEA process.
An update reports `ACTIVATED` only after the affected running Host matches the selected build and contract.
`INSTALLED_NOT_RUNNING` describes the planned stopped-IDE path. It does not claim that IDEA loaded Host.

A loaded Host does not prove readiness in a particular project or worktree.
A successful query keeps its own scope and completion evidence.
