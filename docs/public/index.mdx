**Which callers and values does this change affect?**

Kast gives your coding agent Kotlin source relationships from IntelliJ IDEA's compiler analysis.
It finds callers and implementations, traces supported value transfers, inspects diagnostics, and makes targeted source changes.
Your agent can request source locations and inspect evidence that states what the answer covers.

## A name match does not explain a value path

Consider this question: **Where can this customer end up?**

A sign-up becomes a customer. A welcome-email draft holds that customer as its recipient.
The draft can then be part of a returned list, even though the last function never says `Customer`.

Change one expression, and the same list type can hold a draft for a different customer.
Names and types alone do not explain that difference.

Text search helps an agent find candidate code. Compiler analysis resolves which declaration each call uses, including its overload and receiver.
Kast combines supported relationships and keeps the evidence behind them.

This is an authored source illustration. It does not run Kotlin or query Kast.
The list connection needs a reviewed library rule as well as compiler-resolved calls.

## Use the evidence for your next decision

> Use Kast to trace this function's result. Show where it goes and where the evidence stops.

> Use Kast to find the callers of this function before we change it.

> Use Kast to inspect the diagnostics in the code we changed.

Compare the returned locations with your source before an edit.
A complete result applies to its stated scope and source-analysis model. It does not prove that a path executed or can execute.
If Kast cannot establish completion, it reports the cause. An unfinished search with no matches does not prove absence.

Read [how an answer works](/explanation) for the concepts behind these distinctions.
