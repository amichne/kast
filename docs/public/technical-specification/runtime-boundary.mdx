The runtime boundary admits one canonical repository root before semantic work
begins.

A ready runtime proves that the same root owns:

- the compatible sidecar process;
- its endpoint and workspace; and
- the current semantic generation.

## Exact-root admission

The control executable first canonicalizes the caller's starting path. That
root determines endpoint identity, private state, and later workspace requests.

Admission then verifies:

- the installed sidecar contract;
- IDEA and Kotlin plugin release-line compatibility;
- JBR, bootstrap classes, and Gradle integration; and
- endpoint descriptor, socket, and process ownership.

Compatibility is intentionally broader than identity.

- The installed reference pair is IDEA `262.9437.185` and Kotlin plugin
  `262.9437.185-IJ`.
- Well-formed patch builds are accepted when both remain on release line `262`.
- The observed patch build identities remain in runtime, cache, and endpoint
  evidence.

The result is closed:

- an existing endpoint is reused only when its root and complete product
  identity agree;
- a missing endpoint may be started through the admitted runtime;
- an ambiguous, stale, incompatible, unreachable, or wrong-root endpoint is a
  typed blocker.

The caller never gains authority by selecting a nearby open IntelliJ Project or
by finding a plausible socket. Exact identity is established before transport
is useful.

## Private process and private state

The sidecar runs a release-line-compatible local IntelliJ distribution
headlessly. It does not modify the user's IDE instance.

Kast owns the sidecar's:

- config, system, plugin, log, and index directories;
- endpoint, socket, persistence, and telemetry state; and
- private plugin installation.

The private plugin excludes Kotlin standard-library, coroutine, and
Kotlin-plugin classes already owned by the selected IntelliJ platform.
Distribution checks prove that separation before packaging.

Ordinary startup does not read the user's IDEA cache. Optional index seeding is
a distinct, consent-bearing boundary: it requires a stopped, compatible IDEA
source and validates an allowlisted copy before atomically publishing it into
Kast's private cache. Seeded indexes remain an acceleration hint, never
readiness proof.

<Warning>
  Process liveness is weaker than endpoint ownership. Lifecycle operations act
  only after descriptor, PID, executable, root, and socket evidence establish
  that the target is Kast's exact process.
</Warning>

## Workspace bootstrap and publication

Inside the sidecar, bootstrap proceeds in a strict order:

1. Admit launch arguments and private state paths.
2. Assign Kast's admitted private project SDK and open the exact on-disk
   IntelliJ Project with project-open configurators deferred.
3. After project state loads, apply the admitted Gradle JVM and explicitly
   refresh the linked Gradle project or link an unlinked project.
4. Refresh the VFS and wait for strengthened indexing quiescence.
5. Capture a detached module and source-root model.
6. Reconcile durable workspace publication and issue the current read lease.
7. Construct the complete runtime and publish the endpoint.

Declared local source-root identity comes from IntelliJ model URLs. A declared
directory may be absent and still remain part of the model, but it contributes
no source files. Malformed, non-local, conflicting, or outside-root identities
are rejected.

Readiness is a domain state, not a health boolean. Absent, starting,
reconciling, blocked, ready, and stopping states cannot be confused. A ready
workspace carries the exact canonical root and current semantic generation
needed to construct a `SemanticReadLease`.

## Request-local compiler state

Live IntelliJ and compiler objects never become durable evidence. This includes
Projects, VFS handles, PSI elements, K2 symbols, analysis sessions, and native
scopes.

Each semantic request instead:

1. observes the current ready workspace;
2. performs compiler work inside the adapter; and
3. revalidates its lease when generation movement could invalidate the result.

This is why a selector is generation-bound and why a sidecar restart advances
generation conservatively. The text of a declaration may be unchanged while
the authority that established its identity has expired.

`index.sync` is the explicit repair boundary for on-disk changes made outside
the sidecar. It refreshes admitted source roots, waits for indexing, captures
current source identity, and publishes a successor generation. Startup itself
does not perform a complete topology build; topology remains an explicit
operation with its own proof contract.
