Start with the failure already reported by the agent or harness. Use the Kast
binary directly only for passive status collection or a corrective action named
by that evidence.

## Identify the failing layer

| Symptom | Meaning | Next action |
| --- | --- | --- |
| Kast tools are absent from a new thread | The App Server is disabled or did not qualify and publish the installed catalog. | Check the saved App Server configuration and broker readiness document. |
| The tool invocation is outer `rejected` | Process, runtime, protocol, timeout, output, or schema admission failed. | Preserve its `diagnostic`, then collect passive status from the same repository root. |
| The invocation is outer `completed`, but the semantic document is `rejected` | Kast ran the operation but could not establish successful semantic evidence. | Follow the typed semantic reason. Do not restart the runtime by default. |
| The semantic document is `qualified` | The evidence is usable only within its attached limitations. | Narrow the question, increase an admitted bound, or report the limitation. |
| Some query items have failures | The query returned per-item evidence and retained the items it could not refine. | Keep the successful items and inspect each typed item failure separately. |

An empty complete result is a valid negative answer. An empty qualified result is
not proof that nothing matched.

## Collect passive status

When the integration or outer invocation rejects, run bare `kast` from the exact
repository root:

```console
cd /path/to/kotlin-repository
kast
```

This command does not start, repair, or synchronize the runtime. Its JSON report
can identify:

- the installed control version and compatible IDEA/JBR observation;
- the exact repository root and runtime identity;
- cache and bootstrap state, including a bounded corrective action when one is
  available;
- admitted network configuration or its blocker; and
- the private trace destination and enabled state.

Attach this report to an internal support request only after removing host paths
that your organization treats as sensitive.

## Resolve common cases

### The integration does not start

`kast codex` writes one finite reason to standard error. Check these boundaries
in order:

1. `kast` and `codex` are available to the launching environment.
2. The command runs from the intended Kotlin Gradle repository.
3. `CODEX_EXECUTABLE`, when set, is an absolute executable path.
4. `KAST_ENABLE_APP_SERVER` is `0` or `1`.
5. `KAST_APP_SERVER_TOOLS` is a non-empty, duplicate-free subset of exact names
   returned by `kast --schema`.

The broker rejects startup if it cannot prove the installed projection, the
Codex protocol, the tool catalog, or an executable route. Do not work around
that rejection with handwritten tool definitions.

`kast codex` automatically enrolls the current workspace, refreshes the owned
login bootstrap, and recovers stale or malformed owned broker readiness before
launching the client. `kast app-server status` reports exact paths under `paths`,
including `serviceLog`, `launchEnvironment`, `savedConfiguration`, and
`workspaceRegistry`. Set `KAST_DEBUG=1` to stream bounded, payload-free launch
stages and those diagnostic paths to the calling process's stderr.

If ordinary recovery cannot establish a healthy service, explicitly request the
destructive mode:

```console
kast app-server repair --destructive
```

This retires the exact launchd label for the active physical installation,
deletes that installation's runtime, cache, broker, and workspace-registry state,
re-enrolls the current workspace, rewrites the login bootstrap, and starts clean.
It does not follow symlinks found inside the owned state tree. The operation is
intentionally unavailable without `--destructive` because cached indexes and
durable invocation evidence are discarded.

### A stale reference rejects

Source or imported-model changes can move the semantic generation. Ask the agent
to repeat its `kast.query` search and preserve the newly returned references.
Do not edit or reconstruct an old reference.

### Startup reports a host or import blocker

Follow `bootstrap.correctiveAction` when the passive status report provides it.
Typical blockers concern the supported IDEA/JBR pair, Gradle project import, or
an explicitly configured network policy.

Do not rebuild private state as a generic first response. A rebuild discards a
reusable cache and should be used only when the reported corrective action or a
confirmed cache problem requires it.

### Gradle input links reject during startup

Kast admits conventional Gradle model inputs through symbolic links when each
link resolves inside the canonical workspace. File contents, stored link targets,
resolved entry kinds, and selected descendants beneath directory aliases are
retained separately. Retargeting a link invalidates the imported model even if
the new target has identical content. Two logical aliases remain distinct inputs.

Capture failures report `capturing-model-inputs` with `bootstrap.evidence.input.path`
and a finite `reason`: `OUTSIDE_WORKSPACE`, `LINK_CYCLE`, `TARGET_MISSING`,
`UNREADABLE`, or `UNSUPPORTED`. Correct that repository input and run `kast start`
again. Kast does not materialize links or delete dangling inputs. The previously
selected Gradle JVM remains recorded in the bootstrap report. A JVM property
input can reject earlier during `selecting-gradle-jvm`, before a selected JVM
has been established.

### The sidecar runs out of heap

Set one maximum heap for the next IntelliJ sidecar launch:

```console
KAST_INDEXER_MAX_HEAP=8g kast start
```

Accepted values are positive integral lowercase `m` (MiB) or `g` (GiB), with a
minimum of `256m`. The default remains `1536m`; the initial heap remains `256m`.
Blank values, fractions, missing units, negative values, and overflow reject
before the sidecar launches. The maximum admitted value is `2147483647m`.

For a persistent setting, add `KAST_INDEXER_MAX_HEAP=8g` to
`${XDG_CONFIG_HOME:-$HOME/.config}/kast/environment`. Values are literal.
An explicitly present process environment value takes precedence, including an
invalid value, which rejects instead of falling back. Duplicate saved records
reject. The installer preserves this setting during upgrades.

A running sidecar keeps its existing heap. Run `kast stop`, then start with the
new setting. Changing heap does not change semantic cache identity or require
rebuilding or reseeding caches. This setting controls Kast's isolated IntelliJ
sidecar; Gradle daemon memory and the interactive IDEA heap have separate settings.
Ambient `JAVA_OPTS`, `_JAVA_OPTIONS`, `JAVA_TOOL_OPTIONS`, and `JDK_JAVA_OPTIONS`
remain excluded from the sidecar launch.

The private cache's `log/startup.log` contains a `kast-indexer-heap` record with
`requestedMaxHeapMiB` and JVM-observed `observedMaxHeapBytes`. Use that record to
confirm the active process heap; current caller configuration cannot change a
running JVM. A higher cap addresses a memory limit but does not establish the
cause of memory pressure or guarantee that every workload fits.

### A query reaches a limit

Qualified query output retains its limitations and item failures. Narrow the
scope or relationship expansion first. Increase a result, work, byte, or elapsed
limit only when the larger request is intentional and remains within the
harness-provided schema.

## Escalate with bounded evidence

For a reproducible product defect, include:

- the Kast version and source revision;
- macOS architecture and the observed IDEA, Kotlin plugin, and JBR versions;
- the outer invocation status and diagnostic, if present;
- the inner semantic status, limitations, and rejection codes;
- the passive `kast` report; and
- a minimal reproduction that does not include proprietary source.

Broker activity records contain bounded identities and completion states, not
tool arguments, results, or source. Semantic trace paths come from the passive
status report; apply your host's retention and access policy before sharing them.

Report security issues through [GitHub private vulnerability
reporting](https://github.com/amichne/kast/security/advisories/new), not a public
issue.
