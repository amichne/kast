Ask your agent in plain language. Its installed guidance chooses the Kast commands.
Most sections below give an example question, the answer you get, and the limit to keep in mind.

## Find the right declaration

```text wrap
Find submitOrder in the checkout package. Show each signature and location.
```

**You get:** each matching declaration, with its owner, signature, and file location.

Two functions can have the same name. When you or the agent pick one, Kast returns an exact reference, an ID for that declaration, so follow-up questions stay on that function.
See [Find and trace code](/reference/search).

## Find callers

```text wrap
Which functions call submitOrder, and where are they?
```

**You get:** the resolved callers, with file locations, and whether the search finished.

**Limit:** callers show where the code calls the function. They do not show that those calls run at runtime.

<span id="where-does-this-value-go" />

## Follow a value

```text wrap
Where does the customer returned by loadCustomer go?
```

**You get:** a path through supported steps: returns, arguments, and field reads. Each step keeps its evidence.

**Limit:** the path stops where Kast does not support a step. It does not guess past that point.
See [Program tracing](/reference/program-tracing), or try the [interactive example](/explanation/value-journey).

## Check problems that IDEA reports

```text wrap
Check the checkout module for errors and warnings.
```

**You get:** IDEA's file diagnostics, with locations, and which of the requested files IDEA checked.

**Limit:** this reads IDEA's diagnostics. It does not run a build.
See [Inspect IDEA diagnostics](/how-to/inspect-diagnostics).

## Make a supported edit

Kast can add a declaration to an existing file or replace the body of a supported function.
It checks the target first and returns a change receipt.

Edits need the [optional MCP setup](/reference/integrations#optional-mcp). The guidance from `kast install` only reads code; your agent still edits files with its own tools.
See [Make a targeted change](/reference/change).

<span id="what-if-kast-cannot-finish" />

## When a search does not finish

Every answer says whether the search finished, and in what scope. [Results](/reference/responses) names the fields, and the CLI exits with status `0` only when the search finished.
If it did not finish, an empty answer does not show that nothing exists. Narrow the question or follow the reported recovery step.

[Understand the evidence](/explanation) explains this in more detail. [Help](/troubleshooting) covers failures.
