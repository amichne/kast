## Installed server projection

The installed `serverProjection` is the broker contract. Read
it from the exact configured `kast` executable; never infer tools from a
version string or human-readable command text.

The projection defines:

- Every operation marked `public`, with its canonical ID and evidence document.
- Tool names, descriptions, and closed input and output JSON Schemas.
- Whole-document CLI invocation paths, deferred loading, and approval policy.
- Read façades such as `symbol_lookup`,
  `semantic_query`, `impact_analyze`, and `diagnostic_check`.

Approval is closed:

- Read tools use `none`.
- Every `change_*` tool requires `explicit` approval.

## Sidecar endpoint operations

Semantic command paths are machine-facing. Run them from the repository root and
provide exactly one canonical JSON request document on standard input. The request
shape and constraints in `kast --schema` are generated from the same Kotlin
serializer that decodes the document.

- Success emits one JSON document on standard output.
- Rejection emits one diagnostic document on standard error.
- The private IntelliJ sidecar publishes 10 operations marked
  `public` by the generated registry.

| Operation | Command shape | Result role |
| --- | --- | --- |
| `query.run` | `kast query run < request.json` | Search, refine, filter, and expand exact-symbol sets inside Kast. This is the default read surface. |
| `symbol.discover` | `kast symbol discover < request.json` | Find bounded candidates by name, location, structure, or text. |
| `symbol.inspect` | `kast symbol inspect < request.json` | Refine a candidate or inspect an exact selector and return exact compiler evidence. |
| `source.read` | `kast source read < request.json` | Read bounded source text and structure without establishing compiler identity. |
| `relation.read` | `kast relation read < request.json` | Read one bounded semantic relation from an exact symbol. |
| `traversal.run` | `kast traversal run < request.json` | Read one exact-root semantic generation as normalized node, edge, and proof tables with explicit depth and result limits. |
| `diagnostic.check` | `kast diagnostic check < request.json` | Read compiler diagnostics for one explicit scope. |
| `change.plan` | `kast change plan < request.json` | Sidecar route is available only for `add-declaration`. Derive a typed plan without writing the workspace. |
| `change.apply` | `kast change apply < request.json` | Apply one admitted plan, publish its successor, verify it, and return a receipt. |

## Request document limits

Kast accepts one UTF-8 request document of at most 4 MiB on standard input.
Constrained values, including continuations, retain their smaller serializer-owned
bounds. Malformed, wrong-family, non-canonical, and over-bound values reject before
runtime dispatch. Ordinary command-selection arguments remain limited to 4,096
characters and an invocation to 66 arguments.

## Runtime lifecycle

Kast owns the isolated sidecar lifecycle.

- `start` and semantic commands may launch a release-line-compatible local IDEA build.
- Bare `kast` observes state; `stop` targets only an already proven endpoint.
- The release pair defines compatible platform lines, not patch equality.
- Admission retains the exact observed build pair in runtime identity.

Process ownership is explicit:

- Unset or `KAST_ENABLE_LAUNCHD=0`: launch directly.
- `KAST_ENABLE_LAUNCHD=1`: use launchd.
- Any other value: reject the request.

| Command | Effect |
| --- | --- |
| `kast start` | Start or reuse the exact-root private sidecar and return workspace readiness. |
| `kast stop` | Stop only the process proven to own the exact-root sidecar endpoint. |

## Process-local commands

Bare `kast` reports installed control, IDE/JBR, exact-root runtime, cache,
bootstrap, and network provenance without starting or repairing anything.
One qualified Kast tool catalog and execution path serves two Codex host
projections. `kast codex` preserves the terminal client path, while
`kast codex desktop` launches Codex Desktop with a process-local façade. Desktop
then invokes `kast-codex app-server` as its Codex CLI-compatible child process.

| Command | Result |
| --- | --- |
| `kast` | Passively inspect local identity and state, including typed blockers. |
| `kast codex` | Launch the existing broker UDS and Codex remote-client host. |
| `kast codex desktop` | Launch Desktop with process-local façade and independently resolved upstream Codex identities. |
| `kast-codex app-server` | Present JSONL App Server stdio to the parent and proxy through the same qualified Kast integration. |

## Default local traces

Ready endpoints write topology and traversal spans to a private folder derived
from the exact socket namespace.

Bare `kast` reports:

- Format and enabled state.
- `directoryPath` and `traceFilePath`.

The directory uses mode `0700`; trace files use `0600`. Allowlisted span fields
exclude paths, selectors, source text, exception messages, and stack traces.
