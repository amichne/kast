The installed Kast MCP process runs over stdio from the client's repository
directory. After MCP negotiation, `tools/list` is the authority for this
release's tool names, `inputSchema`, and `outputSchema`.

| Read tools | Purpose |
| --- | --- |
| `query_symbols` | Declarations, exact references, relations, and pipelines |
| `source_read` | Bounded source for an admitted selector |
| `check_diagnostics` | IDEA diagnostics for a path |
| `symbol_lookup`, `symbol_inspect` | Candidate discovery and refinement |
| `health_check`, `validate_workspace` | Readiness and explicit probes |

`change` is the write tool. The App Server's `workspace_lifecycle` is a
separate hosted tool.

## Call and result

An MCP client sends a JSON-RPC tool call after negotiation:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {"name": "health_check", "arguments": {}}
}
```

For a query, set `name` to `query_symbols` and use the
[example arguments](/search). A call returns a JSON-RPC `result` with
`content`, `isError`, and, when the document is admitted,
`structuredContent`.

| `structuredContent.status` | Required meaning |
| --- | --- |
| `complete` | `data`, `coverage`, and `basis` are present. |
| `partial` | Those fields and `stopReason` are present. |
| `rejected`, `unavailable` | A typed `error` is present. |

The generated [tool call wrapper](/reference/models/mcp-tool-call-result) and
[read union](/reference/models/mcp-read-result) show their field schemas.
The [investigation](/reference/models/mcp-investigation-result) and
[change](/reference/models/mcp-change-result) tools have separate result unions.
`data` keeps the canonical operation document; use the generated
**Query symbols** entry in this tab or the corresponding tool schema to
decode it. Preserve exact `ref` values and any qualification.

The OpenAPI `POST /callables/…` labels in this pane organize hosted tool
schemas. They are documentation paths, not HTTP endpoints. The direct MCP
result uses the wrapper above.
