---
title: "Read a symbol"
description: "Use exact compiler references, locations, and signatures without guessing identity."
icon: "braces"
---

Use a symbol's exact reference to carry declaration identity into another request. `query_symbols` returns these references with Kotlin declarations. Keep coverage with each reported symbol.

| Field | Use |
| --- | --- |
| `ref` | Pass unchanged to later queries. |
| `location` | Find the established declaration. |
| `signature` | Distinguish compiler-established declarations. |
| `source` | Inspect bounded committed source, when requested. |

To read source context, request `SOURCE`. A name, path, or reconstructed token does not establish exact identity. See the [query item schema](/reference/models/query-item) for fields. The [scoped example](/reference/walkthrough#1-find-a-declaration-and-inspect-its-source) includes source output.

Local `val` and `var` declarations use `LOCAL_PROPERTY` signatures. Local named functions use `LOCAL_FUNCTION` signatures. Their addresses keep the exact file and declaration range, plus compiler identity and the containing declaration's range. They also keep bounded ranges for lexical ownership.

Function signatures keep callable facts. Property signatures keep type and `VAL` or `VAR` mutability. Declarations with the same name in different scopes keep distinct identities.

Pass the reference unchanged to exact reads and relations. Kast can reacquire a local reference with fresh compiler evidence only while its owning file content stays unchanged. After you edit or move a local declaration, discover it again.

Local variable identity does not establish assignment flow. Local function identity does not establish execution of a deferred body.
