Kast prepares the selected IDEA project when your agent sends a semantic request. Start the agent in the Kotlin Gradle repository or worktree that you want to inspect.

## What happens on the first question

Kast selects the exact Gradle root, reuses or starts IDEA, and waits for import and indexing. Project readiness controls query admission.

The first request can take longer than later queries. Background presentation is not assured. A trust prompt, unsaved document, or failed import can need your attention in IDEA.

Results belong to the selected worktree. References from another worktree need their own admission. Use the [first query](/agent-harnesses#run-the-first-query) to examine readiness and tool use.

## Control when an agent uses Kast

Ask your agent to use Kast for declaration identity, relationships, or saved query results. For text-only work, tell the agent to omit Kast calls.

To remove an installed registration, use `kast disconnect <harness>`. Restart that agent to unload the integration. Disconnect leaves IDEA, existing sessions, and other clients in place.

Semantic queries use automatic preparation. Kast has no management command to disable preparation while those queries remain enabled. Hosted App Server supplies explicit project actions through [workspace lifecycle controls](/workspaces#explicit-workspace-control-in-the-hosted-app-server).
