---
title: "Agent workspace setup"
description: "Prepare and manage a workspace through the agent tool contract."
---

`workspace_lifecycle` is an agent setup capability. Use it to prepare the requested
repository or worktree for compiler-backed queries; do not ask the user to run
workspace commands or manage lifecycle identifiers.

## Setup sequence

1. Inspect the selected host and existing projects.
2. Open the requested absolute repository root if it is not already available.
3. Poll a pending operation with `status`, preserving its host and request ID.
4. Wait for an opened result before requesting semantic evidence. Handle any
   reported blocker according to its finite reason.
5. Release the caller's interest when the workspace is no longer needed. Release
   does not close a project; close only eligible agent-managed projects.

Opening reuses the installer-selected IDEA or launches it when absent. It imports
and waits for semantic admission without deliberately activating the window.
Background behavior is best effort. A running IDEA with an unavailable plugin,
project trust, and unsaved documents can require user intervention. Semantic reads
do not open projects implicitly.

## Requests and identities

Send tagged request documents through the agent tool. For example:

```json
{"type":"open","root":"/absolute/worktree","requestId":"open-worktree-1"}
```

Harnesses use the hosted `workspace_lifecycle` contract from `kast --schema`.
This tool has no CLI invocation; workspace setup goes through the connected agent.

An asynchronous result contains `host`, `requestId` and `stage`. Use `status` with the
host returned by the pending result and that request ID. Preserve returned `target`
objects exactly: they contain the host incarnation, project incarnation and root.
A reopened root is a different target. Keep a request ID stable when retrying the
same operation; different input with that ID rejects.

| Action | Required input and behavior |
| --- | --- |
| `inspect` | No additional fields. Passive host, capabilities, projects and ownership. |
| `open` | `root`, `requestId`. Reuses without activation or reimport; otherwise links, imports and waits for semantic admission. |
| `present` | `target`, `requestId`. Reveals the existing window and protects it from cleanup. |
| `sync` | `target`, `requestId`, `effect`: `FILE_REFRESH` or `GRADLE_MODEL_RELOAD`. Uses the existing refresh owner. |
| `configure_sync` | `target`, `requestId`, `rule`: `off` or an exact `task_success` task and effect. Configures that project's existing refresh owner; a `configured` result returns the admitted rule. |
| `release` | `target`, `requestId`. Removes this caller's interest without closing. |
| `close` | `target`, `requestId`. Closes only an eligible managed project with no other clients. |
| `request_user_close` | `target`, `requestId`. Agent broker requests exact-target user approval for a borrowed/presented project. Direct requests have no approval authority. |
| `status` | `host`, `requestId`. Retained progress or terminal result, including after closure. |

Agent use is attributed to its coordinator thread. Preserve that caller identity
through setup and cleanup; release the same caller's interest when done.

## Resolve blockers

| Blocker | Next action |
| --- | --- |
| `TRUST_REQUIRED` | Review and trust the exact project in IDEA, then submit a new open request. |
| `UNSAVED_DOCUMENTS` | Resolve unsaved documents across the application yourself; native refresh and close can save all documents, so Kast blocks them. |
| `LAUNCH_METADATA_UNAVAILABLE` / `LAUNCH_METADATA_INVALID` / `LAUNCHER_MISSING` / `LAUNCHER_AMBIGUOUS` / `LAUNCHER_INVALID` / `LAUNCH_EXECUTABLE_UNAVAILABLE` | Repair or reselect the IDEA installation. An already-running compatible host remains attachable without launch metadata. |
| `PLUGIN_UNAVAILABLE` | Load the installed plugin using IDEA's normal restart flow. Kast never restarts the application. |
| `PROJECT_BUSY` | Let native work finish; inspect the existing operation before requesting new work. |
| `OTHER_CLIENTS` | Other active callers must release their project use. Approval does not override shared use. |
| `USER_AUTHORIZATION_REQUIRED` | Use the agent's `request_user_close` flow for the exact target. Session-wide approval is insufficient. |
| `IMPORT_FAILED` / `UNLINKED_BUILD` | Inspect IDEA's native Gradle errors/settings, correct the cause, and request sync explicitly. |
| `CLOSE_VETOED` | Resolve the native close veto; the project remains available. |
| `WRONG_HOST` / `STALE_PROJECT` | Inspect again and acquire the current target; do not reuse an old incarnation. |
| `CAPACITY` | The application has reached its bounded operation capacity; no new work was admitted. |

Closing uses IDEA's normal veto-respecting path. Kast never saves or discards
buffers to make it succeed, force-closes a project, kills IDEA, or stops shared
Gradle daemons. Closing the last project leaves application control available.
Semantic reads remain passive and use the existing project-scoped compiler state.
