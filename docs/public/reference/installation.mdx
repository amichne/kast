Use the remote installer for initial setup, then `kast upgrade` for updates.
Kast manages its own Host on macOS ARM64 and Linux x86-64. Desktop IDEA is not a prerequisite.

<Warning>
  This page describes the managed-runtime contract under implementation. Native acceptance and publication are not yet complete. The remote main installer is not evidence that this branch is available.
</Warning>

<span id="before-you-install" />

## Requirements

Use a supported machine, a Kotlin Gradle project, Bash, curl, and standard archive and checksum utilities.
Kast supplies its private interpreter, Java runtime, and IntelliJ analysis runtime. No user Python or uv installation is required.
Your project still supplies its build configuration, dependencies, and any required credentials.

<a id="install" />

## Remote initial install

```shell
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh)" -- --channel preview
```

The installer selects one complete product: an immutable vendor base and exact Control, Host, and agent components.
It verifies the selected records and bytes before activation. A missing component is a failure, not permission to mix builds.
Installation does not grant trust to a project or start its Host.

The installation directory is `$HOME/.local/share/kast`.
The command path is `$XDG_CONFIG_HOME/kast` when `XDG_CONFIG_HOME` is nonempty, or `$HOME/.local/bin/kast` otherwise.
Add the printed command directory to `PATH` if needed. The installer does not edit shell profiles.

Use [agent setup](/reference/integrations) after installation. No desktop plugin installation or restart is needed.

## 1. Install the selected release

```shell
kast versions
kast upgrade --channel preview --dry-run
kast upgrade --channel preview
```

`preview` selects a complete preview build. `stable` selects a complete stable build.
`main` remains an alias for `preview`; new commands use `preview`.
A catalog entry identifies the selected product and its platform. Component publication alone does not establish a selectable product.

### Pin a published build

Use one selector: `--channel`, `--version`, or `--commit`.
Copy an exact version or revision from `kast versions`:

```shell
kast upgrade --version VERSION
kast upgrade --commit REVISION
```

An exact selector records a pin. An unqualified upgrade rejects a pin with `PINNED_BUILD`.
Use `kast upgrade --channel preview` to follow preview builds again.
Use `kast upgrade --repair` to restore the exact installed product, not to select a newer build.

## 2. Inspect installed state

The managed Host loads its plugin on demand. No desktop action is required.

```shell
kast status --json
kast status --all --json
```

Status separates installed product identity, update policy, unfinished transactions, and workspace Host observations.
It does not start a Host, grant trust, repair state, or contact release servers.
A recorded workspace is not proof that its Host can answer a query.

## 3. Prove a semantic connection

From a project whose build code you trust, run:

```shell
kast query --name DECLARATION_NAME --fields name,location --json
```

Replace the name with a declaration in your project. Check its file and the completion evidence.
The first explicit semantic request grants trust to the exact canonical workspace root, creates private state, and prepares its Host.
A sibling worktree has a separate root and trust record. Discovery and session hooks do not grant trust.

## Private workspace state

Each workspace has a private `HOME`, IDE profile, and default Gradle home.
This is process and profile separation, not an OS sandbox. Build code runs with your user permissions.

Saved installation or workspace settings can select an external Gradle home through `GRADLE_USER_HOME`.
Inherited credentials remain available to the build. Treat an external Gradle home as trusted input: it can contain credentials, properties, and init scripts.

Queries use the installed runtime and never consult release servers for an update.
Gradle import and dependency resolution can still require network access.
There is no public container creation, archive import, or desktop fallback step.

Use [Manage Kast](/reference/management) for scoped stops, exact repair, removal, and recovery.
