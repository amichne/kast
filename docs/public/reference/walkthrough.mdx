These examples show request syntax. They are not recorded results.
Use your project names and fresh references from each query.

For a small exercise with known source, use [the first-query tutorial](/tutorials/first-query).

## Start from remembered text

This `SEARCH_TEXT` request finds functions that contain the word `launchd`.

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_TEXT",
      "word": "launchd",
      "declarationKinds": ["FUNCTION"],
      "scope": {
        "type": "DIRECTORY",
        "relativeDirectoryPath": "app-server",
        "sourceSetNames": ["main"]
      }
    },
    "terminalStep": {"type": "EMIT", "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION"]}},
    "executionBudget": {"maxResults": 10}
  }
}
```

Text discovery returns the containing declaration and the line that matched. The match has a one-based line number and a UTF-16 range.

One ASCII identifier word is supported. A relation query must prove calls after discovery.

<a id="1-find-a-declaration-and-inspect-its-source" />

## Find a declaration

This example selects `QueryStepSyntax` in the Kast source. Replace the name and directory for your project.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "QueryStepSyntax",
      "declarationKinds": ["CLASS"],
      "scope": {
        "type": "DIRECTORY",
        "relativeDirectoryPath": "query/contract",
        "sourceSetNames": ["main"]
      }
    },
    "terminalStep": {
      "type": "EMIT",
      "output": {
        "type": "SYMBOLS",
        "fields": ["NAME", "LOCATION", "SIGNATURE", "SOURCE"]
      }
    }
  }
}
```

`CLASS` includes interfaces. Select the exact match by its signature and source location.

<a id="2-follow-its-implementations" />

## Find implementations

Copy the selected declaration's issued `ref` into this request.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {
      "type": "SYMBOL_REFS",
      "symbolRefs": ["<ref from step 1>"]
    },
    "steps": [
      {"type": "EXPAND_RELATION", "relation": "IMPLEMENTATIONS"},
      {"type": "DISTINCT_SYMBOLS"}
    ],
    "terminalStep": {"type": "EMIT"},
    "retention": "RETAIN"
  }
}
```

Each row identifies an implementation. [Combine query results](/reference/query-pipelines) shows how to compare this set with another query.

<a id="3-trace-callers-to-a-chosen-depth" />

## Trace callers

Use an exact function reference to trace callers through two levels.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {
      "type": "SYMBOL_REFS",
      "symbolRefs": ["<exact function ref>"]
    },
    "steps": [
      {"type": "WALK", "relation": "CALLERS", "maximumDepth": 2}
    ],
    "terminalStep": {"type": "EMIT", "output": {"type": "TRAVERSAL_RECORDS"}}
  }
}
```

The depth limits the source relationships that the query follows. It does not describe a runtime stack.

## Read the result

Examine completion and scope before a conclusion. An unfinished query does not prove absence.
Use [Staleness](/reference/staleness) for reference lifetimes and [Program tracing](/reference/program-tracing) for source-path limits.
