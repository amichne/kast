Use this guide to read more output from a preview, retained result reference, or completion rejection with `nextQuery`.

You need the original response and its issued handles. The original read state and retention lifetime must remain valid.

1. [Identify the issued capability.](#1-identify-the-capability)
2. [Read rows with their own cursor.](#2-read-the-next-row-page)
3. [Read evidence with its separate cursor.](#3-read-the-evidence-pages)

## 1. Identify the capability

Read the response's status, coverage, and progress. Select the action for its issued handle:

| Capability | Action |
| --- | --- |
| Output continuation | `RESUME` presents the remaining produced output. |
| Retained result reference | `READ_RESULT` presents stored rows and evidence. |
| Rejection's `nextQuery` | Copy the emitted `READ_RESULT` arguments unchanged. |

Keep the original status and limits. A saved rejection stays a rejection after the last evidence page.

For compact rows, join node and connection IDs through `relation_graph`. [Compact output](/reference/responses#compact-and-detailed-output) lists the joins.
Use `node.symbol.selector` when you need an exact reference. Do not use a node ID as a symbol or result reference.

## 2. Read the next row page

For retained symbol rows, substitute the issued result reference and cursor:

```json
{
  "request": {
    "type": "READ_RESULT",
    "result": "<issued result reference>",
    "cursor": 0
  }
}
```

Use `next_cursor` from the last reply to read the next page. Match the output to the retained row kind.

Count output rows. Graph entries describe row relationships and do not set the evidence cursor.

For retained binding rows, include `"output": {"type": "BINDING_ROWS"}`. [Results](/reference/responses) defines each retained output form.

## 3. Read the evidence pages

If `evidence_window.type` is `MORE`, use `evidence_window.end` as the next `evidence_cursor`.

Keep the row cursor distinct. After the last row, keep it at `invocation.accumulated_row_count`.

```json
{
  "request": {
    "type": "READ_RESULT",
    "result": "<issued result reference>",
    "cursor": 12,
    "evidence_cursor": 8
  }
}
```

The numbers illustrate positions only. Substitute the values from your response.

An evidence-only page can advance without a row. Continue until the response reports the final evidence position.

## 4. Cannot reuse saved state

If Kast rejects a handle, keep the reported cause. Do not substitute an exact reference for a retained result reference.

If the original state is not available, start a fresh query with current references. A fresh query produces a separate answer.

To reacquire an earlier exact reference, submit a fresh `RUN` with a `SYMBOL_REFS` source. Preserve an identity rejection if Kast returns one.

For source text, pass a newly issued reference to `READ_SOURCE.candidateRef`. `READ_SOURCE` checks the reference's original snapshot. It does not reacquire stale references.

Neither action updates retained rows or evidence.

`RETENTION_UNAVAILABLE` provides no result reference for unavailable evidence. Reading retained evidence does not extend its lifetime or resume semantic work.

[Query execution and evidence delivery](/explanation/query-lifecycle) explains the separate owners. [Results](/reference/responses) defines progress and failure variants.
