<a id="select-the-target-and-scope" />

## 1. Select the target and scope

Find the exact target before the write. Read its source. If several declarations match, select its owner and signature.

```text wrap
Use Kast to find retryLimit under checkout. Show matching signatures and locations. If several functions match, stop so I can choose. Read the selected function's source and check whether it has a supported block body before changing it.
```

Request the body replacement with an explicit preservation rule.

```text wrap
Use Kast to replace the chosen function's body with { return 3 }. Keep its signature and the source outside the body unchanged. Report verification and the change receipt; if the outcome is uncertain, preserve recovery evidence and stop before retrying the write.
```

Replacement supports a non-inline named Kotlin function with a block body and no contract. Expression bodies and unsupported ownership reject admission.

The tools do not create files, rename symbols, replace arbitrary ranges, or do multi-file refactors.

<a id="read-the-receipt" />

## 2. Establish the source effect

One public call owns planning, exact internal authorization, preimage admission, source effect, post-write examination, and receipt delivery.

The planned preimage must remain current before the write. Recovery evidence preserves the planned and resulting source effect when a later stage fails.

Examine the receipt's plan identity, phase, state, qualification, source location, and fresh reference. Review the resulting diff.

Known pre-write rejection can establish no write within its reported phase. A missing response or uncertain settlement after dispatch cannot establish that fact.

If the effect is uncertain, preserve the receipt. Read current source before another write. Complete the reported recovery before another write.

IDEA diagnostics and post-write examination cover only the receipt's scope. Run the project's build and tests after a verified source effect.

## 3. Use the supported input form

These examples use placeholders for current exact references. Pass issued handles unchanged.

### Add a declaration

```json
{
  "exactTarget": "<exact-ref-returned-by-Kast>",
  "declaration": "fun retryLimit(): Int = 3"
}
```

Select the existing file. Examine the insertion location. [The generated schema](/reference/callables/add-declaration) defines the full input.

### Replace a function body

```json
{
  "exactTarget": "<exact-function-ref-returned-by-Kast>",
  "body": "{ return 3 }"
}
```

Supply the full block with braces. [The generated schema](/reference/callables/replace-body) defines target and replacement admission.

### Carry exact identity across a change

Use the returned `freshRef` for later operations after a verified change. Earlier references still need current compiler identity admission.

The token prefix remains part of the opaque handle. Do not substitute one reference version for another.

[Staleness](/reference/staleness) protects read and preimage authority. [Lifecycles](/reference/lifecycles) describes uncertain mutation settlement and workspace recovery.
