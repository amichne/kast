A query result carries semantic facts, coverage, producer progress, and output presentation. Each field answers a separate part of the source question.

<a id="interpret-coverage-before-making-a-claim" />
<a id="read-coverage-before-a-claim" />

## Semantic status and coverage

| Status | Meaning |
| --- | --- |
| `complete` | Declared scope covered. |
| `qualified` | Stated limitations or unfinished work remain. |
| `rejected` | Input or state requirements prevented completion. |

Every fact keeps its producing scope and qualifications. Empty qualified output cannot establish absence.

Complete coverage describes finished enumeration in the declared supported domain. Semantic completion also needs the model's proof obligations.

<a id="read-an-automatic-query" />

## RUN completion

The query response uses `kast.query.run.v8`. Host and Control must agree on that contract.

Every public run uses `COMPLETE_ONLY` within `COMPILER_RESOLVED_STATIC_V1`. Success needs exhausted execution without item failures, omitted evidence, or unproven callback graphs.

Impact investigations also need conserved original ledgers and discharged obligations. Runtime activation and path feasibility remain outside the model.

<a id="read-evidence-from-a-completion-rejection" />

### Completion rejection evidence

`COMPLETION_UNPROVEN` preserves the finite cause and original coverage. When retention succeeds, its evidence contains a result reference, preview, original question, and `nextQuery`.

The copyable `nextQuery` uses public `READ_RESULT` arguments. The canonical `question` uses a different grammar and cannot replace those arguments.

`policyProgress` is `EVIDENCE_ONLY`. Reads of that result keep `POLICY_REJECTED_EVIDENCE`, even when original enumeration coverage is complete.

A historical checkpoint supplies evidence of producer progress. It grants no new public semantic execution.

When supplied, `seedQuery` starts a separate investigation from proven preview identities. It does not cover omitted rows or unfinished scope.

Retention failure reports its actual storage cause without an invented handle. `RETENTION_UNAVAILABLE` can preserve complete enumeration while necessary storage remains unavailable.

<a id="read-rows-and-evidence-pages" />

### Row and evidence positions

| Response field | Meaning |
| --- | --- |
| `invocation.accumulated_row_count` | Rows accumulated across admitted execution pages. |
| `invocation.preview.type` | `INLINE` includes every accumulated row. `PREFIX` includes an ordered preview. |
| `invocation.preview.row_count` and `encoded_bytes` | Actual preview rows and UTF-8 bytes of the encoded `items` array. |
| `invocation.stop.type` | Typed reason for the stop, with evidence for a failure. |
| `retention` and `next_cursor` | Issued result reference and position for more saved rows. |
| `evidence_window` | Independent evidence positions: `start`, `end`, and `total`. `MORE` means evidence remains. `FINAL` reaches the saved end. |

The preview uses `INLINE` when all accumulated rows fit. `PREFIX` presents an ordered portion under row and encoded-byte limits.

If retention succeeds, `READ_RESULT` presents more rows with the retained reference and cursor, without semantic replay.

Preview truncation does not change producer coverage. A complete retained result stays complete through its presentation pages.

Row and evidence cursors advance independently. An evidence-only page can advance `evidence_window` while its row cursor stays unchanged.

Evidence order is failures, omissions, walk observations, reference observations, discovery observations, then relation observations.

`evidence_window.type: MORE` names remaining evidence. Its `end` supplies the next `evidence_cursor`.

After the last row, the row cursor stays at `invocation.accumulated_row_count` while evidence advances. `FINAL` marks the stored evidence end.

<a id="follow-progress-not-row-count" />

## Producer progress and output progress

| Operation | Advances | Handle |
| --- | --- | --- |
| `RESUME` | Presentation of already-produced output | Issued `query-output:v1` token |
| `READ_RESULT` | Presentation of stored rows and evidence | Result reference with independent row/evidence cursors |

Public `RUN` owns semantic execution. Public `RESUME` uses an issued `query-output:v1` token to present already-produced output.

`READ_RESULT` presents immutable rows and evidence from the identified retained result. Neither action visits unexamined files or restarts discovery.

The issued `next_action` names legal presentation or recovery. Row count alone cannot establish completion or available output.

`retention_unavailable` records loss of the remaining suffix. A missing continuation does not prove a complete answer.

<a id="carry-the-correct-handle-forward" />

## Handle families

| Handle | Use |
| --- | --- |
| Exact symbol `ref` | Fresh `SYMBOL_REFS` query with current identity checks. |
| Retained-result reference | `RESULT`, composition, or `READ_RESULT`. |
| Row ID | Select a row from its owning result. |
| Issued output continuation | Output-only `RESUME`. |
| Result cursor | Page stored rows. |

An anonymous `candidateSelector` supplies `READ_SOURCE.candidateRef`. An evidence cursor selects a position in the separate evidence sequence.

Handles must keep their issued spelling and owning resource. Names, paths, and opaque token equality cannot replace canonical identity admission.

## Compact and detailed output

Compact output is the default. `verbose: true` adds execution details without a stronger semantic answer.

```json
{
  "request": {
    "type": "RUN",
    "source": {"type": "SEARCH_DECLARATIONS", "declarationName": "QueryStepSyntax"}
  },
  "verbose": true
}
```

`knownMinimum` counts established logical final output, including delivered rows. It does not count unfiltered candidates or remaining pages.

### Byte limits and callback proof

The final response has an encoded-byte guard. Detached callback proof uses separate conservative storage accounting.

A small row count cannot establish capacity in either allowance. A byte rejection preserves its scan state and obligations.

The IDEA `kast_semantic_read` receipt reports retention allowances, admitted accounting, required accounting, and finite decision counters.

That receipt measures conservative proof storage. It does not measure heap use or encoded output bytes.

## Saved state and identity

Exact references can get fresh compiler authority. Retained results and output continuations need their original workspace, owner, read state, and lifetime.

Changed epochs, owner retirement, expiry, or eviction can block reuse. Presentation cannot migrate an answer to another epoch.

[Staleness](/reference/staleness) explains admission and reacquisition. [Composition](/reference/composition) preserves input qualifications and rejects unproven absence.
