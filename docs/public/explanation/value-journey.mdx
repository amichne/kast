## Try three changes

- **Return a different value:** the list contains a separate value. The original route does not reach it.
- **Use the value twice:** choose either use of the same producer.
- **Remove a library rule:** the route stops where the example lacks evidence.

A search for `Pet` finds text in all these examples. The connections explain why the answers differ.

## What the illustration means

The example traces one `Pet`. A `PetListing` can carry it in `pet`, and a list can carry that listing in an element.
The listing and list keep their own identities.

The compiler identifies the function and callback. A reviewed rule for `map` connects a callback result to a possible list element.
Select **Evidence** to inspect that distinction and each source location.

This illustration uses [fixed Kotlin fixtures](https://github.com/amichne/kast/tree/main/relation/intellij/testData/r1-value-flow) and authored expected routes.
The displayed code uses pet-store names. The original fixtures stay unchanged.
It does not query Kast or record execution. Its final step does not prove a complete investigation.
