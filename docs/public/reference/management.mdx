Use the installed `kast` command to check and update Kast.
Save your work in your agent before an update. Start new agent sessions after it.

This page covers a desktop IDEA installation on an Apple silicon Mac. For containers, Linux, or `kast-task`, see [Without desktop IDEA](#without-desktop-idea).

<a id="inspect-the-installation" />

## 1. Check the installation

```shell
kast status --json
```

`status` only reads saved state. It does not start Java or change anything.
Each field is an observation with a `state` of `VERIFIED` or `UNAVAILABLE`, and a `value` or a `reason`.

| Field | What it tells you |
| --- | --- |
| `installedBuild.value.version` | The Kast build on disk. |
| `applicationHost.value.runtimeIdentity.buildIdentity.version` | The build that the running Host has loaded. `UNAVAILABLE` when no running Host advertises a loaded Kast. |
| `applicationHost.value.runtimeIdentity.mode` | `DESKTOP` for your IDEA, or `MANAGED_HEADLESS` for the private Host of a standalone installation. |
| `updatePolicy` | Whether `kast upgrade` follows a channel or a pinned build. |
| `unresolvedTransaction.value.records` | An unfinished install or update. An empty list means none. |

If the two versions differ, restart IDEA. If `records` is not empty, [resolve the unfinished update](#4-resolve-unfinished-recovery) first.

An `UNAVAILABLE` loaded build does not prove that no Host runs. A loaded Host does not prove that your project is ready; a complete query does.

<a id="upgrade" />

## 2. Update

List the builds you can select, and preview the update without changing anything:

```shell
kast versions
kast upgrade --channel main --dry-run
```

A preview returns `PLANNED`. Then apply the update:

```shell
kast upgrade --channel main --restart-ide
```

- `--channel main` selects the latest development build. It replaces a pinned build.
- `--restart-ide` lets Kast restart IDEA normally when needed. A compatible running Host can reload instead.
- Running Kast sessions can end during the update.
- For another IDEA installation, add `--idea-home` with the exact app path.
- To pin a version or commit instead, see [Pin a published build](/reference/installation#pin-a-published-build).

Add `--json` for one structured result on stdout. Progress goes to stderr.

## 3. Read the result

The result's `type` says what happened. A rejection names its cause in `reason`. A successful update can also list `notices`.

| Result | Meaning | What to do |
| --- | --- | --- |
| `ACTIVATED` | The new build is installed, and every affected running IDEA loaded it. | Start new agent sessions. |
| `INSTALLED_NOT_RUNNING` | The new build is installed. IDEA was not running. | Start IDEA, then start new agent sessions. |
| `REJECTED` | Kast stopped before changing the installation. | Fix the `reason`, then repeat the update. |
| `REJECTED` with `reason: RESTART_REQUIRED` | The update needs an IDEA restart that you did not permit. | Repeat with `--restart-ide`. |
| `ROLLED_BACK` | The update failed, and Kast restored the previous installation. `failure` names the cause. | Fix the cause, then repeat the update. |
| `RECOVERY_REQUIRED` | Kast cannot prove that the update finished or was undone. | Keep the output, and [resolve it](#4-resolve-unfinished-recovery) before another update. |
| `REJECTED` with `reason: PINNED_BUILD` | `kast upgrade` without a selector found a pinned build. | Add `--channel main`, or select a version explicitly. |
| Notice `HARNESS_REFRESH_REQUIRED` | The Kast guidance in your agent tool, such as Codex, Copilot, or Pi, is older than the new build. | Repeat your original [agent installation command](/reference/integrations#refresh-guidance-after-a-core-change), keeping `--mcp` if you used it, then start a new session. |

Exit status is zero for `ACTIVATED` and `INSTALLED_NOT_RUNNING`, and nonzero otherwise.
Installed files alone do not mean `ACTIVATED`, and a stopped IDEA after a failed restart does not mean `INSTALLED_NOT_RUNNING`.

An update does not replay an interrupted source change. Check the source and its [change receipt](/reference/change#read-the-receipt) before another edit.

## 4. Resolve unfinished recovery

Use this after `RECOVERY_REQUIRED`, or when `unresolvedTransaction.value.records` is not empty.

1. Keep the recovery output. Fix the failure it names.
2. Run the update again:

   ```shell
   kast status --json
   kast upgrade --channel main --restart-ide --json
   ```

   This run first finishes or undoes the unfinished update, using the build that update selected.
3. When that succeeds, run the update once more to reach the latest build.

Unknown or damaged recovery records block the update.

<span id="reset-outcomes" />

A rollback restores the previous update policy. Agent sessions that the update ended stay stopped.
Restored files do not prove that the previous Host runs again. Check with `kast status --json`.

## Without desktop IDEA

`kast status` reports your installation and its own Host. It does not report container Hosts.

| Setup | Check | Update |
| --- | --- | --- |
| Workspace container | `kast container --json`. Each entry shows its `state`, `ENABLED` or `STOPPED`, and `container.runtime`, the runtime version it uses. | A container keeps the runtime it was created with, and `kast upgrade` does not change it. After an update, run `kast container rm ID`, then `kast container create --name NAME` from the workspace. |
| Linux | The same as a workspace container. | `kast upgrade` installs Apple silicon builds only. Install a newer [candidate build](/reference/installation#install-from-a-candidate-build) in a new root, import its runtime, and create your containers again. |
| `kast-task` | `"$root/bin/kast" status --json`. `mode` is `MANAGED_HEADLESS`. | Install a newer build in a new root with the [standalone procedure](/reference/installation#isolated-runtime). |

`rm` deletes the container's private state, so its next query prepares the Host again.
