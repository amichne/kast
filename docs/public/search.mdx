Ask the engineering question in ordinary language. Your agent translates it into `query_symbols`; the useful path is **discover → identify → relate → interpret coverage**. You only need the request JSON when debugging or integrating the contract directly.

<Note>
  The recorded examples below use the public [Kast repository at `56df091`](https://github.com/amichne/kast/tree/56df0912e46b182bb4ad8beabd1512823100fd72). Counts and coverage describe that captured run, not your current workspace. </Note>

## Start with three moves

<Steps>
  <Step title="Find the declaration">
    Ask for the declaration, the scope that should contain it, and the evidence you want back.

    > Use Kast to find `QueryStepSyntax` in the production sources under `query/contract`. Show its location, signature, and source. Keep its exact reference for the next question.

    The recorded run found one `QueryStepSyntax` in `QuerySteps.kt` with exhaustive coverage. The important output is not only the matching name: it is the issued exact reference plus the scope and coverage that make the result interpretable.

    <Accordion title="Show the recorded request">
      ```json
      {
        "request": {
          "type": "RUN",
          "executionBudget": {"maxElapsedMs": 15000},
          "source": {
            "type": "SEARCH_DECLARATIONS",
            "declarationName": "QueryStepSyntax",
            "declarationKinds": ["CLASS"],
            "scope": {
              "type": "DIRECTORY",
              "relativeDirectoryPath": "query/contract",
              "sourceSetNames": ["main"]
            }
          },
          "output": {
            "type": "SYMBOLS",
            "fields": ["NAME", "LOCATION", "SIGNATURE", "SOURCE"]
          }
        }
      }
      ```
    </Accordion>
  </Step>
  <Step title="Follow a semantic relationship">
    Reuse the exact reference instead of searching for the name again.

    > Reuse that exact reference to find the implementations of `QueryStepSyntax`. Show each declaration once and retain the result so we can compare it with another query.

    The recorded response returned ten implementations with exhaustive coverage. Keeping the result lets the next query consume established identities directly rather than reconstructing a list from prose.

    <Accordion title="Show the recorded request">
      ```json
      {
        "request": {
          "type": "RUN",
          "executionBudget": {"maxElapsedMs": 15000},
          "source": {
            "type": "SYMBOL_REFS",
            "symbolRefs": ["<ref from step 1>"]
          },
          "steps": [
            {"type": "EXPAND_RELATION", "relation": "IMPLEMENTATIONS"},
            {"type": "DISTINCT_SYMBOLS"}
          ],
          "retention": "RETAIN"
        }
      }
      ```
    </Accordion>

    <Accordion title="Show a recorded result excerpt">
      ```text
      QueryStepSyntax.Where
      QueryStepSyntax.Concat
      QueryStepSyntax.Intersect
      QueryStepSyntax.Union
      QueryStepSyntax.Join
      ```

      The excerpt is five of ten names. The full retained result preserves every issued reference and its relation evidence.
    </Accordion>
  </Step>
  <Step title="Trace only as far as the question needs">
    Use a bounded walk when one relationship hop is not enough.

    > Find `QueryPlanCompiler.exactStage` under `query/contract` in `main`, then trace its callers up to two hops. Show the hop depth and call-site evidence, and report any unvisited work.

    The recorded walk returned `QueryPlanCompiler.admit` calling `exactStage` at depth 1, with exact compiler-confirmed relation coverage and no continuation.

    <Accordion title="Show the recorded traversal request">
      ```json
      {
        "request": {
          "type": "RUN",
          "executionBudget": {"maxElapsedMs": 15000},
          "source": {
            "type": "SYMBOL_REFS",
            "symbolRefs": ["<exact function ref>"]
          },
          "steps": [
            {"type": "WALK", "relation": "CALLERS", "maximumDepth": 2}
          ],
          "output": {"type": "TRAVERSAL_RECORDS"}
        }
      }
      ```
    </Accordion>
  </Step>
</Steps>

## Read the answer before asking the next question

A useful Kast result has two dimensions: **facts** and **coverage**. A returned caller is established evidence even when the wider traversal is qualified. An empty qualified result is not evidence that nothing exists.

## Adapt the question to your repository

Give the agent the declaration name or exact reference, the narrowest useful module or directory, and the relationship you need. Specify whether you want unique declarations, individual use sites, or a bounded trace.

A discovery scope limits where starting symbols are found. It does **not** confine later relationship destinations to that directory. Add a destination filter when that distinction matters.

<Info>
  Preserve issued references verbatim. A name, file path, or source excerpt can help a human recognize a declaration, but none of them substitutes for the exact reference Kast issued.
</Info>
