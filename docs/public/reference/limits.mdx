Execution grants limit resource use for a fixed question. They do not change source scope, traversal extent, or the completion model.

## Execution budget

| Field | Unit | Meaning |
| --- | --- | --- |
| `maxElapsedMs` | Milliseconds | Elapsed allowance for the admitted operation. |
| `maxWorkUnits` | Work units | Allowance for accounted semantic work. |
| `maxResults` | Rows | Result allowance. A row limit alone does not prove completed semantic work. |
| `maxReturnedBytes` | Bytes | Allowance for returned data. Callback-proof storage uses separate accounting. |

Omission or `null` selects configured defaults. Positive requests remain subject to operator and transport ceilings.

The response reports the admitted grant. Internal semantic pages share the original run's grant rather than a fresh allowance for each page.

Public output continuations and result cursors permit presentation only. They do not enlarge the original semantic grant.

## Completion failures

| Code | Failed fact | Preserved evidence |
| --- | --- | --- |
| `COMPLETION_UNSUPPORTED` | The output or question has no supported completion proof. | The finite cause. |
| `COMPLETION_UNPROVEN` | Execution or callback proof does not establish the requested complete answer. | Original coverage and available retained evidence. |
| `INVESTIGATION_UNPROVEN` | An impact investigation lacks original evidence, complete path selection, or discharged obligations. | The investigation's original accounting. |
| `RETENTION_UNAVAILABLE` | Necessary evidence storage failed. | Original enumeration coverage and the storage cause. |
| `RESULT_FIELD_UNAVAILABLE` | The retained result lacks the requested field or finalized witness section. | The result's original qualifications. |

The generated result schemas define closed variants and case-specific details. The table groups common proof failures rather than every external error.

Complete enumeration can coexist with unproven callback activation or an unavailable investigation ledger. Completion preserves each independent reason.

## Identity and state failures

Retained results and output continuations need their original workspace, owner, read state, and lifetime. Exact references need current compiler identity admission.

A larger grant cannot restore evicted state, renew expiry, or repair an owner mismatch. [Staleness](/reference/staleness) explains those failures.

`READ_SOURCE` needs an issued `candidateSelector` as `candidateRef`. An exact symbol token cannot substitute for that anchored-source capability.

## Write failures

A lost response does not establish absence of a source effect. A timeout or cancellation after dispatch needs phase and recovery evidence.

Known pre-write rejection can establish that no effect occurred within its reported phase. Uncertain settlement needs source inspection before another write.

[Change recovery](/reference/change#read-the-receipt) supplies that procedure. [Lifecycles](/reference/lifecycles) describes the hosted mutation fence.
