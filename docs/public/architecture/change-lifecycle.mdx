A source change needs both an exact target and authority for the planned source state. A successful read alone does not authorize a write.

1. Planning binds a supported intent to an exact source target and preimage.
2. Application loads the stored plan identity and reexamines the source before mutation admission.
3. The write uses admitted authority and records recovery state.
4. Post-write examination produces a verification outcome. A later failure can require recovery after a source effect.

The diagram summarizes the ordered phases. It does not enumerate every encoded result variant.

<Warning>
  A missing response does not prove that no write occurred. Preserve the receipt and inspect current source before another write.
</Warning>

## What verification establishes

The receipt describes the plan, phase, resulting state, and available evidence. Its verification applies to the reported scope.

The public tools support declaration insertion and supported block-body replacement. They do not provide arbitrary refactoring or prove a successful project build.

[Make a targeted change](/reference/change) gives the procedure and recovery steps. [Generated callable schemas](/reference/schemas) define exact inputs and result variants.
