Use the tool that names your intent. Every search uses the session workspace's saved, indexed IntelliJ state and preserves each matching declaration and its compiler evidence.

| Intent | Tool |
|---|---|
| Known class-like declaration name | `kast.search_classes` |
| Known function or method name | `kast.search_functions` |
| Unknown/mixed kinds, properties or type aliases | `kast.search_declarations` |
| Compiler diagnostics for a file or directory | `kast.check_diagnostics` |
| Enumeration, returned references or ordered transformations | `kast.query_symbols` (deferred) |

## Find your first declaration

Call `kast.search_classes` with:

```json
{"class_name":"OrderService","name_match":null,"scope":null}
```

The same input works with `kast tool search_classes < request.json`. Use `function_name` with `search_functions`. These searches return names, locations, signatures and opaque `symbol_ref` tokens alongside completeness evidence. Every matching overload remains separate. During migration, `symbol_ref` repeats the exact bytes in `ref.token`.

Controls must be present. `null` selects the documented default: exact, case-sensitive name matching and recursive directory `.` in the imported source-set names `main` and `test`. Names are simple declaration identifiers; use a package scope for qualification. Fuzzy matching requires `"name_match":"fuzzy"` and never runs as a hidden retry.

For a property or an unknown declaration kind, call `search_declarations`:

```json
{
  "declaration_name": "retryCount",
  "name_match": null,
  "scope": null,
  "declaration_kinds": ["property"]
}
```

`declaration_kinds: null` includes the supported `class`, `function`, `property` and `type_alias` families. Empty or duplicate kind selections reject. Constructor discovery is not advertised.

## Narrow the search

A directory scope uses paths relative to the session workspace root:

```json
{
  "function_name": "submitOrder",
  "name_match": null,
  "scope": {
    "relative_directory_path": "services/orders",
    "include_subdirectories": true,
    "source_set_names": ["main"]
  }
}
```

A package scope instead uses semantic Kotlin package names:

```json
{
  "class_name": "OrderService",
  "name_match": null,
  "scope": {
    "package_name": "com.example.orders",
    "include_subpackages": false,
    "source_set_names": null
  }
}
```

The two closed shapes are exclusive. Mixed fields, absolute paths, parent traversal and non-canonical paths reject. `source_set_names: null` means exactly `main` and `test`, not every imported source set. Explicit names such as `integrationTest` or `commonMain` must match imported Gradle ownership. Empty and duplicate selections reject. A known absent source-set name contributes no declarations.

Source-set restrictions intersect the chosen directory or package during discovery. They do not constrain later expansion destinations.

## Check diagnostics separately

Call `kast.check_diagnostics`:

```json
{"relative_path":"src/main/kotlin/orders/OrderService.kt","max_diagnostics":null}
```

A path may name a file or directory. Use `.` explicitly for the workspace root. Null selects at most 100 returned entries; the positive maximum is 1000. This request does not build the project. It is independent of diagnostic logging detail and bounded by the host's diagnostic scope policy.

## Use the result

1. Read the outer `status`, then the semantic outcome in `document`.
2. Inspect each match's `kind`, `name`, `location`, and `signature`. Keep overloads separate.
3. Retain `symbol_ref` verbatim for a follow-up query or change plan.
4. Read `failures` and any `qualification` before making a completeness claim.

[Read a response](/reference/responses) explains the layers.
[Symbol results](/reference/symbols) explains the compiler fields.

For callers, implementations, enumeration, or returned-reference input, continue
with [Query pipelines](/query-pipelines). A query expansion returns declarations;
use `semantic_query` when you need individual use-site facts.

<Accordion title="Why did a search miss a saved edit?">
  Save the file and let IDEA finish indexing. Kast reads the saved, indexed
  project, not an unsaved editor buffer. If the host is unready, follow its typed
  blocker. If a reference is stale, repeat discovery and use the new token.
</Accordion>
