# Background knowledge refresh

Work only in this isolated checkout. Do not commit, push, open a pull request,
change Git configuration, fetch, install schedulers, or publish anything.
Do not print credentials, source payloads, or unbounded diagnostics.

Use the native OpenWiki begin, plan, next, submit, and finish lifecycle.
Follow the tool's returned obligations and stop if an obligation cannot be met.
Resume the native checkpoint instead of replacing its queue. Preserve stable
Claim IDs and submit sparse confirm, revise, add, or retract decisions only for
Claims that need attention. Native producers own Claims, verification stamps,
page manifests, and run metadata. Do not write or repair their sidecars directly.
Examine stale Claims against their cited current sources; do not update dates blindly.
Review due associations against their exact source evidence. Keep the prior
review identity when the Claim and evidence do not change. Do not change
`reviewedSourceRevision` merely because of age or an unrelated source change.
Preserve unsupported or uncertain claims as unresolved; never manufacture proof.
Age requests maintenance. It does not establish current evidence or authorize
new verification stamps. Unrelated changes do not need Claim metadata rewrites.
Write native outputs only under openwiki/. Keep status evidence in the caller's
external result. Do not change public source prose or other source inputs.
Run focused checks relevant to your edits. Report failures and work you did not review.
The caller retains the worktree for human review and integration.
The caller freezes native source bytes and HEAD. A change to a model-visible
source input, including public prose, invalidates that candidate. Keep native
maintenance separate from a new authored-source candidate. A successful agent
exit is not native completion or full bundle qualification. Only the existing
publication owner can establish qualification for the exact completed candidate.
Do not advance an accepted snapshot after partial work or failed qualification.

For scheduling, configure a host scheduler separately with an explicit invocation
of this tool using --run and an external state directory. No scheduler is installed
by this procedure. In an ephemeral cloud environment, invoke it on environment
startup; persistence requires a separately configured host scheduler.
A proposed daily trigger must share the manual workflow's concurrency group.
Keep that trigger disabled until an authorized authentication check without user input
and model-access check succeeds. `--readiness` reports only credential presence
and never qualifies authentication or a daily schedule. Do not expose credentials.

The caller preserves interrupted native checkpoints and its external result.
Use `--resume <owned-run-id>` with the same state directory to continue that
frozen candidate. Source or checkpoint mismatch stops the resume. Reassess the
exact candidate before integration. Partial progress remains reviewable, not accepted.
