A tool call reaching Kast does not by itself prove that the semantic question
succeeded. Read the outcome carried by the semantic document.

## Three semantic outcomes

| Outcome | How to use it |
| --- | --- |
| **Complete** | The operation met its admitted scope, bounds, and completeness contract. The payload can support the claim described by the request. |
| **Qualified** | The payload remains useful only with its attached limitations. Do not infer facts beyond the reported coverage. |
| **Rejected** | Kast established no successful semantic payload. Use the typed reason to repair or reformulate the request. |

Query results may also retain failures for individual items. Those failures do
not erase successful items, but they prevent a claim that every requested item
was refined or expanded.

## Evidence belongs to coordinates

Kast retains the coordinates that determine where an answer is valid:

- the exact canonical repository root;
- the semantic workspace generation;
- the requested scope and operation;
- resource and traversal bounds; and
- any qualification or per-item failure.

References returned by Kast carry some of this proof. Agents and harnesses must
preserve them verbatim rather than rebuilding them from a name or file path.

If source or imported-model evidence changes, an older reference can reject as
stale. Repeat the `kast.query` search to obtain a reference for the successor
generation.

## Judge a negative answer

Before concluding that a declaration or relationship does not exist, check the
outcome:

- An empty **complete** result is a valid negative answer within the admitted
  scope.
- An empty **qualified** result means the search was limited or incomplete.
- A **rejected** result supports no semantic conclusion.
- A result with item failures is complete only for the items that succeeded.

Transport or harness failures sit outside these semantic outcomes. See
[Troubleshooting](/troubleshooting) for the outer invocation layer and passive
status collection.
