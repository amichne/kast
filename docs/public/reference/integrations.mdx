Kast installs guidance for your agent to use the installed `kast` command.
These steps assume that Kast already exists on your machine.
The default composition uses the CLI. MCP remains an explicit option.

<span id="1-choose-the-client-and-transport" />

## 1. Install guidance for your agent

<Tabs>
  <Tab title="Codex">
    The bundled plugin supplies the Kast skill and CLI guidance.
    Codex owns its plugin resources and configuration.

    ```shell
    kast install codex
    ```

    Start a fresh Codex session in your Kotlin repository or worktree.
  </Tab>
  <Tab title="Copilot">
    Kast installs the canonical CLI guidance through Copilot's plugin resources.
    Copilot owns those resources and its configuration.

    ```shell
    kast install copilot
    ```

    Start a fresh Copilot session in your Kotlin repository or worktree.
  </Tab>
  <Tab title="Pi">
    Kast copies the canonical skill into Pi's native skill directory.
    Pi discovers that skill for the new session.

    ```shell
    kast install pi
    ```

    Start a fresh Pi session in your Kotlin repository or worktree.
  </Tab>
</Tabs>

Each command examines the installed release and the provider's actual resources.
A successful installation does not establish that an existing agent session contains the new guidance.

<span id="task-tools" />

### Optional MCP

Add `--mcp` to select the optional MCP composition:

```shell
kast install codex --mcp
kast install copilot --mcp
kast install pi --mcp
```

The task service needs uv and Python 3.12 or 3.13.
Its script locks own the dependency versions.
The persistent IntelliJ IDEA Host supplies Kotlin semantics for both the CLI and MCP.

To return to CLI-only guidance, repeat your agent's command without `--mcp`.
Kast removes only exactly owned MCP resources. Foreign registrations stay unchanged.

## 2. Ask about your code

Give your agent the function's file and name.

```text wrap
Use the Kast CLI to find the callers of this function. Show the source locations and explain how they use it.
```

The agent can inspect the installed contract with `kast describe`.
See the [CLI reference](/reference/cli) for command forms and the [example questions](/search) for another task.

Returned evidence applies to its stated worktree, source state, and scope.
A successful guidance installation does not prove that a semantic query succeeds.

## 3. Export the canonical skill

To export the skill into the current repository, run:

```shell
kast install skill
```

The default parent is `./.agents/skills`. Kast writes the skill under `./.agents/skills/kast`.

To select another parent directory, use `--output`:

```shell
kast install skill --output ./guidance
```

This command selects `./guidance/kast` as the skill directory.
`--output` belongs to `install skill`. `--mcp` belongs to agent installation.

A complete identical skill returns `ALREADY_INSTALLED` without writes.
A different or incomplete skill returns `SKILL_EXISTS` and keeps every byte.
Select another output directory or explicitly remove the old skill before another export.

## Refresh guidance after a core change

Core replacement does not refresh copied skills or cached provider resources.
If Kast reports `HARNESS_REFRESH_REQUIRED`, repeat your agent's installation command:

```shell
kast install codex
```

Use `copilot` or `pi` for those agents. Keep `--mcp` if you select the optional MCP composition.
Then start a fresh agent session.

Standalone skill exports keep the same no-overwrite rule after a core change.
