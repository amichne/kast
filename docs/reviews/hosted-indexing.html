01 / IMPLEMENTED DECISION

The primary indexing interface is now kast index

The command family is selected in the executable before installed-runtime composition. Its only runtime capability is an ExistingIdeClient. It cannot request the isolated worker used by the older product graph. A missing or unready IDE produces an explicit failure.

kast index status --root /path/to/kast
kast index classes Refinement --root /path/to/kast
kast index supertype io.github.amichne.kast.kernel.Refinement.Refined \
  --root /path/to/kast
kast index generate-completion zsh

The older kast ide spelling remains available through the same command implementation. --root can be omitted to discover the current directory’s Gradle root. Help and completion do not access a socket, discover a root, or start a runtime.

CommandAuthority and resultSupported boundary
index statusDescribes the selected host, root, PID, and operation list.Endpoint identity; each semantic query separately establishes readiness.
index classes NAMEIDEA’s Kotlin short-name index routes discovery; K2 resolves canonical class identities.Exact short name, saved Kotlin classes in supported cached authored source folders; at most 32 candidates.
index supertype QUALIFIED_NAMEThe full-class-name index selects exactly one class; K2 proves its direct supertype.Exactly one explicit supertype, with both declarations supported by the saved Kotlin source scope.

Index updates belong to IDEA. These commands never ask the user to run a Kast index sync. They reuse the imported project model, the live Kotlin index, PSI, and analysis services in their owning process.

INDEX_SYNC was already internal-only in the canonical registry. The new public index commands do not replace a public sync command. General semantic commands, workspace publication, and App Server still use the existing assembly; changing the indexing entry point does not silently reinterpret those contracts.

Authority: process entry point, runtime selection and client capability, canonical operation exposure.

02 / ACTUAL RUNTIME

A small semantic host inside the existing project

01 · OUTSIDE IDEANative Kast CLITyped arguments, root discovery, descriptor admission, bounded socket exchange.
02 · PROJECT SERVICEOwned local endpointOne admitted root and host, private Unix socket, closed request decoder.
03 · EXISTING IDEKotlin index + K2Cached model, scoped discovery, short cancellable read, canonical identities.
04 · BACK TO CLIDetached evidenceContent and epoch revalidated; shared schema and request correlation checked.

runtime:hosted is a separate plugin with a project-level service. It is not the isolated indexer descriptor installed into a developer IDE. The service owns a coroutine scope and socket lifetime, and delegates semantic work to workspace:intellij-read.

IDEA owns

The live workspace

Project identity, imported Gradle model, VFS, document commitment, Kotlin indexes, dumb mode, and K2 analysis services. IDEA continues to perform its normal synchronization and indexing when the build or sources change.

Kast owns

The proof boundary

Exact root admission, compatible host policy, finite operations and failures, bounded work, epoch checks, source-scope admission, detached result contracts, and endpoint retirement.

The host retains its packaged compatibility-policy authority across requests. Reconstructing equal-looking policy data had previously lost the original admission authority and caused RETAINED_AUTHORITY_MISMATCH. Retaining the original value preserves the proof rather than comparing only primitive fields.

The endpoint directory is ~/.kast/ide-hosted/<root-digest>, where the key is the first 16 SHA-256 bytes of the canonical root. The owner holds an exclusive lock and records the filesystem identity of its socket and descriptor. Retirement removes only the artifacts that still match that ownership. Unknown leftovers fail closed.

Authority: HostedEndpointService, OwnedHostedEndpoint, HostedQueryService.

03 / INFORMATION ONLY GETS STRONGER

Index discovery becomes compiler-proven identity

The new qualified selector removes the manual file-and-offset handoff. It carries a CanonicalCompilerSignature.ClassLike after input admission. Qualified names are bounded and each component must satisfy the admitted Kotlin name subset. Escaped or otherwise unsupported identifiers are rejected.

  1. Admit the request. Match the exact canonical root and original host service. Establish compatible existing-project authority, readiness, and a current read epoch.
  2. Capture the cached model. Detach bounded model facts from the open project without linking or importing a Gradle build. Restrict reads to supported production/test source folders classified as authored by cached model evidence.
  3. Collect index candidates. Query KotlinFullClassNameIndex using the qualified identity. The callback only checks cancellation and collects candidates. Candidate collection finishes before declaration PSI traversal or K2 analysis begins.
  4. Prove uniqueness. A complete empty result becomes DECLARATION_NOT_FOUND. Multiple candidates become AMBIGUOUS_DECLARATION. Overflow or incomplete enumeration is a failure. Only a unique complete collection yields HostedUniqueDeclaration.
  5. Resolve in the same admitted read. Locate the selected class name in its supported file and reuse the existing direct-supertype reader. Index routing and K2 analysis share one admitted read and epoch.
  6. Verify compiler identity. Compare the detached inheritor signature with the requested class-like signature. A same-spelling type alias or a class in another namespace cannot satisfy that proof.
  7. Revalidate and publish. Verify content stamps, saved/committed state, and epoch freshness. Emit detached data only after the platform read has ended.

The legacy file/offset selector remains a closed alternative at the endpoint for acceptance tooling. A request cannot combine that selector with qualifiedName. Both alternatives pass through the same query service, deadline, freshness checks, and result contract.

The scope of the relation is intentionally narrow. This proves one explicit direct supertype for a selected supported Kotlin class. It does not enumerate every inheritor, resolve an arbitrary inheritance graph, admit Java/library endpoints, or establish a complete workspace publication.

What never crosses the boundary

Live PSI elements, K2 sessions, compiler symbols, and IntelliJ search scopes stay inside the read lifetime. The response contains canonical signature data, compiler identity, file/model provenance, and saved-content stamps. Transport does not hold a platform read lock.

Authority: qualified selection and uniqueness, index-to-analysis bridge, shared read and publication boundary, supertype proof.

04 / WIRE CONTRACT

Small requests, bounded work, finite failures

The shared schemas and hosted operation registry now belong to protocol:contract. The CLI loads the schema resources from that dependency; the plugin owns its compatibility properties. Production CLI/plugin packaging no longer pulls protocol assets or host properties from the Python experiment directory.

{
  "type": "DIRECT_SUPERTYPE",
  "root": "/canonical/workspace/root",
  "qualifiedName": "example.Outer.Child"
}
BoundaryImplemented limit or invariant
TransportOne request per connection; four-byte big-endian length followed by strict UTF-8 JSON.
Request / response16 KiB maximum request; 64 KiB maximum response. Duplicate keys, extra fields, malformed encoding, and oversized frames are rejected.
Index collectionAt most 32 candidates. A truncated collection cannot masquerade as a complete answer or unique declaration.
Name admissionShort-name components: 1–512 UTF-8 bytes. Qualified selector: 1–4096 UTF-8 bytes, with every component admitted.
TimeTwo-second cooperative semantic deadline inside a five-second host connection budget; six-second client transport deadline.
ConcurrencyOne active semantic permit; cancellation drains original work before releasing ownership. The endpoint admits socket connections serially.
ContentSaved and PSI-committed IDE content. Dirty documents, indexing, changed stamps, and lost freshness reject publication.
Client correlationExact response root; exact short name for class lookup; exact qualified inheritor identity for supertype; detached publication stage; status PID must match the descriptor.

The semantic deadline is cooperative, not a promise of hard real-time preemption. The six-second client deadline bounds waiting independently. No published latency or throughput claim is based on the small live qualification.

Preserved evidence is narrower than canonical publication

Hosted answers explicitly identify request_local_same_source_epoch, saved_committed_ide_vfs, cached_gradle_source_folders, and cached_source_folder_flag. Those values are meaningful limitations. Document/VFS stamps are observations of IDE content, not disk hashes. Cached folder classification is not producer-attested source-set ownership.

The three new semantic failures are DECLARATION_NOT_FOUND, AMBIGUOUS_DECLARATION, and DECLARATION_IDENTITY_MISMATCH. They join the existing closed outcomes for lifecycle, indexing, content, cancellation, and scope failures. No fuzzy fallback selects the first candidate.

Following the CLI’s existing convention, received host or semantic JSON is printed on stdout with exit status 0. Callers must inspect type or outcome. Client admission/transport failures use stderr and a nonzero exit. An HTTP-style success assumption based only on the process exit code would be incorrect.

Authority: semantic response schema, endpoint schema, closed request decoder, client admission and correlation.

05 / DEPENDENCIES AND OWNERSHIP

Python can leave the product path

It already has. The native CLI sends the socket request, admits the shared schema, checks correlation, and prints the result. The compiled Kotlin plugin performs discovery and analysis. Neither requires the Python interpreter, jsonschema, an ideScript invocation, or a generated Kotlin script for normal queries.

ComponentCurrent roleRetirement decision
Python socket clientOptional experiment and acceptance utility; duplicates a subset of the native client.Not a runtime dependency. Remove after the remaining acceptance callers are ported.
Fixture/management scriptsExplicit development plugin load/unload, fixture refresh, and older lifecycle qualification.Replace with durable Kotlin/IDE integration tests and normal plugin delivery. Do not make scripts part of production requests.
Historical experimentsSource and regression evidence for cancellation, restoration, and retirement behavior.Keep until equivalent executable coverage preserves those claims. Deletion alone would discard evidence.
Shared JSON schemasProduction protocol contracts in the Kotlin contract module.Keep. Schema validation is independent of the language used by a client.

What “no indexes of our own” means here

The implemented hosted path creates no Kast-owned semantic index store. It reads IDEA’s existing Kotlin indexes. Source edits are incorporated by IDEA’s indexing lifecycle; Kast observes readiness and fails while required state is unproven.

The older isolated implementation also uses IntelliJ’s native discovery machinery. Its extra burden is a separately owned runtime, workspace/import lifecycle, index readiness, and publication machinery. The migration removes the need to operate that second environment for supported hosted reads; it does not replace a hand-written search engine with a new one.

Kast still needs epoch observation, request budgets, endpoint ownership, and evidence validation. These are the proof and transport responsibilities around a live index. Removing them would allow stale or cross-workspace results even if IDEA’s index itself were correct.

Authority: existing native symbol discovery, isolated assembly and refresh ownership.

07 / TRANSITION PLAN

Retire the second workspace one proven capability at a time

The intended destination is an existing-project semantic host used by the normal agent flow, with IDEA owning import and index maintenance. Reaching that destination requires contract work beyond changing a command name. The sequence below separates delivered behavior from proposals.

Implemented · 1

Use the existing IDE for primary indexing reads

Compiled project service, retained admission, bounded socket endpoint, class discovery, qualified supertype proof, native CLI, primary kast index routing, and production-owned protocol assets are present. No automatic isolated fallback exists in this path.

Proposed · 2

Turn the remaining manual qualification into Kotlin tests

Port the lifecycle and controlled-fixture effects to supported IntelliJ test infrastructure or a narrowly owned development test adapter. Preserve wrong-root, dirty content, edit-during-read, cancellation, rename, ambiguity, disposal, and retirement evidence before deleting the Python harnesses. Normal queries should continue to have no mutation or refresh capability.

Exit evidence: a repeatable Kotlin acceptance command exercises the live/plugin boundary, cleans up only owned fixtures, and records bounded stages on both success and failure.

Proposed · 3

Choose the hosted publication contract explicitly

The cached IDEA model proves less than the current canonical workspace publication expects. Existing isolated import uses a Gradle producer model to retain project/source-set identity and authored/generated provenance. A normal already-open project may lack those nodes.

There are two valid directions: retain a separately typed hosted read publication for consumers that accept its evidence, or obtain the missing producer facts through an explicitly selected same-project integration/sync and refine them into the stronger publication type. Do not fabricate source-set ownership from directory names or module suffixes.

Exit evidence: source-backed supported-build mappings, closed rejections for unsupported/ambiguous roots, and tests proving that weaker cached evidence cannot construct stronger canonical authority.

Proposed · 4

Expose the hosted capability through App Server

Add an explicit existing-IDE host selection and client capability at coordinator composition. Advertise only hosted operations whose input, result, and publication contracts are supported. A closed/missing IDE should yield unavailability, not trigger worker demand. Keep headless isolated operation an explicit policy if that product requirement remains.

Exit evidence: agent requests bind the exact root and original host, missing/retired hosts never reach worker-launch code, and endpoint/schema mismatches remain finite rejections.

Proposed · 5

Expand discovery, source reads, relations, and query composition

Current exact class lookup is not equivalent to the general search/query surface. Add needed declaration kinds and bounded discovery modes, exact source selection, supported relations, then query-plan composition. Every step must retain compiler identity, source scope, content semantics, cancellation, and explicit completeness limits.

Exit evidence: operation-specific parity checks against the existing IDE, including exclusions and failure semantics. Avoid mapping a partial result to a complete canonical answer merely to reuse a serializer.

Proposed · 6

Complete delivery and retire obsolete hosted-mode ownership

Qualify full IDE startup, plugin upgrades, simultaneous roots, endpoint crash leftovers, and client disconnects under sustained work. Then remove isolated worker/import/index-maintenance dependencies from the hosted production composition. Delete obsolete Python and duplicate index-lifecycle plumbing only once callers and equivalent tests have moved.

Exit evidence: the normal hosted agent path operates end to end without Python, a second project, a separate indexer, or manual Kast index synchronization; closed IDE state produces the documented unavailable outcome.

Contract gap: producer source-root evidence, publication authority, current publication lifecycle.

08 / USING THIS BRANCH

Build once, query the open project

  1. Use the branch checkout and an already-open supported Kotlin Gradle project in IDEA. Let IDEA complete its normal model import and indexing.
  2. Build :runtime:hosted:hostedPlugin with -PhostedIdeaHome pointing to the exact running installation. The release shell installer verifies and installs the resulting versioned, exact-build archive into IDEA’s user plugin directory; restart IDEA to activate it.
  3. Build :cli:installDist. Run cli/build/install/kast/bin/kast index status --root /absolute/root.
  4. Use index classes to discover a class identity, then pass the qualified identity to index supertype. The latter performs fresh index selection and semantic proof within its own request.

Use matched artifacts. The operation list remains DESCRIBE, CLASS_LOOKUP, and DIRECT_SUPERTYPE; the qualified selector extends the last operation. An older plugin may reject the new selector. The semantic failure set also grew, so older schema-strict clients may reject newly typed failures. This branch is not a claim of arbitrary cross-version compatibility.

For development reloads, unload the owned plugin and atomically replace the owned JAR files before reattachment. Do not modify loaded archives in place: script compiler processes may retain open archive mappings. The management script is optional development tooling, not part of normal query delivery.

Dependency verification remains temporarily disabled by the earlier explicit request. That pre-existing branch decision has not been reversed or presented as production release hardening. Restore and requalify it as a separate delivery change when requested.

Known delivery limits: full IDE restart startup, multi-root qualification, crash-left endpoint recovery, and unattended script-free lifecycle acceptance remain open. Unknown endpoint artifacts are preserved and rejected rather than deleted speculatively.

Detailed commands and management history: endpoint runbook, hosted runtime design.

10 / REVIEW PRIORITIES

The decisions that matter next

  1. Hosted evidence versus canonical publication. Decide which consumers can accept the explicitly typed cached-model publication, and which need additional producer evidence. This determines the App Server integration shape.
  2. Coverage needed for the normal agent loop. Prioritize the next operation by real usage. Exact class lookup and one direct supertype are proven; arbitrary search, source reads, diagnostics, and change operations are not automatically covered.
  3. Headless behavior. The hosted path fails unavailable when IDEA is absent. Retaining an explicitly selected headless isolated mode is a separate product decision; automatic fallback would reintroduce the second indexer unexpectedly.
  4. Qualification ownership. Replace fragile script-based acceptance with supported compiled tests before deleting the remaining Python evidence tooling. Preserve closed stage/outcome observations at the effect boundary.
  5. Release readiness. Treat startup, upgrades, multi-root behavior, stale artifacts, and dependency verification as concrete qualification tasks before presenting this as a fully migrated production release.

The implemented result is useful now: primary indexing reads operate through the existing IDE, and the new relation query no longer requires manually maintained file offsets. The next migration step should extend the same authority chain rather than create a second index abstraction.
