Tool RPC carries JSON through an installed process. Its working directory selects the Kotlin repository or worktree.

<a id="discover" />

## Catalog command

`catalog` returns installed tool names, descriptions, input schemas, and effects.

```shell
"${HOME:?HOME is required}/.local/share/kast/installation/bin/kast-tool-rpc-complete" catalog
```

The reply uses `type: "catalog"`. Its `catalog.schemaVersion` is the installed public tool contract version, 18 for the required-terminal grammar.
Each effect is `READ` or `WRITE`.

The catalog reports the call timeout and maximum response bytes. It can also report the `querySession` capability. If that capability is absent, use one-shot calls.

<a id="call" />

## Call command

`call` accepts a tool name and one JSON argument object on stdin. It emits one reply object on stdout.

```shell
printf '%s\n' '{}' |
  "${HOME:?HOME is required}/.local/share/kast/installation/bin/kast-tool-rpc-complete" call health_check
```

Tool RPC shares direct MCP's tool names, including `health_check` and change tools. It omits hosted `workspace_lifecycle`.

The process checks input shape, installation state, and the exact root. It then dispatches semantic work. The reply keeps specific failures from the process or tool.

## Query session

If advertised, `query-session` accepts `query_symbols` inputs, one JSON object per line. It owns one initial query. Later output reads use authority issued by earlier replies.

A session admits at most 64 requests. Later actions can read the issued retained result. They can also resume the issued output continuation.

The child returns `QUERY_SESSION_TRANSITION_REJECTED` for a second `RUN`, unrelated result, source action, or unsupported transition. It then ends.

Keeping the process alive does not extend retained-state expiry. It does not authorize semantic replay. [Staleness](/reference/staleness) still governs each action.

## Reply variants

| `type` | Necessary field | Meaning |
| --- | --- | --- |
| `catalog` | `catalog` | Installed inventory. |
| `complete` | `document` | Completed operation. |
| `qualified` | `document` | Facts with limitations. |
| `rejected_document` | `document` | Semantic or hosted rejection. |
| `rejected` | `failure` | Finite failure at the process interface. |

Each document uses the response schema for its tool. An unknown reply kind means the contracts do not match.

`rejected_document` keeps a semantic or hosted rejection. `rejected` reports a process failure. In that case, no admitted document is yet available.

[The reply schema](/reference/models/tool-rpc-reply) defines the wrapper. [The adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md) supplies integration details.

[The source map](/reference/source-map#installation-and-transport) identifies the process and query-session owners.
