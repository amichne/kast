A semantic request needs the IDEA project for the exact Gradle root. The project has to be compatible, imported, and indexed. Kast prepares it when authorized demand needs it. The plugin's MCP session starts preparation as it starts up or on its first admitted modern request. The passive context hook does not prepare projects. It needs no `uv` environment or third-party Python package.

## What happens on the first question

The coordinator selects the canonical root and asks the Host to prepare the project. The Host reuses or starts the selected IDEA instance. It then admits the project.

1. Kast selects the exact Gradle root.
2. The Host reuses or starts the selected IDEA instance.
3. The Host opens the project and checks import.
4. Kast waits for indexing and the current read state before it admits a semantic request.
5. Trust, save, import and plugin blockers keep their own causes.

`WorkspacePreparations` owns one sequence for each root. It opens once. It then reads the issued operation until the project is ready or a final cause is reported.

Multiple demands can share setup that is still pending. After setup blocks or rejects, a later demand can check the Host again.

This retry gets current native facts. It does not change past outcomes or replay earlier semantic calls.

## Readiness and blockers

Import and indexing can make the first call slower. IDEA can need your attention, so it cannot always stay in the background.

Trust prompts, unsaved documents, plugins that do not match, and failed import keep explicit causes. They cannot become a successful query with no rows.

Readiness belongs to the exact worktree. A ready project in another worktree cannot supply the requested authority.

## Connection state and project readiness differ

Registration supplies a client adapter. Catalog admission supplies the tool schemas. Neither fact proves that the IDEA project is ready.

Each semantic request still needs current read admission. Completed setup can be reused only while its native authority stays valid.

Disconnect removes the recorded integration. It does not remove IDEA state. A loaded client adapter needs a restart to unload.

Semantic demand still prepares the project. Kast has no switch to turn off preparation while leaving semantic tools enabled.

Hosted `workspace_lifecycle` supplies distinct project actions. [Manage Kast](/reference/management#explicit-workspace-control-in-the-hosted-app-server) describes their use.
