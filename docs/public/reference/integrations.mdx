Kast writes no agent configuration. Declare the Kast skill and MCP server in your repository's `agents.toml`. [dotagents](https://github.com/getsentry/dotagents) then writes the configuration for each agent you list.

## Before you start

- [Install Kast](/start). Your agent must find the `kast` command on its `PATH`.
- Install Node.js. It runs `npx @sentry/dotagents`.

## 1. Export the Kast skill

From your repository root, run:

```shell
kast install skill
```

Kast writes the skill to `.agents/skills/kast`. dotagents uses this directory in place, so keep it in Git.

## 2. Declare Kast in agents.toml

Create `agents.toml` in your repository root, or add these entries to your existing file:

```toml agents.toml
version = 1
agents = ["claude", "codex"]

[[skills]]
name = "kast"
source = "path:.agents/skills/kast"

[[mcp]]
name = "kast"
command = "kast"
args = ["--internal-entrypoint=mcp"]
```

Set `agents` to the agents that you use. The dotagents documentation lists the supported names.

The `[[mcp]]` entry runs the installed `kast` command as a stdio MCP server in the agent's working directory.
If your agent cannot find `kast`, set `command` to the absolute path that the installer printed.

## 3. Apply the configuration

```shell
npx @sentry/dotagents --project install
```

dotagents links the skill and writes the MCP configuration for each listed agent.
Start a new agent session in the repository to load them.

## Work with your agent

Describe your task as usual. The skill tells your agent when a Kast query gives a better answer than a text search.
The agent can read the installed CLI contract with `kast describe`.

The first explicit semantic request grants trust to the exact workspace root and prepares its Host. This applies to the CLI and to MCP.
Use Kast only in a workspace whose build code you trust. MCP registration and `tools/list` do not grant trust or start a Host.
Each result applies to its stated worktree, source state, and scope.

The [MCP contract](/reference/mcp-catalog) describes the server's tools and replies. The [CLI reference](/reference/cli) describes the command forms.

## Refresh the skill after an upgrade

An upgrade can change the bundled skill. `kast install skill` never overwrites an existing skill:

- An identical skill returns `ALREADY_INSTALLED` and writes nothing.
- A different or incomplete skill returns `SKILL_EXISTS` and leaves the directory unchanged.

To refresh the skill, run these steps from your repository root:

1. Remove the old export with `rm -rf .agents/skills/kast`.
2. Export the skill again with `kast install skill`.
3. Apply the configuration with `npx @sentry/dotagents --project install`.
4. Start a new agent session.

## Export to another directory

`--output` selects the parent directory of the skill:

```shell
kast install skill --output ./guidance
```

This command writes the skill to `./guidance/kast`. Set the skill `source` in `agents.toml` to the same path.
Add `--json` to print one structured result.

Recovery: [Help](/troubleshooting).
