A semantic query answers a source question. Output delivery presents the evidence from that query within a separate response limit.

Kast keeps these operations separate because a preview cannot change the question or strengthen its proof.

## One question and one execution grant

A public `RUN` selects its source, ordered steps, output, and scope. Kast admits one grant for work, elapsed time, and retention.

The runner drains internal semantic pages under that grant. Empty pages can advance discovery or relationship work.

Every public run uses `COMPLETE_ONLY` within `COMPILER_RESOLVED_STATIC_V1`. Completion needs exhausted execution and satisfied proof obligations.

Missing callback proof, item failures, omitted evidence, or unresolved investigation obligations prevent completion.

## A preview describes delivery

A completed investigation can produce more evidence than one reply can carry. The preview reports the rows that fit the presentation allowance.

Its row count does not describe unfinished semantic work. Conversely, a small result does not prove enough work or storage capacity.

1. Admit the question, workspace, and current read state before semantic work.
2. Resolve the supported symbols and relationships within one execution grant.
3. Establish completion or preserve the rejection and available evidence.
4. Present retained rows without replaying the semantic query.

<Warning>
  A rejected or incomplete query does not establish that a caller is absent.
</Warning>

## Retention preserves the original answer

A retained result keeps immutable rows, identity, qualifications, and original producer progress. Its reference identifies that stored result.

`READ_RESULT` presents those rows and evidence. Its row cursor and evidence cursor advance independently.

`RESUME` uses an issued output continuation to present a produced suffix. It does no new semantic work.

Neither action grants a stronger answer. Historical execution checkpoints in rejection evidence do not authorize another strict run.

## State determines whether reuse remains legal

Retained evidence belongs to its workspace, IDEA owner, read epoch, committed source state, and lifetime.

An exact declaration can undergo fresh compiler revalidation. Retained results and output continuations need their original state.

If that state is unavailable, a new query establishes a new answer. It cannot restore the original delivery.

[Read retained evidence](/how-to/read-retained-evidence) gives the procedure. [Results](/reference/responses) defines the encoded fields and rejection causes.
