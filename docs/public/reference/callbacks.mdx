Kast preserves the anonymous body that owns a call. It also records how that body receives a value and reaches a supported invocation.

Kast keeps those owners separate because callback supply does not establish execution. The agent can trace the body without a guessed named caller.

## Named callers and lexical ownership

`REFERENCES` can establish lexical containment. `CALLERS` and `CALLEES` add callback observations with a separate named-edge policy.

Direct or supported inline invocation can admit a named edge while it keeps anonymous ownership. Non-inline, `noinline`, and `crossinline` exclusions keep their reasons.

Containment supplies location context. It does not establish that a named function directly invokes the call inside a deferred body.

## Static bindings and unfinished proof

Compiler argument mapping establishes the supplied value's receiving formal. Formal-body evidence then enumerates supported invocation and forwarding sites.

An immutable alias keeps the value-transfer derivation. Each forwarding hop keeps source formal, exact expression, and destination binding.

A default keeps its defining formal and expression. An explicit supplied argument replaces that default for the selected call.

An unused formal can have an exhaustive scan with no invocations. That fact does not create a call to the default body.

A nested anonymous or local named owner needs its own activation proof. An exhaustive formal scan cannot discharge that obligation by itself.

`owner_bindings` preserves anonymous supply and mapping when available. Unresolved mapping, escaped storage, returns, cycles, or exhausted grants keep finite causes.

[Observation fields](/reference/callback-observations) defines policies, bindings, scan states, forwarding, and obligations.

## Reviewed dependency models

Kast admits supported calls-in-place effects from the compiler-selected formal and dependency class digest. The record keeps the exact declared invocation kind.

Missing effects cannot become a guessed `UNKNOWN`. Explicit `UNKNOWN` is a supported declared effect with its own limited meaning.

The contract does not supply invented dependency-body invocation sites. Unsupported or contradictory effect evidence rejects the model.

`KOTLIN_LAZY_JVM_V1` admits reviewed digests for the facade, factory, initializer implementations, and mode dispatch.

Its `DEFERRED_DEPENDENCY` records the callable or property that supplies the initializer. It contains no invocation site or count.

The supplying container does not gain a direct named caller edge for the deferred body. Property access and initializer execution remain unproved.

Unavailable or changed binaries keep finite dependency-model failures. [The source map](/reference/source-map#callback-and-deferred-ownership) links those rejection cases.

## Symbolic callees and source exclusions

For `block()` or `block.invoke()`, `PARAMETER_INVOCATION` records the defining named callable, formal position, exact occurrence, and actual owner.

That symbolic target does not select a runtime function value. Formals owned by anonymous functions remain unsupported.

`SOURCE_LESS` preserves resolved compiler callable identity and compiler module. Proven builtin or excluded-library facts can support complete enumeration as known exclusions.

Requested but unavailable library source keeps `LIBRARY_SOURCE_UNAVAILABLE` and qualified coverage. Missing PSI alone cannot establish a source exclusion.

<a id="read-the-exact-anonymous-source" />

## Anonymous source selectors

This action reads the anonymous body's anchored source through its issued selector.

```json
{
  "request": {
    "type": "READ_SOURCE",
    "candidateRef": "<issued candidateSelector>"
  }
}
```

An epoch change needs new source authority. The enclosing named function remains a separate declaration identity.

<a id="continue-output-delivery" />

## Output delivery

Callback and callable evidence can advance on a zero-row page. `page_progress` and the issued `next_action` describe that presentation.

Relation and walk documents need `callable_observations`, including empty arrays. Observed flows need `scan`, and parameter invocations need `forwardings`.

Missing fields reject schema admission. Complete traversal coverage can precede the final output page.

[Program tracing](/reference/program-tracing) connects callback routes to value impact. [Staleness](/reference/staleness) explains source-state reuse.
