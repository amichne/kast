`kast.query_symbols` applies an ordered pipeline to Kotlin declarations.

This example filters public functions before finding their callers:

```json
{
  "source": {
    "type": "all_declarations",
    "declaration_kinds": ["function"],
    "scope": null
  },
  "steps": [
    {"type":"filter_visibility","visibilities":["public"]},
    {"type":"expand_relation","relation":"callers"}
  ],
  "return_fields": ["name","location","signature"]
}
```

## Build the pipeline

| Part | Supported values |
| --- | --- |
| Sources | `search_declarations`, `all_declarations`, `symbol_refs` |
| Steps | `filter_visibility`, `expand_relation`, `distinct_symbols` |

Step order changes the result:

- Filter before expansion to find callers of public functions.
- Filter after expansion to keep only public callers.
- Expect discovery sources to deduplicate after compiler refinement.
- Add `distinct_symbols` to deduplicate downstream results.

Kast preserves every explicit step in order.

## Choose returned fields

| Input | Result |
| --- | --- |
| `steps: null` or `steps: []` | No transformations |
| `return_fields: null` | Name and location |
| `return_fields: []` | Mandatory identity and kind only |
| Duplicate projection fields | Rejected request |

## Reuse an exact symbol

Copy `ref` verbatim into the `symbol_refs` source:

```json
{"type":"symbol_refs","symbol_refs":["<returned token>"]}
```

- Do not construct, shorten, or edit a reference.
- Expect the original owner to re-admit its workspace, lifetime, epoch, and scope.
- Use `read_relations` for occurrence-oriented facts such as use-site locations.
- Use query expansion for related declarations.


## Continue an ordered pipeline

Use a returned continuation to resume the same pipeline.

1. Omit `continuation` or use `null` for the first page.
2. Retain a non-null `continuation` from a qualified result.
3. Repeat the same source, steps, and return fields with that token.
4. Append each returned page in order.

The checkpoint retains:

- unfinished relation expansion
- pending output
- identities seen by each distinct stage

Resuming does not rerun an emitted prefix.

`distinct_symbols` keeps the first occurrence and its connections.

Later occurrences do not add connections to that result.

Use `read_relations` when individual occurrences matter.

### Know why continuation stopped

A null continuation means no resumable suffix remains.

Read `terminal_reason` before interpreting the final page:

| Reason | Meaning |
| --- | --- |
| `upstream-incomplete` | A provider or discovery stage retained incomplete coverage without resumable state. |
| `output-item-too-large` | One indivisible projected item or failure exceeds the query execution output budget. |
| `checkpoint-capacity-exceeded` | The unfinished state exceeds the configured checkpoint capacity. |
| `no-progress` | The execution could not prove a progressing checkpoint. |

The transport also checks actual encoded response bytes.

If no prefix fits, the request rejects with `RESULT_TOO_LARGE`.

### Keep a continuation valid

- Keep the project, source snapshot, and query unchanged.
- Expect changed queries to reject.
- Expect expired, evicted, or stale checkpoints to reject.
- Rediscover after source or model changes.
- Never reconstruct an opaque token.

[Read-limit settings](https://github.com/amichne/kast/blob/main/docs/hosted-read-configuration.md)
define checkpoint size, count, aggregate bytes, and lifetime.

### Check every page

- Read qualification and item failures.
- Apply source-set restrictions to `query_symbols` discovery subjects only.
- Keep expansion destinations outside that discovery restriction.
- Preserve the exact subject reference for `read_relations`; its destinations may be in other files and packages. A returned continuation stays bound to that subject and relation.
- Keep incomplete upstream coverage after buffered output drains.

## Traverse a large graph

`traverse_relations` exposes `traversal.run`.

Use these strategy rules:

- Include `"strategy": {"type": "breadth_first"}` in tool requests.
- Expect the direct CLI to supply breadth-first strategy when omitted.
- Finish one node's resumable relation before moving to the next node.
- Use `bounded_fan_out` with `maximumEdgesPerNode` to limit each node.
- Keep truncated fan-out coverage explicitly incomplete.

An exact edge from a terminal-qualified relation remains eligible for later query
stages and traversal reads. Its omission stays attached to the aggregate after
known work and buffered output finish. A terminal child has no continuation of
its own; the parent can still have resumable downstream work. Fully consuming a
child limited only by page capacity does not leave permanent incompleteness.

Traversal cannot establish absence in omitted subtrees.

Each page exposes cumulative progress:

| Field | Meaning |
| --- | --- |
| `checkpointSequence` | Ordered checkpoint number |
| `totalReads` | Reads completed so far |
| `totalEdges` | Edges retained so far |
| `maximumDepthReached` | Deepest returned edge, cumulative across pages |

Reading a depth-1 leaf with no outgoing edges increases `totalReads` without
producing depth-2 evidence. An empty second expansion therefore does not prove
that the service skipped a read. A `not_explored` remainder describes omitted
relation output at that node, not the exploration state of every returned target.

- Every resumable page must advance its checkpoint.
- `no-progress` is terminal.
- Time budgets renew for each request.
- Subject, relation, scope, strategy, and depth remain bound to the continuation.
- Older tokens without progress and strategy witnesses require a restart.

Use [Symbol results](/reference/symbols) to distinguish declarations from connections.

Use [Read a response](/reference/responses) before interpreting an empty result.

### Interpret time limits

Elapsed time is an observation; the time allowance is an admitted grant.

When execution exceeds the grant, traversal:

- retains measured time and proven facts
- stops further reads
- returns `time-limit-reached`
- resumes only when unfinished work remains

An over-budget page cannot claim completion.

## Keep semantic bounds separate from page budgets

Keep operational grants separate from semantic scope:

| Control | Boundary |
| --- | --- |
| `execution_budget` | Time, provider work, results, and encoded bytes for one request |
| Relation `limit` | Relation page capacity |
| Traversal `maximumResults` | Traversal page capacity |
| Source `entityLimit` | Source-entity page capacity |
| Traversal `maximumDepth` | Requested graph depth |
| Traversal `strategy` | Requested exploration policy |

A continuation may request a larger execution grant without changing its query.

A larger page grant cannot increase depth or erase a provider omission.

### Read source structure

For a hosted v4 or v5 exact selector returned by search or inspection, `source_read` accepts a
single `symbol` field. It reads the declaration with complete text, no entities,
and compact output. The selector stays opaque; pass it unchanged. A selector
that cannot be reacquired in the current IDE epoch returns a closed read failure.

The short request can override `region` (`declaration`, callable `body`,
`class-body`, or `file`), `text` (`complete`, `none`, or a `window`), `entities`
(`none` or direct `declarations`), and `format` (`compact` or `expanded`). A
window defaults to 20 lines before and after the anchor and requires
`maximumBytes`; declarations require a `limit`. The generated callable reference
contains executable request examples and the exact field schema.

Candidate and source selectors use the existing typed `anchor` request. In that
request, `region` and `entities` are selected separately.

For `entities.type: "matching"`:

- `containment: "direct"` selects direct children.
- `containment: "descendants"` also walks nested elements.
- `filters` select declarations, parameters, calls, or references.

Source containment is separate from recursive directory or package discovery.

### Choose the evidence shape

| Tool | Evidence shape |
| --- | --- |
| Query expansion | Related declarations with retained connections |
| `read_relations` | Individual occurrences, including repeated call sites |
| `distinct_symbols` | Changed declaration cardinality at its pipeline stage |
| `traverse_relations` | Bounded reachability with depth, strategy, and coverage |

Traversal does not predict which edits break callers or which tests must run.

## Calls inside inline lambda arguments

Callers and callees attribute an inner call to the enclosing supported callable
when K2 maps the literal lambda argument to an ordinary function parameter of
the selected inline callable. This includes standard-library and user-defined
helpers; names do not authorize ownership. Every intervening lambda must pass
that check. The original inner occurrence and exact endpoints remain unchanged.

Returned or stored lambdas, ordinary callbacks, `noinline`, `crossinline`,
unresolved or ambiguous mappings, and accessor boundaries remain unsupported
or unresolved. A local named function retains its own owner. Independent
omissions remain qualified beside supported edges. Exact static ownership does
not establish runtime execution or invocation frequency.
