# Selected JBR startup correction

The checkout installer admitted IDEA metadata but let ambient `JAVA_HOME`/PATH choose Gradle's first JVM. Broker command composition also fell back to ambient Java or the current JVM when no IDEA was selected, and executable admission alone did not establish Java 25 compatibility. The public release installer already selected and checked the admitted IDEA's bundled JBR.

The checkout installer now canonicalizes the selected IDEA, checks its executable JBR and release feature >=25, and sets Java only for its own children before Gradle. Missing or incompatible JBR rejects before build/installation state with an actionable selection or repair message. Installed launchers recheck their recorded selected JBR before starting Java, including paths with spaces or apostrophes. Review correction `6327216a9` requires exactly one fully quoted `JAVA_VERSION` declaration in both shell paths. Duplicate declarations, unclosed quotes, trailing text and a valid declaration beside a malformed duplicate reject; broker admission retains the same uniqueness rule.

Broker composition now requires selected IDEA JBR or the existing explicit `javaHomeCandidate` used for ownership-qualified receipt recovery. The explicit override keeps precedence and passes the same compatibility check; ambient Java never supplies fallback authority. `BrokerJavaRuntime` retains canonical home/executable and a bounded single release-version declaration, so service identity and command assembly consume admitted facts. This is release-file compatibility evidence, matching installer policy, not cryptographic verification of a replaced binary.

Tests cover ambient `/usr/bin/java`, valid ambient Java without selected IDEA, missing executable/release, Java 24, malformed/duplicate release declarations, spaces/apostrophes, and valid/invalid owned override. Shell positive controls admit Java 25, 25.0.2 and 26-ea with surrounding release metadata. Launcher checks execute only a case-owned inert shell child, whose output proves the selected Java identity; rejected cases never reach that child. Checkout rejection retains an empty Gradle call log and no installation state. Existing broker-policy fixtures retain their original effect/ownership assertions.
