Kast supports Apple Silicon macOS, on-disk Kotlin Gradle repositories, and the
IntelliJ `262` release line described in [Install and connect](/start). Linux,
Intel macOS, other languages, and other IntelliJ release lines are not currently
supported. IDEA and its bundled Kotlin plugin may have different patch builds
within `262`; their exact observed identities remain in runtime evidence.
Protocol, schema, and artifact integrity checks remain exact.

## Agent integration contract

The exact installed `serverProjection` is the harness compatibility boundary.
It versions the hosted bootstrap and invocation bindings and supplies the tool
names, schemas, loading hints, effects, approval policies, and budgets.

Harnesses should qualify that projection at startup. They must not infer
compatibility from a version string or reuse a catalog from another installation.

The Codex App Server integration remains a preview while its upstream protocol
is experimental. Failure of that integration does not weaken or change the
installed Kast semantic contract.

## Evidence lifetime

Tool names and schemas can remain compatible while repository evidence moves.
A source or imported-model change may invalidate a returned reference. The safe
response is a new Kast declaration search, not reinterpretation of the stale value.

Complete, qualified, and rejected retain their documented meanings. A new
version must not turn unknown or stale evidence into an unqualified success.

## Upgrades

The installer downloads and verifies a matched control, semantic-runtime, and
existing-IDE plugin for the selected release line before replacing the active Kast installation
and the Kast-owned IDEA user plugin directory. Restart IDEA after an install or
upgrade to load that plugin. Ordinary upgrades and uninstall preserve repository
source and unrelated JetBrains state.

For reproducible environments, run the installer from the same explicit release
tag passed to `--version`:

```shell
release_tag="v0.35.0"
/bin/bash -c "$(curl -fsSL "https://raw.githubusercontent.com/amichne/kast/${release_tag}/install.sh")" \
  -- --version "$release_tag"
```

Replace the example tag with the release your environment has approved. Do not
assume that a future release exists.

If an upgrade cannot start the integration or admit the repository, follow
[Troubleshooting](/troubleshooting) and retain the reported boundary evidence.
