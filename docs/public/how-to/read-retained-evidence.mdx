Use this guide when a query returns a preview, a retained result reference, or a completion rejection with `nextQuery`.

You need the original response and its issued handles. The original read state and retention lifetime must remain valid.


1. [Identify the issued capability.](#1-identify-the-capability)
2. [Read rows with their own cursor.](#2-read-the-next-row-page)
3. [Read evidence with its separate cursor.](#3-read-the-evidence-pages)

## 1. Identify the capability

Read the response's status, coverage, and progress. Then identify the issued capability:

| Capability | Action |
| --- | --- |
| Output continuation | `RESUME` presents the remaining produced output. |
| Retained result reference | `READ_RESULT` presents stored rows and evidence. |
| Rejection's `nextQuery` | Copy the emitted `READ_RESULT` arguments unchanged. |

Keep the original qualifications. A saved rejection remains a rejection after all evidence pages reach their end.

## 2. Read the next row page

For retained symbol rows, substitute the issued result reference and cursor:

```json
{
  "request": {
    "type": "READ_RESULT",
    "result": "<issued result reference>",
    "cursor": 0
  }
}
```

Use `next_cursor` from the previous reply for subsequent pages. Match the output to the retained row kind.

For retained binding rows, include `"output": {"type": "BINDING_ROWS"}`. [Results](/reference/responses) defines each retained output form.

## 3. Read the evidence pages

If `evidence_window.type` is `MORE`, use `evidence_window.end` as the next `evidence_cursor`.

Keep the row cursor independent. After the last row, keep it at `invocation.accumulated_row_count`.

```json
{
  "request": {
    "type": "READ_RESULT",
    "result": "<issued result reference>",
    "cursor": 12,
    "evidence_cursor": 8
  }
}
```

The numbers illustrate positions only. Substitute the values from your response.

An evidence-only page can advance without a row. Continue until the response reports the final evidence position.

## 4. Handle unavailable state

If a handle rejects, keep its finite cause. Do not substitute an exact reference for a retained result reference.

If the original state is unavailable, start a fresh query with current references. A fresh query produces a separate answer.

`RETENTION_UNAVAILABLE` supplies no invented handle. Reading retained evidence neither renews its lifetime nor resumes semantic execution.

[Query execution and evidence delivery](/explanation/query-lifecycle) explains the separate owners. [Results](/reference/responses) defines progress and failure variants.
