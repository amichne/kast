Final delivery can explicitly choose a compact provider-facing presentation of an already admitted query. The default remains the original presentation. This policy applies only after semantic work and required retained reads have ended; WORK and pending evidence reads retain their existing context.

The raw verbose result, canonical SDK details, original tool request and original user/agent messages remain unchanged. The final provider context contains one compact view of the selected admitted query, using the shared `queryPresentation` owner. Every received occurrence retains its exact identity, location, ownership and provenance. The native outcome, coverage, question/scope, minimum, missing evidence and observed authority remain truthful. Received failures and observations remain inline; final answering cannot depend on a live retained handle. Unsupported result families or identity changes fail closed through the existing policy.

Projection happens before provider serialization and byte/call admission. Existing presentation, request, response, output, wall and post-response accounting bounds remain separate and unchanged. No projection executes semantic work, extends authority, retries a result or increases a quota. Saved archives and canonical details preserve the full audit material.
