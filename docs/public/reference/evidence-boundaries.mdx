Identity and coverage answer different questions. An exact reference identifies a declaration. Coverage describes the completed portion of the declared search. Each fact belongs to a workspace, source state, declared scope, and coverage record.

[Query execution and evidence delivery](/explanation/query-lifecycle) explains the separate execution and presentation owners.

## Exact facts are not the same as exhaustive coverage

| Result | Supported conclusion |
| --- | --- |
| Exact symbol, complete coverage | The declaration is established, and Kast covered the requested search scope. |
| Exact symbol, qualified coverage | The declaration is established, but more matches or unresolved proof can remain. |
| Empty, complete coverage | No match in the declared, supported scope. |
| Empty, qualified coverage | Absence remains unproven. |
| Rejected or unavailable | The request did not establish a successful semantic answer. |

Coverage applies to the declared, supported Kotlin sources. Excluded sources, libraries, other languages, and runtime execution need separate evidence. Examine restrictions, omissions, and item failures before a conclusion.

<a id="decide-whether-to-continue" />

## Evidence delivery cannot strengthen a proof

Public `RESUME` presents produced facts through an issued output token. It performs no semantic execution. Terminal progress names the reason for the stop. `retention_unavailable` means that Kast lost the remaining output suffix. A missing continuation does not prove completeness.

An empty page can advance through saved evidence. All saved rows keep their original coverage limits, even after you read every page. See [Results](/reference/responses#follow-progress-not-row-count) for the next action.

<a id="can-i-reuse-this-result-later" />

## The original state constrains reuse

Issued handles identify specific capabilities. Stale references and unavailable saved state prevent their reuse. A fresh query establishes a new answer. A new query cannot recover the original delivery.

Kast can revalidate an exact symbol with fresh compiler evidence. retained results and continuations need their original read state and lifetime. See [Saved state and identity](/reference/responses#saved-state-and-identity) before reuse.

<a id="check-relationship-and-verification-claims" />

## Read relationship and edit evidence

A compiler-confirmed call site establishes a source relationship. Lexical containment alone does not establish a named caller. [Callback evidence](/reference/callbacks) identifies anonymous owners and the limits on activation claims.

An edit receipt establishes verification for its reported scope. If the outcome is uncertain, keep the receipt. Use [change recovery](/reference/change#read-the-receipt) before another write. Run your project's build and tests after a verified change.
