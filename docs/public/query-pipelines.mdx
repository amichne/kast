Use retained results when a question builds on earlier investigations. Kast can consume the established rows directly instead of asking the agent to reconstruct a list of symbols from prose.

This walkthrough continues [Find and trace code](/search) against [Kast at `56df091`](https://github.com/amichne/kast/tree/56df0912e46b182bb4ad8beabd1512823100fd72). Counts and outcomes describe that historical recording, not a fresh run. [Full requests, responses, and capture details](/reference/schemas#recorded-walkthrough) remain available.

**A**, **B**, and **C** below are teaching labels for issued retained-result references. Pass your own references unchanged. Builds or edits can advance the workspace's semantic basis and make retained inputs unavailable.

> Combine A and B by exact symbol identity. From that combined set, keep declarations named `Concat` and show their signatures. Do not merge different declarations just because they share a name.

The recorded union and filter (`04-union-filter`) returns both declarations with exhaustive coverage. The filter runs **after** the union, so it applies to symbols from either input.

<Accordion title="Request: union by identity, then filter by name">
  Replace the placeholders with the retained-result references from your session.

  ```json
  {
    "request": {
      "type": "RUN",
      "executionBudget": {"maxElapsedMs": 15000},
      "source": {"type": "RESULT", "result": "<result A>"},
      "steps": [
        {"type": "UNION", "right": {"type": "RESULT", "result": "<result B>"}},

          "type": "WHERE",

            "type": "PRIMITIVE",
  ```

</Accordion>

## Keep the matched pair, then select a side and continue

Use an inner join when you need both inputs' established rows, not only the matched symbol. Project a named symbol cell before applying another symbol relationship.

> Join A to B by symbol identity. Name the left cell `step` and the right cell `candidate`, and retain the paired rows. Then select `step` from those rows and find its reference occurrences.

The recorded join (`06-join-c`) retains one pair as **C**, with exhaustive coverage. Both cells identify `QueryStepSyntax.Concat`; `step` preserves the implementation occurrence and `candidate` the discovered symbol. The opaque reference strings differ. The join compares canonical symbol identity, not token strings.

<Accordion title="Requests: retain pairs as C, then follow one side">
  First retain the pairs:

  ```json
  {
    "request": {
      "type": "RUN",
      "executionBudget": {"maxElapsedMs": 15000},
      "source": {"type": "RESULT", "result": "<result A>"},
      "steps": [
        {
          "type": "JOIN",
          "mode": {"type": "INNER", "leftName": "step", "rightName": "candidate"},
          "right": {"type": "RESULT", "result": "<result B>"}
        }
      ],
      "output": {"type": "BINDING_ROWS"},
      "retention": "RETAIN"
    }
  }
  ```

  Then project the `step` cell and follow its references:

  ```json
  {
    "request": {
      "type": "RUN",
      "executionBudget": {"maxElapsedMs": 15000},
      "source": {"type": "RESULT", "result": "<result C>"},
      "steps": [
        {"type": "PROJECT_BINDING", "name": "step"},
        {"type": "EXPAND_RELATION", "relation": "REFERENCES"}
      ],
      "output": {"type": "OCCURRENCES"}
    }
  }
  ```

  The recorded query (`07-project-references`) found this use in `QueryPlanCompiler.exactStage`, with exact compiler-confirmed evidence and exhaustive coverage:

  ```kotlin
  is QueryStepSyntax.Concat -> ExactQueryStage.Concat(step.input, stage)
  ```
</Accordion>

Kast does not expose a general-purpose `MAP` operator or arbitrary-field join. `PROJECT_BINDING` selects a named symbol from each row; later steps operate on those symbols.

## Resume work or inspect retained rows

> If this query reports resumable work, resume its issued continuation. Do not rerun its completed steps. To inspect retained rows without advancing execution, read the retained result instead.

`RESUME` advances stored unfinished execution. `READ_RESULT` presents immutable retained rows; its result cursor does not resume semantic execution. Reading every retained page cannot erase the producing query's limitations.

<Accordion title="Requests: resume execution or read retained rows">
  Resume only with the execution continuation issued by the result:

  ```json
  {"request":{"type":"RESUME","continuation":"<issued execution continuation>"}}
  ```

  Read retained symbols:

  ```json
  {"request":{"type":"READ_RESULT","result":"<issued symbol-result reference>"}}
  ```

  Read the retained pairs from C:

  ```json
  {"request":{"type":"READ_RESULT","result":"<result C>","output":{"type":"BINDING_ROWS"}}}
  ```

  The recorded reads (`08-read-a` and `09-read-c`) returned ten symbols and one paired row, respectively, with exhaustive coverage and their original retained-result identities. Current retained reads also support occurrences and traversal records with the matching output type; see [Query forms](/reference/api).
</Accordion>

### Observe a resumable result

The recording bounds a `SYMBOL_REFS` query to one result (`12-bounded-symbols`). It returns one row, a qualified outcome, `result-limit-reached`, and resumable progress. Resuming without the one-result allowance returns the remaining row with complete coverage (`13-resume`), without repeating the first row.

Use the continuation from your own result, not the historical token. A terminal qualification does not promise a successor. Stale or unavailable state requires an explicit recovery decision, not indefinite retries.

### Reject an incomplete absence check

`DIFFERENCE` and an `ANTI` join require complete right-hand coverage to establish absence. An unfinished search cannot prove that a symbol is missing.

<Accordion title="Recorded rejection: incomplete right-hand input">

  ```json

    "rejection": {
      "type": "execution-rejected",

    "next_action": "correct_request"
  }
  ```

  Do not use this old terminal-discovery example to predict a current `ALL_DECLARATIONS` result. Supported progressive Kotlin-source reads can retain undiscovered input. Inspect the actual result's progress and coverage.
</Accordion>
