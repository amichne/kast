---
title: "Background startup"
description: "How Kast prepares an IDEA project for a semantic request."
icon: "monitor-cog"
---

On the first valid MCP request or an RPC tool call, Kast binds the client's
working directory to its exact Gradle root. The installed service reuses or
starts the selected IDEA, opens the project, and waits for its model and
indexing state. A `catalog` request only lists tools.

Kast does not deliberately focus IDEA. A trust prompt, failed save, or import
failure can still need user action; Kast reports that blocker instead of an
empty successful query.

The diagrams on [How Kast works](/concepts/architecture) show the full flow.
