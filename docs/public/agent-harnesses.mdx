[Install Kast](/start) first, then choose your agent. Connect the integration, restart your agent, and run the query below to check that the tools work.

## Choose your agent

<Tabs>
  <Tab title="Codex">
    Install the bundled plugin to get the MCP tools, query skill, and examples together. If you already registered Kast directly with `kast connect codex mcp`, run `kast disconnect codex` first so Codex has only one Kast MCP connection.

    ```shell
    kast plugin codex
    cd /path/to/kotlin-repository
    codex
    ```

    Restart Codex after installation and select the repository or worktree you want to inspect.

    <Accordion title="Direct MCP without the bundled plugin">
      Choose this instead of the plugin when you only need the direct MCP registration:

      ```shell
      kast connect codex mcp
      cd /path/to/kotlin-repository
      codex
      ```

      Start a new Codex session after connecting. `kast connect codex` without an explicit transport fails with usage guidance.
    </Accordion>

    <Accordion title="App Server transport">
      New persistent installations publish Kast's broker at the standard Codex control socket. Ordinary managed `codex` invocations can discover it automatically. The existing macOS service also publishes the desktop daemon-selection flag, so compatible desktop builds can use the broker on a normal fresh launch. Quit and reopen an already running desktop app after installation.

      No desktop launch wrapper, app bundle edit or signing change is involved. An existing saved `private` endpoint stays explicit, and client overrides can bypass discovery. Desktop UI tool exposure needs qualification against the installed client version; see the [App Server compatibility record](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md).

      The owned launcher remains available for an explicit attachment:

      ```shell
      kast connect codex app-server
      cd /path/to/kotlin-repository
      kast-codex
      ```

      This installs `~/.local/bin/kast-codex` and attaches it to Kast's persistent broker and existing IDEA host. Start a fresh thread to load the dynamic tools. An App Server client can use `kast-codex app-server` for JSONL stdio.
    </Accordion>
  </Tab>
  <Tab title="Copilot">
    ```shell
    kast connect copilot
    cd /path/to/kotlin-repository
    copilot
    ```

    Restart Copilot after connecting so it loads the bundled extension and its installed tool catalog.
  </Tab>
  <Tab title="Pi">
    ```shell
    kast connect pi
    cd /path/to/kotlin-repository
    pi
    ```

    Restart Pi after connecting so it loads the bundled extension and its installed tool catalog.
  </Tab>
</Tabs>

Use the exact repository or worktree you want to inspect. Kast [prepares IntelliJ when a semantic request needs it](/concepts/background-startup); there is no separate workspace-open step.

## Check that the tools work

Ask your agent:

> Use Kast to find one Kotlin declaration in this repository. Show its name, kind, signature, source location, and coverage. If Kast is not ready or cannot prove a result, report the blocker rather than substituting a text search.

The connection works when a Kast query returns a declaration with its location and coverage. `kast status` shows registration information; this query checks that the agent can use the tools.

**Next:** [Find and trace code](/search). If tools are missing, a version disagrees, or the first query cannot prepare IDEA, use [Troubleshooting](/troubleshooting).

## A connection already exists

If the registered integration already matches, Kast leaves it in place. If Kast reports a conflict, inspect the existing registration before replacing it.

<Accordion title="Explicitly replace a conflicting registration">
  `--force` replaces only that harness's Kast slot. Use the command for the integration you selected, not every command below.

  ```shell
  kast connect codex app-server --force
  # or: kast connect codex mcp --force
  # or: kast connect copilot --force
  # or: kast connect pi --force
  ```

  Forced connection verifies the bundled payload and captures the previous registration before replacement. A failed transaction attempts to restore the previous registration and receipt. If restoration fails, the error identifies the backup and recovery destination. Unrelated registrations stay in place.
</Accordion>

## Disconnect or upgrade

<AccordionGroup>
  <Accordion title="Disconnect an integration">
    For a registration made with `kast connect`, name the agent you connected:

    ```shell
    kast disconnect copilot
    ```

    `kast disconnect codex` removes its owned App Server launcher and MCP registration when recorded. Restart the affected agent so it stops using the loaded integration.

    The bundled Codex plugin is owned by Codex instead. Remove it with `codex plugin remove kast@kast`.
  </Accordion>

  <Accordion title="Reload integrations after a Kast upgrade">
    After `kast upgrade`, restart IDEA and your connected agents so they load the matched payload and rediscover its catalog. For the bundled Codex plugin, rerun `kast plugin codex` to install the matching skill.
  </Accordion>
</AccordionGroup>

## Install the skill independently

If you already connected Kast, you can install the skill or marketplace separately.

<AccordionGroup>
  <Accordion title="Install a release skill or marketplace archive">
    Each [release](https://github.com/amichne/kast/releases) provides `kast-skill-v<VERSION>.zip`, `kast-plugin-v<VERSION>.zip`, and `kast-marketplace-v<VERSION>.zip` with SHA-256 checksums.

    The skill ZIP contains one `kast/` directory. Extract it into `~/.agents/skills/` or your repository's `.agents/skills/`. The skill covers scoped lookup, public inventories, fuzzy search, containing declarations, references, callers and callees, implementations and overrides, bounded traversal, and retained query composition.

    Its JSON examples are generated from Kast's public contract and validated by the typed input parser. Replace illustrative references with values returned by your current workspace.

    To install a downloaded marketplace ZIP, verify its checksum, extract it, and run:

    ```shell
    codex plugin marketplace add /absolute/path/to/extracted-marketplace
    codex plugin add kast@kast
    ```

    The source marketplace is also available with `codex plugin marketplace add amichne/kast`. The plugin uses the installed Kast MCP launcher; install Kast and its matching IDEA plugin first.
  </Accordion>

  <Accordion title="Connect a different client">
    Custom clients can launch `kast-codex app-server` after connecting Codex with the App Server transport, or use [direct MCP](/reference/mcp-catalog) or [one-shot Tool RPC](/reference/rpc-catalog).

    The [repository integration guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md) documents the adapter boundary.
  </Accordion>
</AccordionGroup>
