Run the public diagnostic operation with one explicit scope and result bound:

```console
kast diagnostic check \
  --scope app/src/main/kotlin \
  --limit 100
```

## Canonical contract

`diagnostic.check` is published in the typed operation registry, command graph,
installed server projection, and IDE endpoint capability descriptor. The scope
is resolved against the exact workspace root and bound to its current semantic
generation.

A **Complete** result proves the admitted files were analyzed within the
requested bound. A qualified result retains known diagnostics together with
the analyzed files and exact limitations. A stale generation, unavailable
index, or rejected scope fails closed instead of manufacturing an empty result.

| Outcome | How to read it |
| --- | --- |
| **Complete** | The admitted scope is fully accounted for. An empty diagnostic list is meaningful within that scope. |
| **Qualified** | Known diagnostics remain usable, while analyzed files and limitations name the coverage still missing. |
| **Rejected** | No diagnostic payload is presented as success. Repair the typed blocker before drawing a semantic conclusion. |

<Tip>
  Treat “no diagnostics” as evidence only when the outcome is complete for the
  exact scope you intended to inspect.
</Tip>

Use the [CLI reference](/reference/cli) as the availability boundary.
