## Run the first query

Ask your agent:

> Use Kast to find one Kotlin declaration in this repository. Show its name, kind, signature, source location, and coverage. Report any readiness or proof blocker.

A declaration with its location and coverage shows that the agent called Kast. Use `kast status` to inspect the recorded registration.

To investigate a function, substitute its name and directory in this prompt:

```text wrap
Use Kast to find submitOrder in the production Kotlin sources under checkout. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

After you select a function, ask:

```text wrap
Use the exact reference for the function I selected to find its callers. Show the call sites and searched scope, and report any unfinished work.
```

[Find and trace code](/reference/search) explains the results. For missing tools or readiness blockers, use [Troubleshooting](/reference/troubleshooting).

## Choose a connection destination

Pass an absolute directory when connecting:

```shell
kast connect pi --destination "$HOME/.config/pi/agent"
kast connect copilot --destination "$HOME/.config/copilot"
kast connect codex mcp --destination "$HOME/.config/codex"
kast connect codex app-server --destination "$HOME/bin"
```

| Connection | What the directory contains |
| --- | --- |
| Pi | `extensions/kast.ts` under the Pi agent home |
| Copilot | `extensions/kast/extension.mjs` under the Copilot home |
| Codex MCP | Codex's `config.toml`. The registered executable stays in the Kast installation. |
| Codex App Server | The `kast-codex` launcher |

Kast saves these directories in `~/.config/kast/config.json`. Reconnect, upgrade, and disconnect reuse them. An explicit `--destination` overrides the saved preference.

Without a saved destination, Kast reads `PI_CODING_AGENT_DIR`, `COPILOT_HOME`, or `CODEX_HOME` for the selected agent. If that variable is absent, Kast uses the agent's default directory. App Server defaults to `~/.local/bin`.

For a custom directory, run the agent with the same harness home. For example, `PI_CODING_AGENT_DIR="$HOME/.config/pi/agent" pi` loads the adapter from that directory. Kast's saved destination does not change the agent's settings.

When you change `--destination`, Kast examines the new connection and removes its previous owned slot in the same transaction. Other harness settings remain in place.

## Recover an existing connection

Matching registrations stay in place. By default, `kast connect` recovers a conflicting Kast slot with the verified release payload. Kast keeps the displaced bytes in a private backup and prints its location. Other extensions and registration names remain in place.

If the connection fails, Kast restores the previous connection, preferences, checkpoint, and ownership receipt. If a concurrent change or filesystem refusal prevents restoration, Kast keeps the recovery copy and reports the necessary action. Unverified release payloads and symbolic-link slots reject before replacement.

Kast keeps a verified configuration checkpoint in `~/.config/kast/config.last-good.json`. Reconnect restores a damaged or missing configuration from that checkpoint.

If both copies are invalid, Kast reconstructs preferences from recorded connection directories and keeps the rejected copies. If an older receipt lacks that routing proof, supply `--destination` to reconstruct preferences. Kast keeps the rejected configuration.

Use `--no-recover` to reject conflicts without replacing them. `--force` remains available for explicit replacement of the selected Kast slot.

## Disconnect or upgrade

For a registration made with `kast connect`:

```shell
kast disconnect copilot
```

`kast disconnect codex` removes its recorded App Server launcher and MCP registration. Remove the Codex-owned bundled plugin with `codex plugin remove kast@kast`. Restart the affected agent.

After `kast upgrade`, restart IDEA and connected agents. For the bundled Codex plugin, repeat `kast plugin codex`.

## Install the skill independently

<Accordion title="Release archives and custom clients">
  [Control 0.3.1](https://github.com/amichne/kast/releases/tag/control-v0.3.1) supplies `kast-skill-v0.3.1.zip`, `kast-plugin-v0.3.1.zip`, and `kast-marketplace-v0.3.1.zip` with SHA-256 checksums.

  Extract the skill's `kast/` directory into `~/.agents/skills/` or your repository's `.agents/skills/`. The generated examples use the public contract. Replace example references with handles from your current workspace.

  Examine the checksums, then extract the marketplace. To install it, use:

  ```shell
  codex plugin marketplace add /absolute/path/to/extracted-marketplace
  codex plugin add kast@kast
  ```

  The source marketplace is available through `codex plugin marketplace add amichne/kast`. Install Kast and a compatible Host first.

  Custom clients can use [MCP](/reference/mcp-catalog), [Tool RPC](/reference/rpc-catalog), or App Server. See the [adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md).
</Accordion>
