A Kast answer states what the compiler established within one admitted question. Identity, coverage, completion, and runtime execution remain separate facts.

Kast keeps those facts separate because each one supports a different conclusion. A stronger claim needs its own evidence.

## Exact facts are not the same as exhaustive coverage

An exact identity establishes one declaration. Complete coverage also establishes finished enumeration within the declared supported scope.

Qualified coverage preserves the established declaration with its limits. More matches or unresolved proof can remain.

Complete empty enumeration can establish absence within that supported scope. Qualified empty output cannot establish that conclusion.

A completion rejection preserves the missing execution, graph, or investigation proof. Complete enumeration alone cannot discharge those obligations.

Scope excludes sources that the question does not admit. Libraries, generated sources, unsupported languages, and unavailable bodies keep their stated restrictions.

An exact occurrence can remain useful when complete proof fails. Its qualifications must remain attached to each later interpretation.

<a id="decide-whether-to-continue" />

## Evidence delivery cannot strengthen a proof

A preview limits output presentation. It does not reduce or expand the original semantic question.

`RESUME` and `READ_RESULT` present produced facts without new semantic execution. A final output page cannot discharge an unresolved callback or investigation obligation.

`retention_unavailable` records loss of remaining output. Absence of a token does not establish complete coverage.

<a id="can-i-reuse-this-result-later" />

## The original state constrains reuse

Retained evidence belongs to its original workspace, IDEA owner, read state, and lifetime. A later source state needs a new answer.

Exact-reference reacquisition can establish fresh compiler authority under its identity policy. It does not migrate an earlier retained result.

[Staleness](/reference/staleness) explains that difference. [Results](/reference/responses) defines handles and presentation progress.

<a id="check-relationship-and-verification-claims" />

## Read relationship and edit evidence

A compiler-resolved source call establishes a static relationship. It does not prove runtime execution, branch feasibility, or invocation frequency.

Callback supply does not prove invocation. Lexical containment does not alone establish a named caller. [Program tracing](/reference/program-tracing) identifies the necessary path evidence.

A verified edit receipt establishes its reported source effect and examination scope. Project tests and builds establish separate behavior.

An uncertain write needs source and recovery evidence before another write. [Change recovery](/reference/change#read-the-receipt) supplies that procedure.
