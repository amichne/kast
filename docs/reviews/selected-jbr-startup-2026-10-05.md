# Selected JBR startup correction

The checkout installer admitted IDEA metadata but let ambient `JAVA_HOME`/PATH choose Gradle's first JVM. Broker command composition also fell back to ambient Java or the current JVM when no IDEA was selected, and executable admission alone did not establish Java 25 compatibility. The public release installer already selected and checked the admitted IDEA's bundled JBR.

The checkout installer now canonicalizes the selected IDEA, checks its executable JBR and release feature >=25, and sets Java only for its own children before Gradle. Missing or incompatible JBR rejects before build/installation state with an actionable selection or repair message. Installed launchers recheck their recorded selected JBR before starting Java, including paths with spaces or apostrophes.

Broker composition now requires selected IDEA JBR or the existing explicit `javaHomeCandidate` used for ownership-qualified receipt recovery. The explicit override keeps precedence and passes the same compatibility check; ambient Java never supplies fallback authority. `BrokerJavaRuntime` retains canonical home/executable and a bounded single release-version declaration, so service identity and command assembly consume admitted facts. This is release-file compatibility evidence, matching installer policy, not cryptographic verification of a replaced binary.

Tests cover ambient `/usr/bin/java`, valid ambient Java without selected IDEA, missing executable/release, Java 24, malformed/duplicate release declarations, spaces/apostrophes, and valid/invalid owned override. Existing broker-policy fixtures now provide selected IDEA/JBR facts and retain their original effect/ownership assertions; no fixture JBR process is launched. The installer suite has 28 passing cases. On the final branch, all 330 CLI tests pass; 580 app-server cases have zero failures/errors and three existing native-acceptance skips. JSON contracts, architecture, formatting, file-length and knowledge source-citation guards pass.

The combined Gradle run exits unsuccessfully only for four pre-existing Detekt task failures: CLI main/test 53/163 and app-server main/test 126/180. Comparison by rule, normalized source URI and message with an untouched base archive yields zero introduced/removed findings. Current main differs from that archive only in three release-pin documentation pages. Original failed runs remain private evidence; no lint suppression or baseline expansion is used.

No active app/service restart, global Java setting, installation, publication or limit change is part of this patch. Socket ownership/recovery, lifecycle-history retirement and private-repository performance are deferred followups. The installed OpenWiki 0.6.1 local stdio MCP route (`openwiki mcp --host codex`) completed its supported begin/plan/page/finish lifecycle.
