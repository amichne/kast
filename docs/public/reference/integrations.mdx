Use this guide to choose a transport, set a custom destination, or recover a connection. [Install Kast](/reference/installation) first.

## 1. Choose the client and transport

<Tabs>
  <Tab title="Codex">
    The bundled plugin supplies MCP tools. It also gives the agent a short brief at session start. The brief includes absolute paths to the schema and examples.

    After Codex admits the plugin, installation removes Kast-owned legacy MCP and App Server registrations. It leaves other registrations in place.

    ```shell
    kast plugin codex
    cd /path/to/kotlin-repository
    codex
    ```

    Restart Codex after installation. Review and trust its session hook in Codex. Hooks without trust do not inject context.

    `kast connect codex` selects the same plugin. The compatibility form `kast connect codex mcp` also selects the plugin. `kast connect codex app-server` rejects before registration effects. Codex owns its App Server and control socket.
  </Tab>
  <Tab title="Copilot">
    If `kast connect copilot` installed the RPC extension, first remove it with `kast disconnect copilot`.

    ```shell
    copilot plugin install "$HOME/.local/share/kast/installation/share/kast/agent-tools/plugins/kast"
    cd /path/to/kotlin-repository
    copilot
    ```

    Restart Copilot to load the plugin. Its session hook supplies the same brief and absolute reference paths as Codex.
  </Tab>
  <Tab title="Pi">
    ```shell
    kast connect pi
    cd /path/to/kotlin-repository
    pi
    ```

    Restart Pi to load the extension. It supplies the shared brief. It registers the server through Pi's native MCP support.
  </Tab>
</Tabs>

Codex and Copilot context hooks use Python 3.9 or later with the standard library. Pi reads bundled context directly with Node. Startup needs no uv process, dependency download, or Python environment. If Pi cannot read context, it reports one warning and keeps native MCP registered.

The MCP session starts [IntelliJ preparation](/reference/internals/background-startup) for the exact Kotlin Gradle project. Semantic calls wait for that preparation. You need no separate setup hook or workspace-open step.

## 2. Prove tool and workspace admission

Ask the agent for one Kotlin declaration with signature, location, coverage, and the reported readiness or proof blocker.

For a named function, narrow discovery before relation work.

```text wrap
Use Kast to find submitOrder in the production Kotlin sources under checkout. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

After you select the declaration, request its callers through the issued exact reference.

```text wrap
Use the exact reference for the function I selected to find its callers. Show the call sites and searched scope, and report any unfinished work.
```

Queries prepare IDEA on demand. Readiness still needs checks for the exact worktree and loaded Host.

[Find and trace code](/reference/search) supplies investigation steps. [Lifecycles](/reference/lifecycles) distinguishes registration, session, preparation, and semantic execution.

## 3. Set a custom destination when needed

Supply an absolute destination for the selected integration.

```shell
kast connect pi --destination "$HOME/.config/pi/agent"
kast connect copilot --destination "$HOME/.config/copilot"
```

| Connection | What the directory contains |
| --- | --- |
| Pi | `extensions/kast.ts` under the Pi agent home |
| Copilot | `extensions/kast/extension.mjs` under the Copilot home |
| Codex plugin | Codex owns its plugin cache and settings. Kast does not select a connection destination. |

Kast saves preferences in `~/.config/kast/config.json`. An explicit destination overrides the recorded preference.

Without a preference, Kast reads the selected agent's `PI_CODING_AGENT_DIR`, `COPILOT_HOME`, or `CODEX_HOME`. Otherwise, it uses that agent's default home.

A saved destination does not change the agent's own home selection.

If you use a custom home, start the agent with the same home. For Pi, use `PI_CODING_AGENT_DIR="$HOME/.config/pi/agent" pi`.

A destination change admits the new connection and removes the old owned slot in one transaction. Other harness settings keep their existing owner.

## 4. Recover a conflicting connection

Matching registrations stay in place. By default, recovery replaces a conflicting Kast slot with the verified release payload. It keeps the displaced bytes in a private backup.

A failed transaction restores the connection, preferences, checkpoint, and receipt. If the filesystem refuses a write or changes race, a recovery copy can remain. Follow its reported action.

Kast rejects unverified payloads and symbolic-link slots before replacement. `--no-recover` rejects a conflict and leaves it in place. `--force` asks to replace the slot.

`config.last-good.json` supplies a settings checkpoint. If both settings files fail, saved routing receipts can rebuild preferences. Kast keeps rejected copies.

If an older receipt lacks routing proof, supply `--destination`. Keep the reported backup until recovery succeeds.

<a id="disconnect-or-upgrade" />

## 5. Reload clients after a lifecycle change

Disconnect an owned registration with its selected agent name.

```shell
kast disconnect copilot
```

`kast disconnect codex` removes recorded App Server and MCP integration. Remove the Codex-owned plugin with `codex plugin remove kast@kast`.

Restart the affected client to unload its adapter. After an upgrade, restart IDEA and connected clients.

For the bundled Codex plugin, repeat `kast plugin codex`. Disconnection does not itself retire IDEA or the shared daemon.

## Plugin archives and custom clients

<Accordion title="Release archives and custom clients">
  Control releases supply a plugin archive and a marketplace archive with SHA-256 checksums. The plugin includes session context, the schema, and a JSON array of named query examples. Replace example references with handles from your current workspace.

  Check the checksums, then extract the marketplace. To install it, use:

  ```shell
  codex plugin marketplace add /absolute/path/to/extracted-marketplace
  codex plugin add kast@kast
  ```

  The source marketplace is available through `codex plugin marketplace add amichne/kast`. Install Kast and a compatible Host first.

  Custom clients can use [MCP](/reference/mcp-catalog) or [Tool RPC](/reference/rpc-catalog). See the [adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md).
</Accordion>
