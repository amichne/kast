A result describes the workspace, source state, and scope that Kast checked. Read those limits before using it to answer a broader question or making a source change.

## Exact facts are not the same as exhaustive coverage

| Result | What it supports |
| --- | --- |
| Exact symbol with complete coverage | Kast confirmed the declaration and covered the requested search scope. |
| Exact symbol with qualified coverage | Kast confirmed the declaration, but more matches or unfinished checks may remain. |
| Empty with complete coverage | No matching result exists within the declared, supported search scope. |
| Empty with qualified coverage | Absence remains unproven, even when this page has no rows. |
| Rejected or unavailable | No successful semantic result was established by this request. Resolve the reported failure. |

A complete Kotlin-source search covers the stated source scope. It does not establish facts about other languages, libraries, or runtime behavior. Read any restrictions, omissions, and item failures alongside the result.

## Decide whether to continue

Ask the agent to state the scope checked, confirmed facts, limitations, and any next action. When Kast reports resumable work, continue with its issued token. When it reports a terminal limit, keep the facts and explain the unfinished work. A missing continuation does not mean coverage is complete.

An empty page can still represent progress. Retrieving all saved rows does not finish an incomplete search. See [Results](/reference/responses#follow-progress-not-row-count) for execution and paging details.

## Can I reuse this result later?

Kast checks references against the workspace and source state that produced them. Pass them unchanged. If a reference is stale, or saved results have expired or become unavailable, start a fresh query. Do not replace a rejected reference with a guessed name or source location.

A fresh read of an exact symbol may validate it again through the compiler. Saved results and continuations require their original state to remain valid. [Saved state and identity](/reference/responses#saved-state-and-identity) explains workspace ownership, IDEA read state, lifetimes, and the different handles.

## What does a caller trace prove?

A confirmed call site is evidence for that relationship in the checked source. A reference occurrence may only show where a name appears. Invocations in lambdas have separate ownership and callback limits; they do not prove runtime execution or exhaustive library callback activation. See [Callback evidence](/reference/callbacks).

## Check the scope of verification

Kast identifies the exact target of a source change and reports its verification outcome. If the outcome is uncertain, preserve the receipt and recovery evidence and avoid automatic write retries. The [change guide](/change) explains supported targets and what to do next.

Run the build and tests your project requires. IDEA diagnostics and verification of one edit cover their reported scope; they do not establish whole-project behavior.
