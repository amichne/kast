<a id="inspect-the-installation" />

## 1. Inspect the installation

```shell
kast status --json
```

Status keeps the installed build, loaded Host, update policy, and unfinished transaction separate.
It reads passive runtime evidence without starting Java or a Host lifecycle action.
An unavailable loaded identity does not prove that no Host runs.

Installed files do not prove that IDEA loaded them.
Host activation does not prove project readiness or semantic completion.

<a id="upgrade" />

## 2. Upgrade a compatible installation

List selectable builds and preview the latest development build:

```shell
kast versions
kast upgrade --channel main --dry-run
```

A successful preview returns `PLANNED`. It makes no installation changes and does not restart IDEA.

Apply the update:

```shell
kast upgrade --channel main
```

If the running Host needs a normal IDEA restart, permit it explicitly:

```shell
kast upgrade --channel main --restart-ide
```

Without that permission, a necessary restart returns `RESTART_REQUIRED` before installation changes.
Kast admits the selected artifacts before replacement.
A compatible running Host can use reload instead of a normal restart.

For another IDEA installation, add `--idea-home` with the exact app path.
Use the [selection reference](/reference/installation#pin-a-published-build) for exact version and commit pins.

## 3. Read the update outcome

### Lifecycle result contract

Add `--json` to get one structured terminal result.
Stage evidence goes to stderr.

| Outcome | Meaning | Exit |
| --- | --- | --- |
| `ACTIVATED` | Selected files and each affected running Host match the selected build and contract. | Zero |
| `INSTALLED_NOT_RUNNING` | The planned stopped-IDE path completed. No affected IDEA instance runs. | Zero |
| `REJECTED` | Preparation rejected before retirement or active installation changes. | Nonzero |
| `ROLLED_BACK` | The exact prior installation or prior absence returned with the necessary runtime and profile facts. | Nonzero |
| `RECOVERY_REQUIRED` | Settlement, activation, or restoration remains unproved. Kast keeps its fence and recovery evidence. | Nonzero |

A failed promised reload or restart cannot become `INSTALLED_NOT_RUNNING` merely because IDEA stopped.
A successful file replacement alone does not prove `ACTIVATED`.

### Workspace recovery after replacement

For `INSTALLED_NOT_RUNNING`, start IDEA before a fresh agent session.
For `ACTIVATED`, start a fresh agent session in the intended repository or worktree.

An update does not replay an interrupted source change.
Inspect the source and change record before another write.

## 4. Resolve unfinished recovery

If the result is `RECOVERY_REQUIRED`, keep the reported recovery evidence.
Resolve the named failure before another update.

```shell
kast status --json
kast upgrade --channel main --json
```

When an unfinished transaction exists, the next upgrade recovers its recorded build selection.
That recovery does not resolve a newer build.
Kast does not discard unknown or corrupt evidence to manufacture success.

<span id="reset-outcomes" />

A rollback restores the prior update policy.
Interrupted agent sessions stay stopped after restoration.
Neither restored files nor removal of temporary files proves that the prior Host runs again.
