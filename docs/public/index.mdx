Kast gives coding agents compiler-grounded search over one exact Kotlin
repository. Developers install it and connect a harness; the agent asks the
questions and Kast manages the runtime and intermediate evidence.

## Search is the main surface

Use `kast.search_classes` or `kast.search_functions` when the declaration kind
is known, and `kast.search_declarations` for unknown or mixed kinds. Searches
return exact references, names, locations and signatures. Diagnostics use the
separate `kast.check_diagnostics` tool.

The deferred `kast.query_symbols` composes enumeration, returned references,
filters and semantic expansion. Keep the returned references intact rather
than rebuilding identities from text.

## Kast owns readiness

An agent does not need to start Kast, synchronize the repository, or build a
topology before asking a semantic question. Semantic reads use the existing saved, indexed IntelliJ project. An unavailable
or unready host rejects the read without a hidden import or worker startup.

Kast returns a typed limitation or rejection when it cannot establish current
evidence. It does not manufacture readiness or silently weaken a result.

## The compiler resolves what text cannot

```kotlin
import billing.PricePolicy as BillingPricePolicy

class Checkout(private val policy: BillingPricePolicy) {
    fun total(order: Order): Money = policy.price(order)
}
```

Text search can find `PricePolicy`, `policy`, and `price`. Compiler evidence can
establish which declaration the alias names and which overload receives
`order`, while retaining the repository root, semantic generation, scope, and
limits behind the answer.
