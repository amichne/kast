## Check that the tools work

Ask your agent:

> Use Kast to find one Kotlin declaration in this repository. Show its name, kind, signature, source location, and coverage. Report any readiness or proof blocker.

A returned declaration with location and coverage verifies tool use. `kast status` reports registration.

For a useful first investigation, substitute your function and directory:

```text wrap
Use Kast to find submitOrder in the production Kotlin sources under checkout. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

Then ask:

```text wrap
Use the exact reference for the function I selected to find its callers. Show the call sites and searched scope, and report any unfinished work.
```

[Find and trace code](/search) explains the results. For missing tools or readiness blockers, use [Troubleshooting](/troubleshooting).

## Choose a connection destination

Pass an absolute directory when connecting:

```shell
kast connect pi --destination "$HOME/.config/pi/agent"
kast connect copilot --destination "$HOME/.config/copilot"
kast connect codex mcp --destination "$HOME/.config/codex"
kast connect codex app-server --destination "$HOME/bin"
```

| Connection | What the directory contains |
| --- | --- |
| Pi | `extensions/kast.ts` under the Pi agent home |
| Copilot | `extensions/kast/extension.mjs` under the Copilot home |
| Codex MCP | Codex's `config.toml`; the registered executable stays in the Kast installation |
| Codex App Server | The `kast-codex` launcher |

Kast saves the selected directories in `~/.config/kast/config.json`. Reconnect, upgrade, and disconnect reuse them. An explicit `--destination` takes precedence over saved preferences. With no saved destination, Pi uses `PI_CODING_AGENT_DIR`, Copilot uses `COPILOT_HOME`, and Codex MCP uses `CODEX_HOME`, then their ordinary default directories. App Server defaults to `~/.local/bin`.

Run Pi, Copilot, or Codex with the same harness home when using a custom directory. For example, `PI_CODING_AGENT_DIR="$HOME/.config/pi/agent" pi` loads the Pi adapter installed there. Kast's preference does not change the harness's own settings.

Changing `--destination` moves an owned connection: Kast verifies the new connection and removes the prior owned slot within the same transaction. Other harness settings remain in place.

## Recover an existing connection

Matching registrations stay in place. By default, `kast connect` recovers a conflicting Kast slot using the verified release payload. It retains the displaced bytes in a private backup and prints its location. Other extensions and registration names remain in place.

Failed connection attempts restore the previous connection, Kast preferences, checkpoint, and ownership receipt. If a concurrent change or filesystem refusal prevents restoration, Kast retains the recovery copy and reports the exact remaining action. Unverified release payloads and symbolic-link slots reject before replacement.

Kast keeps a verified configuration checkpoint in `~/.config/kast/config.last-good.json`. A damaged or missing config recovers from that checkpoint on reconnect. If both copies are invalid, Kast rebuilds preferences from recorded connection directories and retains the rejected copies. When an older receipt lacks that routing proof, supply `--destination` to rebuild the preferences while retaining the rejected config.

Use `--no-recover` to reject conflicts without replacing them. `--force` remains available for explicit replacement of the selected Kast slot.

## Disconnect or upgrade

For a registration made with `kast connect`:

```shell
kast disconnect copilot
```

`kast disconnect codex` removes its recorded App Server launcher and MCP registration. Remove the Codex-owned bundled plugin with `codex plugin remove kast@kast`. Restart the affected agent.

After `kast upgrade`, restart IDEA and connected agents. For the bundled Codex plugin, rerun `kast plugin codex`.

## Install the skill independently

<Accordion title="Release archives and custom clients">
  [Control 0.3.1](https://github.com/amichne/kast/releases/tag/control-v0.3.1) supplies `kast-skill-v0.3.1.zip`, `kast-plugin-v0.3.1.zip`, and `kast-marketplace-v0.3.1.zip` with SHA-256 checksums.

  Extract the skill's `kast/` directory into `~/.agents/skills/` or your repository's `.agents/skills/`. Its generated examples use the public contract. Replace illustrative references with current workspace values.

  After checksum verification and marketplace extraction:

  ```shell
  codex plugin marketplace add /absolute/path/to/extracted-marketplace
  codex plugin add kast@kast
  ```

  The source marketplace is available through `codex plugin marketplace add amichne/kast`. Install Kast and a compatible Host first.

  Custom clients can use [MCP](/reference/mcp-catalog), [Tool RPC](/reference/rpc-catalog), or App Server. See the [adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md).
</Accordion>
