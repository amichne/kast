Install Kast once, then start it through the agent integration for the repository
you want the agent to inspect. Semantic requests manage readiness automatically.

## Requirements

Kast currently supports this host contract:

| Requirement | Supported value |
| --- | --- |
| Platform | macOS on Apple silicon |
| Repository | An on-disk Kotlin Gradle repository |
| IntelliJ | IDEA and Kotlin plugin on JetBrains platform release line 262 |
| Runtime | The Java 25 JBR bundled with the selected IDEA installation |

The tested reference pair is IDEA `262.9437.185` with Kotlin plugin
`262.9437.185-IJ`. Compatible patch builds on release line 262 are accepted.
Kast uses the observed patch pair as part of runtime identity.

The built-in Codex integration also requires an installed `codex` executable on
`PATH`, or an absolute `CODEX_EXECUTABLE`.

## Install Kast

Install the latest published release:

```shell
curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh | bash
```

The installer verifies the matched control and semantic-runtime payloads before
activation. It does not install IDEA or write to an IDEA plugin directory.

If more than one compatible IDEA installation is available, select it
explicitly:

```shell
curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh | \
  bash -s -- --idea-home "/Applications/IntelliJ IDEA.app"
```

The installer creates the public commands in `~/.local/bin` by default. Add that
directory to `PATH` if the installer reports that it is not already available.

## Connect Codex

Start the included integration from the repository root:

```console
cd /path/to/kotlin-repository
kast codex
```

The integration ensures a launchd-owned App Server at Codex's standard local
daemon socket, qualifies the exact installed Kast projection, and starts Codex
through its supported remote transport. The default catalog omits only direct
symbol lookup and inspection.

To launch Codex Desktop through the same qualified integration:

```console
kast codex desktop
```

Quit an already running Desktop before launching it this way. Kast sets
`CODEX_CLI_PATH` for the new Desktop process to its installed `kast-codex` façade.
Desktop exchanges the native App Server protocol over stdio; the façade connects
to the same persistent broker and catalog used by the CLI. Closing Desktop leaves
the broker running. Full desktop UI compatibility remains unqualified; see the
[compatibility record](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md).

Ask the agent a question about the Kotlin repository. Its first Kast read should
normally use `kast.query`. A successful tool row can be expanded to inspect the
compiler-grounded result.

<Info>
  You do not need to run a separate start, sync, or topology command. The tool
  invocation owns those prerequisites and either returns current evidence or a
  typed blocker.
</Info>

## Connect another harness

Use the installed `serverProjection` as the integration contract for a different
agent host. It contains the exact tool names, schemas, policy, loading hints,
approval requirements, execution budgets, and invocation bindings for that
installation.

[Integrate an agent harness](/agent-harnesses) explains the boundary without
requiring application developers to learn the underlying CLI operations.

## Uninstall

Run the current installer in uninstall mode:

```shell
curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh | \
  bash -s -- uninstall
```

Uninstall removes Kast-owned commands, installations, runtime state,
configuration, and services. It preserves repositories and unrelated JetBrains
state.

If installation or the first agent request fails, continue with
[Troubleshooting](/troubleshooting).
