Kast is a repo-local semantic runtime for Kotlin repositories. It answers code
questions through IntelliJ and the Kotlin compiler, then returns the root,
generation, scope, limits, and identities needed to judge each result.

## The compiler sees more than text

Consider a checkout service that imports one of several declarations named
`PricePolicy`:

```kotlin
import billing.PricePolicy as BillingPricePolicy

class Checkout(private val policy: BillingPricePolicy) {
    fun total(order: Order): Money = policy.price(order)
}
```

| Text can suggest | Compiler evidence can establish |
| --- | --- |
| A search can find `PricePolicy`, `policy`, and `price`; it cannot establish which declaration the alias names or which overload receives `order`. | The property and call each have an exact compiler identity. Their source locations and semantic relationship remain part of the result. |

The distinction becomes important when an answer crosses files, modules, or a
change boundary. Kast makes the strength and limits of that answer visible.

## Start from the repository root

```console
cd /path/to/kotlin-repository
kast start
```

`kast start` launches or reuses the exact-root private IntelliJ sidecar. It
returns when semantic evidence is ready, or returns a typed blocker instead of
manufacturing readiness.

[Set up and start Kast](/start) to install the matched control and sidecar
release, admit one repository, and inspect the first compiler-backed result.

## Eleven sidecar operations

The installed sidecar endpoint publishes explicit index synchronization,
topology build, candidate discovery, compiler-backed symbol inspection, bounded
source reads, one-hop relation reads, bounded traversal, scoped diagnostics,
and planning, verified application, or recovery for AddDeclaration changes.

## Evidence keeps its boundary

<Info>
  **Complete** means the operation met its declared scope and completeness
  contract. **Qualified** keeps usable evidence and names its limits.
  **Rejected** returns no evidence as success.
</Info>

Every CLI outcome names its operation and status. Generation-sensitive
authority remains in the selectors, snapshots, plans, receipts, and evidence
documents that need it. A moved generation, unsupported scope, exhausted
bound, or missing capability stays visible at the relevant boundary.
