# Kast 1.0.0 readiness

The CLI now exposes the existing container runtime through `kast container`.
The release remains unqualified for 1.0.0 until the requirements in this report pass.
This change does not set a release version, publish an image, or promote release assets.

## Installation and CLI review

The public installer called retired `plugin codex` syntax after payload installation.
The corrected path calls `install codex` and preserves the guidance installer's exit code.
The installer now describes CLI guidance and names the current setup command.
The regression fixture rejects the retired command instead of accepting an obsolete protocol.

Root help now names each command purpose and the container entry.
The native command delegates container arguments to one packaged Python owner.
The installation manifest authenticates the launcher, script lock, and helper before delegation.
Help uses Python without dependency downloads or VM startup.
Normal operation uses the locked uv script. The launcher writes no Python cache into its installed payload.

`run` needs a command. Unknown actions and invalid task names reject before VM effects.
Named tasks keep separate workspace copies for the same source repository.
The `--image` option admits immutable registry digests or existing local image IDs.
A prepared image permits execution without a Kast checkout.
The default source build remains available through `build --checkout`.

## Image and isolation review

A live trial found a cached image with the old format label and no workspace setup helper.
The first task failed before the guest command, with its copied workspace still unready.
Image admission now needs the v2 format label. The `Dockerfile` supplies the necessary helper modules.
The retained regression case rejects the old image before workspace creation.

Host source stays separate from container edits.
The container receives no host mounts, SSH agent, Docker socket, or host credentials.
Default network access permits reachable host services. Offline mode disables external network access.
These controls do not establish protection against malicious kernels, hypervisors, or trusted image contents.

## Evidence and limits

The installer suite passed 64 cases. The container suite passed 43 cases.
The management module passed 377 tests and its scoped quality gate.
Native compilation, architecture, JSON contracts, knowledge, glossary, and Control archive guards passed.
The native command ran from a private installation outside the checkout.
Its help, literal arguments, working directory, streams, exit status, and changed-payload rejection passed.
The child adapter case used a uv process double and does not prove a live Docker task.
The artifact harness also invokes extracted help outside the checkout.
The native experiment uses a temporary image derived from the existing ARM64 image and the current workspace setup helpers.
The base image identity was `sha256:93783a4d2e08f3dd16c2553b87a1996db826a89a2e41315b6468f52796713a5f`.
The trial removed its old workspace grant inside the disposable image before task creation.
Two named tasks received separate copies. A repeated task kept its edit, while host source stayed unchanged.
The guest did not read the selected host-only file or reach the external network in offline mode.
The guest had no Docker socket. Its native `kast --version` returned `0.0.0`.
All trial containers and the derived image were removed afterward.
The trial did not exercise simultaneous tasks, compiler queries, or native components from this source revision.
The change delivery report records the source gates and their outcomes.

## Release requirements

| Requirement | Remaining evidence |
| --- | --- |
| Install without graphical IDEA | A public bootstrap that installs Control for container use without a desktop Host prerequisite. |
| Install without a Kast checkout | Published native images with immutable digests and an authenticated default selection. Explicit digest selection now exists. |
| Qualify both image architectures | Fresh ARM64 and x86_64 images from the release source, with compiler queries and rejection cases. |
| Delegate agent work | A selected agent inside the container, private authentication, a real edit, and a compiler result for that edit. |
| Qualify task retirement | Cancellation, failed initialization, workspace export, and an explicit retirement command under real Docker. |
| Freeze 1.0.0 contracts | Reviewed help, schemas, exit codes, supported platforms, compatibility policy, and upgrade recovery. |
| Promote tested bytes | Exact-source product qualification, terminal required CI, and promotion of those same artifacts. |

Image publication, release promotion, and a merge need separate authorization.
A passing source gate does not satisfy these release requirements.
