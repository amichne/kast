The first successful run opens one exact on-disk repository in a private
headless IntelliJ sidecar and publishes its compiler-backed evidence.

<Info>
  The installer verifies both release payloads: the `kast` command and its
  small private sidecar extension. It installs no IDEA distribution and writes
  nothing into a JetBrains plugin directory.
</Info>

<Steps>
  <Step title="Check the host">
    Kast currently requires:

    - macOS on Apple silicon
    - Java 25 or newer
    - IntelliJ IDEA build 262.9437.185
    - Kotlin plugin build 262.9437.185-IJ
    - an on-disk Kotlin Gradle repository

    Kast uses the installed IDE's JBR, Kotlin plugin, Gradle integration, PSI,
    and indexing implementation. Its Project and mutable IDE state remain in
    Kast-owned directories.
  </Step>

  <Step title="Install Kast">
    Use the repository installer as the installation boundary:

    ```shell
    curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh | bash
    ```

    The installer validates the host and Java version, then downloads the
    latest stable control command and matched private sidecar with their SHA-256
    records. It rejects unsafe archive paths or unexpected contents and
    smoke-tests local metadata before moving either payload into place.
  </Step>

  <Step title="Confirm the local contract">
    The installer creates `~/.local/bin/kast` but does not edit your shell profile.
    If it warns that the directory is absent from `PATH`, add it for the current
    shell before verifying the process-local surface:

    ```shell
    export PATH="$HOME/.local/bin:$PATH"
    kast --version
    kast --schema
    ```

    `kast --schema` lists all thirteen canonical operations, command shapes, wire
    schema, and the installed `serverProjection`. That projection owns the
    server-visible tool names, descriptions, input and output JSON Schemas,
    deferred-loading policy, explicit approval policy, and exact field-to-CLI
    bindings for every public sidecar operation. Read workflows appear as
    `workspace_ensure_ready`, `symbol_lookup`, `symbol_inspect`,
    `semantic_query`, `impact_analyze`, and `diagnostic_check`; every
    `change_*` tool requires explicit approval. The current sidecar endpoint
    publishes thirteen operations: workspace inspection, index synchronization,
    topology build, three symbol operations, relation reads, traversal,
    diagnostics, and four AddDeclaration lifecycle operations.
  </Step>

  <Step title="Start the exact repository">
    Run Kast from the repository's canonical root:

    ```console
    cd /path/to/kotlin-repository
    kast product inspect
    kast start
    ```

    Kast discovers the exactly supported standard IDEA installation and starts
    its JBR with private config, system, plugin, and log paths. It opens the
    Project, imports the on-disk Gradle model, refreshes its private VFS, waits
    for smart mode, and only then publishes semantic readiness. If no unique
    standard installation matches, pass `--idea-home /absolute/IDEA/home`.

    Sidecar processes launch directly by default. Set
    `KAST_ENABLE_LAUNCHD=1` to opt into launchd-backed process ownership; leave
    it unset or set it to `0` for direct launch. Every other value is rejected.

    Use `kast index sync` when files changed outside the sidecar and its VFS or
    semantic evidence may be stale.
  </Step>

  <Step title="Inspect the first answer">
    Read lifecycle state and compiler-backed workspace evidence separately:

    ```console
    kast status
    kast workspace inspect
    kast symbol discover --mode name --query PricePolicy --limit 25
    ```

    `status` reports runtime identity and a cache state such as `fresh`,
    `seeded`, `refreshing`, `smart`, or `rebuild-required`. The semantic command
    tells you what is ready. Discovery then returns bounded candidates, not an
    exact declaration claim.
  </Step>
</Steps>

<AccordionGroup>
  <Accordion title="Where the installer writes files" icon="folder-tree">
    The versioned control product and matched private sidecar live under
    `${XDG_DATA_HOME:-$HOME/.local/share}/kast`. The command is linked at
    `$HOME/.local/bin/kast`. Persistent private IDEA state lives under
    `$HOME/.cache/kast`; no JetBrains path is written.
  </Accordion>

  <Accordion title="Seed from a stopped IDEA cache" icon="copy-check">
    Ordinary startup never reads the user's IDEA cache. For an explicit
    one-time acceleration, close IDEA cleanly and request an APFS copy-on-write
    clone of the version-specific allowlist:

    ```shell
    kast start --seed-from-idea
    ```

    Interactive use first discloses copied categories, estimated size, and the
    fact that required global VFS/index files can contain entries for other
    projects. Supply `--source-idea-system /absolute/path` when the source is
    non-standard. Non-interactive use must also pass
    `--accept-global-index-copy`.

    Kast rejects a running, changed, incompatible, wrong-project, non-APFS, or
    unconsented source. It validates manifests before atomically publishing the
    clone and never mounts or modifies the source directory.
  </Accordion>

  <Accordion title="Rebuild only Kast state" icon="rotate-ccw">
    `kast reindex` stops the exact sidecar, atomically quarantines only its
    private cache, and starts a fresh import with the recorded IDEA runtime.
    `kast clean` removes inactive endpoint artifacts but retains the cache.
  </Accordion>

  <Accordion title="Install a local matched release" icon="package-check">
    Build the control archive, private sidecar, and SHA-256 records together, then
    point the reviewed installer at that local release root. A custom release
    base requires an explicit semantic version.

    ```shell
    release_version="${KAST_RELEASE_VERSION:?set KAST_RELEASE_VERSION to an unreleased semantic version}"
    ./gradlew -Pversion="$release_version" assembleSidecarRelease
    bash install.sh install --purge-existing \
      --version "$release_version" \
      --release-base-url "file://$PWD/build/release"
    ```

    `--release-base-url` also accepts an HTTPS mirror. It does not bypass
    checksums, archive validation, product smoke checks, or sidecar matching.
  </Accordion>

  <Accordion title="Inspect a release's module knowledge" icon="network">
    Every GitHub release includes a
    `kast-module-knowledge-v&lt;version&gt;.json` asset and matching `.sha256`
    record. The document identifies the exact release commit, preserves the
    accepted Gradle architecture verification and canonical module dependency
    policy, records the direct dependency graph admitted by that build, embeds
    every repository `AGENTS.md` with its content digest, and maps each module
    to governing and narrower descendant guidance.

    Download it without installing Kast:

    ```shell
    gh release download "v${KAST_VERSION:?set KAST_VERSION}" \
      --pattern "kast-module-knowledge-v${KAST_VERSION}.json*"
    ```
  </Accordion>

  <Accordion title="Find the default OpenTelemetry traces" icon="activity">
    Every ready endpoint asynchronously forwards topology and traversal spans
    into a private folder derived from its exact socket namespace. Inspect the
    authoritative destination instead of reconstructing it:

    ```console
    kast product inspect
    ```

    The product document reports enabled state, `otlp-json-lines-v1`,
    `directoryPath`, and `traceFilePath` without starting the sidecar. The
    directory uses mode `0700`, trace files use mode
    `0600`, and the exported allowlist excludes repository paths, selectors,
    source text, exception messages, and stack traces. The trace folder persists
    across ordinary restarts inside the exact socket's state directory; apply
    the host's retention policy as needed.
  </Accordion>

  <Accordion title="Uninstall Kast" icon="trash-2">
    The uninstall action removes Kast-managed commands, installed versions,
    runtime state, configuration, services, and old Kast plugin directories.
    It preserves repositories and unrelated JetBrains state.

    ```shell
    curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh | bash -s -- uninstall
    ```
  </Accordion>
</AccordionGroup>

## Recover from an older installation

If a prior local, Homebrew, or release-managed installation conflicts with the
current release, download the reviewed installer and use its opt-in purge-first
flow:

```shell
installer_file="$(mktemp)"
curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh --output "$installer_file"
bash "$installer_file" install --purge-existing
rm "$installer_file"
```

The installer verifies the replacement before removing Kast state. It does not
remove repositories or unrelated JetBrains state.

<Warning>
  `--purge-existing` removes current and historical Kast commands, services,
  runtime state, configuration, and old Kast IDE plugins before reinstalling.
  Use it only when replacing an existing installation.
</Warning>
