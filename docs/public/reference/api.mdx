`query_symbols` runs queries, resumes execution, reads retained rows, or reads anchored source. Use the [generated schema](/reference/schemas) for exact variants and [Find and trace code](/search) for agent prompts.

## Choose an action

| Action | Required input | Behavior |
| --- | --- | --- |
| `RUN` | `source` | Evaluate optional `steps` in order. Select `output` and optional `retention`. |
| `RESUME` | Issued `continuation` | Continue saved execution with its original source and steps. |
| `READ_RESULT` | Issued `result`. Optional `cursor` | Present retained rows without semantic execution. Output must match the retained row type. |
| `READ_SOURCE` | Issued `candidateRef` | Read an exact anchored occurrence or anonymous body. See [callbacks](/reference/callbacks#read-the-exact-anonymous-source). |

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "QueryStepSyntax"
    }
  }
}
```

Omitted output selects symbol name and location. `retention: "RETAIN"` keeps results for later use. Pass issued handles unchanged. Placeholders are not valid references.

Completion defaults to `COMPLETE_ONLY` within `COMPILER_RESOLVED_STATIC_V1`. Supported row queries drain issued execution pages under one grant before admitting a complete answer. Unsupported or unproven answers reject with typed evidence. Set `completion: {"type": "PROGRESSIVE"}` explicitly for qualified investigation and manual execution continuation. Compact output remains the default for both policies.

## Start from the right input

| Source | Purpose |
| --- | --- |
| `SEARCH_DECLARATIONS` | Simple declaration name. Exact, case-sensitive matching by default. Fuzzy matching is explicit. |
| `SEARCH_TEXT` | One case-sensitive ASCII identifier word. Exact containing declarations and match context. |
| `ALL_DECLARATIONS` | Supported Kotlin declarations, including nested declarations, ordered by file path and source offset. |
| `AT_LOCATION` | Nearest containing named declaration at a workspace-relative `file` and UTF-16 `offset`. |
| `SYMBOL_REFS` | Exact references from previous results. |
| `RESULT` | Retained rows, optionally selected by their issued row IDs. |
| `IMPACT` | Producer values through supported Kotlin transfers and supplied reviewed models. |

Discovery accepts directory or package scope. Its default is recursive workspace search in `main` and `test`. Discovery scope does not restrict later relationship destinations.

`SEARCH_TEXT` requires a letter or underscore followed by letters, digits, or underscores. Phrases, substrings, qualified literals, and regular expressions are rejected. Text matches establish discovery, not calls.

`ALL_DECLARATIONS` covers supported Kotlin classes, functions, properties, and type aliases. Direct library enumeration is unsupported. Inspect restrictions and progress before claiming completeness.

## Apply only the steps you need

| Step | Meaning |
| --- | --- |
| `WHERE` | Filter compiler-confirmed visibility or literal `NAME`, `KIND`, or `FILE`. Comparisons: `EQUALS`, `NOT_EQUALS`, `STARTS_WITH`, `ENDS_WITH`. |
| `DISTINCT_SYMBOLS` | Keep the first row per canonical identity at this pipeline position. |
| `EXPAND_RELATION` | One hop through `REFERENCES`, `CALLERS`, `CALLEES`, `IMPLEMENTATIONS`, `INHERITORS`, `OVERRIDES`, or `TYPE_USES`. |
| `WALK` | Exhaustive relation traversal when `maximumDepth` is omitted or null; explicit depth bounds reach. Default breadth-first strategy. |
| `CONCAT` | Append `input`, preserving order and duplicates. |
| `UNION`, `INTERSECT`, `DIFFERENCE` | Compare retained symbol rows in `right` by canonical identity. Difference requires complete right coverage. |
| `JOIN` | `INNER` pairs named cells. `SEMI` keeps matches. `ANTI` requires complete right coverage to establish absence. |
| `PROJECT_BINDING` | Select one named symbol cell before further symbol steps. |

There is no arbitrary-field join or general-purpose `MAP`. Steps after composition apply to the combined stream. See [Combine query results](/query-pipelines).

### Choose the relationship search domain

`expansionScope` controls native search before enumeration. A later `WHERE` filters returned rows.

| Scope | Meaning |
| --- | --- |
| `WORKSPACE` | Workspace expansion. Default for `EXPAND_RELATION` and for `WALK` with omitted or null `maximumDepth`. |
| `RETAINED_SEED` | Scope carried by each seed. Default for `WALK` with explicit `maximumDepth`. Acquire an `AT_LOCATION` seed for exact-file scope. |
| `SOURCE_DOMAIN` | Exact imported `sourceSets`, source policy, generated-source policy, and optional workspace-relative directory. |

Omission or `null` uses the operation's default. `SOURCE_DOMAIN` requires `sourcePolicy` and `generatedSources`. `includeSubdirectories` defaults to `true`. `IMPACT.domain` requires an explicit scope.

Observations retain requested and effective domains, coverage, and proven exclusions. [Callback observations](/reference/callbacks) preserve anonymous ownership. Excluded callbacks do not become named edges.

A `WALK` with omitted or null `maximumDepth` exhausts the reachable relation graph in its declared expansion domain and defaults to workspace expansion. Its result evidence carries `extent: {"type": "EXHAUSTIVE"}`. Explicit `maximumDepth` includes nodes at that depth without expanding them; evidence carries `extent: {"type": "THROUGH_DEPTH", "maximum_depth": N}`. Complete coverage requires complete one-hop reads at every required node. Result, work, and time limits can pause evaluation while retaining the original extent. Terminal incomplete reads keep the walk incomplete. Explicit expansion policies remain part of the completion question.

## Choose the result you need

| Output | Evidence |
| --- | --- |
| `SYMBOLS` | Identity and kind, plus selected `NAME`, `LOCATION`, `SIGNATURE`, or bounded committed `SOURCE`. |
| `OCCURRENCES` | Relation facts and use sites, including file-scoped imports and aliases. |
| `TRAVERSAL_RECORDS` | Relation facts with hop depth. |
| `BINDING_ROWS` | Named cells from an inner join. |
| `VALUE_PATHS` | Producer sites, transfers, model applications, representation history, terminals, and obligations. |
| `IMPACT_WITNESS` | Retained impact sections from a complete-only `IMPACT` run or `READ_RESULT`. |

Explicit symbol `fields: []` requests mandatory identity and kind. File-scoped occurrences remain use sites. Walks cannot expand them as declaration endpoints.

## Investigate value impact

`KOTLIN_FORWARD_V1` transfers a final try or catch value to its enclosing try expression when the compiler confirms a value type and the try has no `finally`. Each transfer retains the enclosing try range, branch range, `TRY_BODY` or indexed `CATCH_BODY` alternative, and `NORMAL_COMPLETION` condition. Catch fallback values have their own producers. These paths describe static provenance; they do not prove runtime path feasibility.

Non-final branch expressions do not supply the try result. Explicit returns remain return transfers, and throws do not produce normal branch results. Crossing a try boundary with `finally`, including an explicit return, retains `FINALLY_UNSUPPORTED`. Keep that obligation and every independent qualification attached to the useful partial paths.

`IMPACT` requires `seeds`, `declarations`, `domain`, `flow`, and `models`. Use no transformation steps and select `VALUE_PATHS`, or select `IMPACT_WITNESS` with `COMPLETE_ONLY` to complete the original investigation before presenting its selected section. Retain the result for later inspection.


| Input | Requirement |
| --- | --- |
| `seeds` | Issued `enclosing` and producer `callable` references, plus UTF-16 `start` and `end` covering the whole invocation. |
| `declarations` | Modeled callable references paired with identity claims for fresh revalidation. |
| `flow` | `KOTLIN_FORWARD_V1`. |
| `domain` | Explicit expansion scope. |
| `models` | Reviewed representation or boundary rules. `[]` supplies none. |
| Optional `requestedSites` | Enclosing identity, range, and role. Argument sites also identify invocation, callable, and formal parameter index. |

Native reads establish invocation and site identity. Supplied models define representation and boundary meaning. Unsupported transfers, rejected reads, and unresolved obligations preserve qualifications.

An explicit `PROGRESSIVE` work-limited run can return empty `VALUE_PATHS` with `EVIDENCE_ONLY` accounting and a resumable checkpoint. Before ledger finalization, witnesses return `RESULT_FIELD_UNAVAILABLE`. `RESUME` advances the investigation. Retained reads preserve its checkpoint.

Strict value-path completion requires discharged original ledger obligations and every original path. Missing evidence, an incomplete path selection, or unresolved obligations returns `INVESTIGATION_UNPROVEN` with case-specific proof details. Budget rejection retains original accounting when storage permits it. Cyclic path expansion and mutable or unsupported native flow remain unproven.

### Read retained witnesses

`READ_RESULT` accepts `IMPACT_WITNESS` sections `PRODUCERS`, `MODELS`, `NATIVE_READS`, `READ_REJECTIONS`, `FINDINGS`, and `SITE_ACCOUNTING`.

`FINDINGS` returns one compact row per original path: producer, destination, representation, model provenance, terminal, and obligations. Expand its evidence with `VALUE_PATHS`, cursor `pathOrdinal`, and `executionBudget.maxResults: 1`. The row retains `pathRowId`.

`SITE_ACCOUNTING` returns requested sites in original order with admission grants and observed work:

| State | Meaning |
| --- | --- |
| `REACHED` | Links original paths by ordinal and row ID, preserving separate scope exits. |
| `EXCLUDED` | Retains proven scope-exclusion witnesses. |
| `RELATIONSHIP_UNPROVEN` | Preserves identity and adds `REQUESTED_SITE_RELATIONSHIP`, preventing semantic completion. |

Site identity alone does not establish a producer relationship. Retained witness paging performs no semantic reads and preserves unresolved obligations. `EVIDENCE_ONLY` supplies no closed investigation claim.

## Defaults and limits

Omitted budgets use configured defaults and ceilings. Omission is not unlimited execution. Budgets do not change requested scope or output shape.

Every public tool accepts root-level boolean `verbose`. Omission or `false` selects compact output without removing semantic limitations. [Results](/reference/responses) explains continuation, coverage, and recovery.
