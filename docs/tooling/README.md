# Kast glossary tool

This directory owns the local grammar and projections for `docs/glossary.json`.
It also projects tracked OpenWiki OKF into the public site.
It does not depend on a shared glossary service or installed plugin files.
The [documentation policy](../documentation-structure.md#glossary-ownership) defines its consumer commands.

## Inputs and outcomes

The parser checks the JSON schema first. It then creates fixed concept values.
It rejects duplicate keys, unknown fields, unknown variants, missing evidence, label collisions, invalid scopes, and unknown related concepts.
Source citations remain evidence references. The tool never fetches their URLs or proves their meaning.

The reader views and Vale rules come from the parsed glossary.
`--render` writes the internal reader view. `--public-render` writes the public MDX glossary.
Both views use the same canonical definitions and source links.
`--vale-dir` exports rules into a new directory.
`--check-render` rejects a stale internal view. `--check-public-render` rejects a stale public view.
`--check-vale` compares the complete rule set with its generated bytes.
These checks do not change their input files.

Exit `0` means that the glossary and requested projections passed, without rejected forms in the supplied prose.
Exit `1` means that scoped prose contains a replacement target or review target.
Exit `2` means that an input, grammar, local effect, or projection failed.
The JSON report keeps the glossary digest. It also keeps file digests, findings, and their source locations.

CommonMark documents use `mdast-util-from-markdown` 2.0.2 with explicit YAML frontmatter extensions.
The fences start on the first line with `---` and end with `---` or `...`.
Each delimiter starts in column one and permits trailing spaces or tabs.
An incomplete delimiter pair remains Markdown. The adapter does not parse YAML values.
The adapter excludes code, frontmatter, and link destinations through native source ranges.
It matches raw glossary literals, with exact source positions for repeated text, escapes, and Unicode.
It does not match a term that needs entity decoding.
Opaque HTML keeps the earlier lexical policy, including visible text, attribute text, and prose after a comment terminator.
Image alternatives and reference definitions keep that same conservative policy.
Native code ranges protect literal comment markers before the lexical comment policy applies.
This opaque-markup policy does not claim rendering semantics.

MDX keeps the earlier lexical procedure. Plain text keeps literal scanning.
Neither path invokes the CommonMark parser.
CommonMark and MDX keep the earlier URL mask.
All paths apply the declared include and exclude patterns, with the longest label at overlapping locations.
Directory scans omit Git metadata, Gradle state, virtual environments, Python caches, build outputs, and Node dependencies before file selection.
Vale supplies a separate native markup parser.
These checks do not prove that source meaning is the same. They do not prove current source truth or that readers understand it.

The CLI sends all scoped CommonMark documents through one parser process.
The adapter checks each source identity and fixed range first. The glossary matcher then reads them.
It converts UTF-16 offsets to Python source positions and rejects offsets inside surrogate pairs.
The process can run for 30 seconds. A request can hold up to 8 MiB. A response can hold up to 32 MiB.
A batch admits at most 4,096 CommonMark documents. Each document admits at most 262,144 ranges.
Parser failures stop the scan with a finite `MARKDOWN_*` code. No lexical fallback replaces a failed parser.
`MARKDOWN_START` means that Node cannot start. `MARKDOWN_RUNTIME` means that its version differs from the declared runtime.
`MARKDOWN_INPUT` rejects the request contract. `MARKDOWN_LIMIT` rejects a size or count limit.
`MARKDOWN_PARSE` reports a parser failure. `MARKDOWN_NODE` rejects an unknown node type.
`MARKDOWN_RESPONSE` rejects the response contract or source identity.
`MARKDOWN_EXIT` reports a child exit without a response. `MARKDOWN_TIMEOUT` reports the process time limit.

## Development

Node 24.21.0 is a direct runtime dependency in the root `mise.toml`.
The parser uses the local `npm` lock. It does not import a global Mintlify installation or the Node dependency of Pyright.
The Gradle tasks install locked `npm` dependencies with package scripts off and isolated `npm` configuration.
CI pins the same Node version.

From the repository root, install the locked parser dependencies:

```shell
mise exec -- ./gradlew documentationMarkdownDependencies
```

From this directory, run:

```shell
mise exec -- npm run check --prefix markdown
mise exec -- uv run --locked pytest
mise exec -- uv run --locked pyright
mise exec -- uv run --locked ruff format --check .
mise exec -- uv run --locked ruff check .
```

The root `verifyDocumentationGlossary` task examines repository projections and current prose without the tooling tests.
Run `documentationToolingTest` to examine the tooling itself.
The root `check` and `productBuildGate` tasks include both tasks.
Both consumers use one locked Python environment under `build/documentation/python`.
Their reports reside in `build/reports/validation/`.
Gradle reuses unchanged reports and reruns consumers after an input change or a report deletion.

The shared prose assessor remains a separate consumer.
Its report v2 omits glossary fields and does not accept `--glossary`.
Keep historical reports under `docs/reviews` unchanged at their recorded revision.

## Shared OKF projection

`okf_public.py` reads `docs/okf-public.json`, tracked OKF pages, their Claim sidecars, and cited source files.
`markdown/project-okf.ts` changes actual CommonMark link destinations and adds scoped heading anchors.
Code literals keep their original text. Shared concepts use one generated snippet across public routes.
Presentation metadata and existing diagrams remain in the route manifest.

From the repository root, regenerate the public views:

For new OKF pages, stage the canonical pages and their Claim sidecars before this command.

```shell
mise exec -- uv run --locked --project docs/tooling python docs/tooling/okf_public.py --write
```

Use `--check` to reject changed outputs without a write.
The provenance report keeps page and sidecar digests, Claim identities, resources, recorded versions, and current file digests.
`MATCHED` means that a whole-file evidence digest matches current bytes.
`CHANGED` means that those bytes differ. `NOT_ASSESSED` keeps opaque or range versions without a freshness claim.
The public view qualifies changed and unassessed evidence.
No digest comparison proves semantic truth.

Missing source files, untracked evidence, unreconciled page edits, parser failures, and undeclared public pages reject the projection.
The projector does not change OpenWiki pages, Claims, indexes, or run state.
Use the native OpenWiki lifecycle for shared prose changes.

`verifyPublicKnowledge` examines current Git state and cited source bytes on each run.
The documentation CI lane runs the same parity procedure.
