Use the native `kast` command for Kotlin queries in one exact repository or worktree.
The persistent IntelliJ IDEA Host supplies compiler analysis. CLI queries need no MCP registration.

## Discover the installed contract

```shell
kast describe
kast source --help
kast result --help
kast describe query
kast describe query --section input --pointer '' --json
```

These commands read packaged contracts without workspace preparation.
Help lists commands and flags. `kast describe COMMAND` returns a contract summary.
Add `--section input` or `--section output` with `--pointer ''` to browse the schema root.
Each page lists direct children with their JSON Pointers, kinds, and child counts.
Scalar values are exact. Containers and references do not expand automatically.

Schema pages default to 16 entries and 16384 returned bytes, including the final newline in either output format.
Set `--max-results` from 1 to 128 and `--max-returned-bytes` from 1024 to 65536.
If `complete` is false, use `next_cursor` as `--cursor` with the same command, section, pointer, and catalog.
Copy a returned pointer unchanged to inspect a child. Quote pointers so your shell preserves `$` and other special characters:

```shell
kast describe query --section input --pointer '/properties' --json
kast describe source.read --section input --pointer '' --json
kast describe result.read --section input --pointer '' --json
```

A schema page is an inspection view, not a standalone validation schema.
References still point into the full section. A missing pointer or an entry larger than the byte budget rejects explicitly.
For validation or archival use, omit `--pointer` and write the complete schema to a file:

```shell
kast describe query --section input --json > input-schema.json
kast describe query --section examples --json > examples.json
```

Full exports can be large. Use schema pages for discovery and export only when you need the whole contract.

## Wait for the workspace

Session hooks start preparation in the background. Their context tells the agent when the workspace is being prepared.
Wait explicitly when the next task needs a ready workspace:

```shell
kast workspace wait --wait 30000
kast workspace wait --wait indefinite
```

The first command waits for up to 30000 milliseconds. The second has no preparation deadline.
Both print the selected mode before waiting and return a JSON outcome.
Failure, cancellation, a changed host or project, and editor closure can end either wait.
A preparation timeout returns exit status `124`. Cancellation returns `130`.
A timeout does not prove that native import work stopped.

Set `KAST_WORKSPACE_PREPARATION_WAIT` to positive milliseconds or `indefinite` for the default policy.
Saved installation and workspace settings support the same key. An explicit `--wait` overrides those settings.
Without a setting or flag, preparation permits 1020000 milliseconds, or 17 minutes.
See [workspace lifecycles](/reference/lifecycles#workspace-preparation-lifecycle) for ownership and failure rules.

## Find a declaration

Replace `submitOrder` and `checkout` with your function name and its directory.
Run the command from the intended Kotlin repository or worktree:

```shell
kast query --name submitOrder --in checkout --source-set main \
  --fields name,signature,location --max-results 20 --max-returned-bytes 8192 --retain
```

Use `--workspace PATH` when your current directory differs from the target worktree.
The `--fields` option accepts unique values from `name,location,signature,source` with `--output symbols`.
For `--output occurrences`, omit `--fields`.

Examine the owner, signature, and location before you select an exact reference.
An exact name can match several overloads.
The `--in` option limits discovery. It does not limit later relationship expansion.

## Inspect callers and source

Set `SYMBOL_REF` to the exact reference from the selected declaration.
Keep its value unchanged:

```shell
kast query --ref "$SYMBOL_REF" --relation callers --fields name,location
kast source read --ref "$SYMBOL_REF"
```

A caller result describes source relationships. It does not prove that those calls ran.
Keep the result's scope and qualifications with your conclusion.
Source reads and queries from issued references use the existing workspace authority.
They do not start another preparation that can reload the model.
A model change can still make a reference stale.

## Check file diagnostics

Select a Kotlin file or directory explicitly:

```shell
kast diagnostic check --path checkout/src/main/kotlin --max-diagnostics 100 --json
kast diagnostic check --path checkout/src/main/kotlin --max-diagnostics 100 \
  --continuation "$DIAGNOSTIC_TOKEN" --json
```

Keep the same path and diagnostic limit when you resume.
Use `--path .` explicitly for the whole workspace.
Keep incomplete coverage and qualifications with the result. An incomplete empty result does not prove a clean scope.
This command reads IDEA file diagnostics. It does not build the project.
Use `kast diagnostic check --help` or `kast describe diagnostic.check` for the installed contract.

## Read retained output

Use the result reference and cursors from the response:

```shell
kast result read --ref "$RESULT_REF" --cursor 100 --evidence-cursor 0
kast result resume --continuation "$OUTPUT_TOKEN"
```

The cursor values are examples. Replace them with both issued cursors from your response.
Use `result resume` only with an issued output continuation.
The CLI returns one page. It does not drain later pages or repeat the semantic query.

An expired or foreign reference rejects. Find the declaration again only when the reported recovery calls for discovery.

## Submit a full request

Save a public argument document from the installed examples as `query.json`:

```shell
kast query --request query.json --json
kast query --request - --json < query.json
cat query.json | kast query --request - --json > result.json
```

The document contains the public `request` field, without an RPC envelope.
The `--request` value names a file or selects stdin with `-`. It does not accept inline JSON.
Do not combine `--request` with semantic flags or `--verbose`.

## Read the outcome

Semantic commands emit JSON on stdout by default.
Set `KAST_OUTPUT_TOON=1` to select TOON.
Use `--json` to select JSON even when this variable selects TOON.
An unset, empty, or `0` value selects JSON.
The input document remains JSON with either output format.
For pipelines, keep stderr separate from the JSON result.

Use `--max-results`, `--max-returned-bytes`, and a narrow `--fields` selection before the query.
These limits bound presentation without stripping completion or recovery evidence.
Query byte limits measure canonical JSON presentation before TOON encoding. The outer envelope, newline, and stderr are outside that allowance.
An explicit `--request` document owns its execution budget; do not add semantic budget flags beside it.

Progress and diagnostics use stderr.
Read the outer outcome and its qualifications before a semantic conclusion.
An unfinished search with no matches does not prove absence.

`--max-results` limits presentation. It does not establish semantic completion.
A complete page can still have an issued continuation.

If `COMPLETION_UNPROVEN` includes `UNRESOLVED_ARGUMENT_MAPPING`, Kast cannot prove the requested callback relationships.
Keep the reported cause and original coverage with your conclusion.
If the response supplies `nextQuery`, save that argument document as `evidence.json`:

```shell
kast query --request evidence.json --json
```

This request reads retained evidence. It does not establish a complete callee list or repeat semantic work.
Use the issued result reference and both cursors for later pages.

The `--max-elapsed-ms` option sets an explicit elapsed budget.
If that budget expires, the CLI returns status `124`.
A longer grant does not resolve missing callback proof.
Keep the reported stage and readiness evidence before a new query.

## Filter structured output

Use `--jq FILTER` to project one successful JSON result with bundled jackson-jq before Kast encodes it as TOON or JSON:

```shell
kast query plan --name OrderService --fields name,location \
  --jq '{type,fields:.request.output.fields}'
```

The filter must emit exactly one JSON value. Use `map(...)` or `[FILTER]` to collect a generator explicitly.
An empty stream rejects; an empty array, `false`, and `null` are valid results.
Kast does not add an array, flatten nested arrays, select the first result, or enable jq's `-e` option.
For ordinary jq streams, raw strings, `--arg` bindings, or other jq command options, use a JSON pipeline:

```shell
set -o pipefail
kast query plan --name OrderService --json | jq -r '.request.output.fields[]'
```

Read the actual output contract before selecting paths. A presentation header, compact graph, and verbose result can have different fields.
Filtering does not request missing fields, read another page, follow a continuation, or rerun a query.
Keep `--fields` and semantic scope constraints on the original request when they can reduce its work.
Preserve completion, qualifications, and recovery evidence when interpreting a projection.

Kast checks filter syntax and numeric literals before workspace effects. Unknown functions and input types reject during evaluation.
Workspace failures, qualified results, time limits, and other nonzero Kast statuses keep their original documents without filtering.
After successful semantic work, a jq runtime failure discards any partial filter output and reports its stage and child exit status.
Use the retained result authority for recovery when available; projection failure does not retry semantic work.
If a rejection includes `recovery`, save that value as `recovery.json` and read it without the failed filter:

```shell
kast query --request recovery.json --json
```

The recovery preserves the issued reference and original output kind. A normal retained result is read from its beginning; an issued detail request remains unchanged.

### Embedded engine

Kast embeds jackson-jq `1.6.5` with jq `1.7` compatibility. No external jq, JVM installation, PATH lookup, or runtime download is needed.
The native Control image contains the library. `--jq-executable` is no longer accepted.
The version catalog in `gradle/libs.versions.toml` owns the library and compatible Jackson pins; installed discovery reads generated version metadata.
The separate jq pin in `mise.toml` supplies the independent qualification oracle.

Navigation, optional paths, `map`, `select`, sorting, grouping, function definitions and composition are supported.
This is a library subset, not full jq parity. CLI I/O functions such as `input`, `inputs` and `halt_error` are unavailable.
`implode` preserves complete Unicode scalars, including supplementary characters. Invalid scalars reject.
Environment access and external module or data loading are disabled. String interpolation rejects; use string concatenation or a JSON pipeline.
Kast passes the program as one argument without a shell. It does not echo program text, source payloads, or worker stderr in rejection documents.

### Numeric values

Input JSON and `fromjson` or `tonumber` conversions keep exact decimal values. An encoding change, including lost negative zero, rejects with `NUMERIC_VALUE_LOSS`.
Direct numeric literals must be whole numbers with magnitude at most `2147483647`.
Whole decimal and exponent forms such as `2147483647.0` and `1e3` are accepted.
The minus sign is a separate token, so `-2147483648` also needs quoted conversion.
For larger or fractional constants, use quoted JSON with `fromjson` or `tonumber`, such as `("1.25" | fromjson)`.
Unsupported literals report `NUMERIC_LITERAL_LIMIT` before workspace effects. Non-finite results reject.

Kast rejects input numeric conversions that change values during comparison, grouping or array indexing. Exact navigation and conversion to strings remain available.

Arithmetic follows jackson-jq: integral operators use signed 64-bit arithmetic, including overflow, and other numeric operators use doubles.
With input `9007199254740993`, `. + 1` produces `9007199254740994`. With input `9223372036854775807`, `. + 1` wraps to `-9223372036854775808`.
These arithmetic rules differ from native jq and do not provide exact arithmetic. The conversion checks do not verify intermediate arithmetic results. Keep opaque identifiers as strings when filtering them.

Before TOON publication, the existing guard separately rejects any changed value, key, null, or array shape with `OUTPUT_VALUE_LOSS`; use `--json` for values TOON cannot preserve.

### Limits and cancellation

| Option | Default | Accepted values |
| --- | --- | --- |
| `--jq-timeout-ms` | `5000` | `1..60000`, for each syntax-checking and filtering worker |
| `--jq-max-bytes` | `16777216` | `1..67108864`, for input, worker stdout, and successful encoded projections including their newline |

These options require `--jq` and have no effect on workspace waiting or semantic budgets.
Each worker has a private 512 MiB heap and a 32768-byte stderr bound. Programs are limited to 32768 UTF-8 bytes.
JSON nesting is limited to 1000 levels, and numeric tokens to 1000 characters. Exceeding these limits reports `JSON_LIMIT`.

A worker exits before workspace waiting starts; no filter process is kept alive while the workspace is being prepared.
On expiry or cancellation, Kast terminates and reaps its owned worker and joins its pipe readers before returning.

Heap or stack exhaustion reports `RESOURCE_LIMIT`; a smaller input or projection can still need more working memory than its encoded size.
`kast describe COMMAND` includes the default filter limits and a standalone schema for fixed filter rejections.
Its normal output schema describes unfiltered results; a successful user projection can be any JSON value.

TOON projections must preserve the selected JSON values exactly, including numerical precision and array shape.
If the encoder cannot preserve a number, Kast rejects with `OUTPUT_VALUE_LOSS` and directs you to `--json`.
JSON keeps jq's original numeric tokens. TOON encoding also rejects projections nested more than 128 levels deep.
Filtering can reduce returned data; the reduction depends on the filter and result shape.
