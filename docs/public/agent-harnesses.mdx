[Install Kast](/start) first. Your agent's command must be available in your terminal. Replace `/path/to/kotlin-repository` below with the exact repository or worktree you want to inspect.

## Choose your agent

<Tabs>
  <Tab title="Codex">
    The bundled plugin installs MCP tools, the query skill, and examples. If direct MCP is already registered, run `kast disconnect codex` first to avoid duplicate connections.

    ```shell
    kast plugin codex
    cd /path/to/kotlin-repository
    codex
    ```

    Restart Codex after installation.

    <Accordion title="Direct MCP without the bundled plugin">
      ```shell
      kast connect codex mcp
      cd /path/to/kotlin-repository
      codex
      ```

      Start a new session. `kast connect codex` requires an explicit transport.
    </Accordion>

    <Accordion title="App Server transport">
      New persistent installations use the standard Codex control socket when available. If it is occupied or cannot be inspected, Kast installs with a private endpoint. Routine installation preserves your saved endpoint. At the standard socket, managed `codex` invocations can discover Kast automatically. Compatible desktop builds also use the service's daemon-selection flag on a fresh launch.

      Quit and reopen an existing desktop app. Saved `private` endpoints and client overrides can bypass discovery. Desktop tool exposure depends on the [tested client boundary](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md).

      For explicit attachment:

      ```shell
      kast connect codex app-server
      cd /path/to/kotlin-repository
      kast-codex
      ```

      This installs `~/.local/bin/kast-codex`. Start a fresh thread to load dynamic tools. Custom clients can use `kast-codex app-server` for JSONL stdio.
    </Accordion>
  </Tab>
  <Tab title="Copilot">
    ```shell
    kast connect copilot
    cd /path/to/kotlin-repository
    copilot
    ```

    Restart Copilot to load the extension and installed catalog.
  </Tab>
  <Tab title="Pi">
    ```shell
    kast connect pi
    cd /path/to/kotlin-repository
    pi
    ```

    Restart Pi to load the extension and installed catalog.
  </Tab>
</Tabs>

Queries [prepare IntelliJ automatically](/concepts/background-startup). There is no separate workspace-open step.

## Check that the tools work

Ask your agent:

> Use Kast to find one Kotlin declaration in this repository. Show its name, kind, signature, source location, and coverage. Report any readiness or proof blocker.

A returned declaration with location and coverage verifies tool use. `kast status` reports registration.

For a useful first investigation, substitute your function and directory:

```text wrap
Use Kast to find submitOrder in the production Kotlin sources under checkout. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

Then ask:

```text wrap
Use the exact reference for the function I selected to find its callers. Show the call sites and searched scope, and report any unfinished work.
```

[Find and trace code](/search) explains the results. For missing tools or readiness blockers, use [Troubleshooting](/troubleshooting).

## A connection already exists

Matching registrations stay in place. For a conflict, inspect the existing registration before replacement.

<Accordion title="Explicitly replace a conflicting registration">
  Run only the command for your chosen integration:

  ```shell
  kast connect codex app-server --force
  # or: kast connect codex mcp --force
  # or: kast connect copilot --force
  # or: kast connect pi --force
  ```

  `--force` replaces that harness's Kast slot. Kast verifies the payload and captures the previous registration. Failed replacement attempts restoration. Failed restoration reports the backup and recovery destination.
</Accordion>

## Disconnect or upgrade

For a registration made with `kast connect`:

```shell
kast disconnect copilot
```

`kast disconnect codex` removes its recorded App Server launcher and MCP registration. Remove the Codex-owned bundled plugin with `codex plugin remove kast@kast`. Restart the affected agent.

After `kast upgrade`, restart IDEA and connected agents. For the bundled Codex plugin, rerun `kast plugin codex`.

## Install the skill independently

<Accordion title="Release archives and custom clients">
  [Control 0.3.1](https://github.com/amichne/kast/releases/tag/control-v0.3.1) supplies `kast-skill-v0.3.1.zip`, `kast-plugin-v0.3.1.zip`, and `kast-marketplace-v0.3.1.zip` with SHA-256 checksums.

  Extract the skill's `kast/` directory into `~/.agents/skills/` or your repository's `.agents/skills/`. Its generated examples use the public contract. Replace illustrative references with current workspace values.

  After checksum verification and marketplace extraction:

  ```shell
  codex plugin marketplace add /absolute/path/to/extracted-marketplace
  codex plugin add kast@kast
  ```

  The source marketplace is available through `codex plugin marketplace add amichne/kast`. Install Kast and a compatible Host first.

  Custom clients can use [MCP](/reference/mcp-catalog), [Tool RPC](/reference/rpc-catalog), or App Server. See the [adapter guide](https://github.com/amichne/kast/blob/main/docs/tool-rpc.md).
</Accordion>
