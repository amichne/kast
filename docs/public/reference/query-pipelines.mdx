## Complete static answers

Every public run needs complete execution within `COMPILER_RESOLVED_STATIC_V1`. Combining inputs keeps their identities and stated limits.

A finished output page cannot supply producer proof that is missing. During later output reads, rejection evidence stays `POLICY_REJECTED_EVIDENCE`.

The request examples use contract 17 syntax. The counts and replies come from the [historical recording](/reference/schemas#recorded-walkthrough) at `56df091`.
Adding explicit EMIT terminals does not rerun those calls or establish current counts. The recorded request bytes remain unchanged.

## 1. Keep a second query result

The recording's input A contains ten implementations of `QueryStepSyntax`. Input B contains two class-like declarations named `Concat`.

Only `QueryStepSyntax.Concat` implements that interface. `ExactQueryStage.Concat` has a separate identity despite the equal name.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "Concat",
      "declarationKinds": ["CLASS"],
      "scope": {
        "type": "DIRECTORY",
        "relativeDirectoryPath": "query/contract",
        "sourceSetNames": ["main"]
      }
    },
    "terminalStep": {
      "type": "EMIT",
      "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION", "SIGNATURE"]}
    },
    "retention": "RETAIN"
  }
}
```

<a id="combine-both-inputs-then-filter-the-combined-stream" />

## 2. Combine the inputs

Use `UNION` to combine symbol identities. Apply a later `WHERE` to the combined stream.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {"type": "RESULT", "result": "<result A>"},
    "steps": [
      {"type": "UNION", "right": {"type": "RESULT", "result": "<result B>"}},
      {
        "type": "WHERE",
        "predicate": {
          "type": "PRIMITIVE",
          "field": "NAME",
          "operator": "EQUALS",
          "value": "Concat"
        }
      }
    ],
    "terminalStep": {
      "type": "EMIT",
      "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION", "SIGNATURE"]}
    }
  }
}
```

Recorded call `04-union-filter` returned both declarations with exhaustive coverage. The filter acted after the union.

`CONCAT` uses `input` and keeps order and duplicates. It does not use union's identity reduction.

## 3. Select the composition rule

Use `INTERSECT` to keep identities present in both inputs.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {"type": "RESULT", "result": "<result A>"},
    "steps": [
      {"type": "INTERSECT", "right": {"type": "RESULT", "result": "<result B>"}}
    ],
    "terminalStep": {"type": "EMIT"}
  }
}
```

Recorded call `05-intersection` returned `QueryStepSyntax.Concat`. The shared identity kept evidence from both producers.

## 4. Project a joined cell before another symbol step

Use an `INNER` join to keep two named cells. Select one cell before a later symbol step.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {"type": "RESULT", "result": "<result A>"},
    "steps": [
      {
        "type": "JOIN",
        "mode": {"type": "INNER", "leftName": "step", "rightName": "candidate"},
        "right": {"type": "RESULT", "result": "<result B>"}
      }
    ],
    "terminalStep": {"type": "EMIT", "output": {"type": "BINDING_ROWS"}},
    "retention": "RETAIN"
  }
}
```

Recorded call `06-join-c` kept one pair as C. Both cells identified `QueryStepSyntax.Concat` through their own evidence.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {"type": "RESULT", "result": "<result C>"},
    "steps": [
      {"type": "PROJECT_BINDING", "name": "step"},
      {"type": "EXPAND_RELATION", "relation": "REFERENCES"}
    ],
    "terminalStep": {"type": "EMIT", "output": {"type": "OCCURRENCES"}}
  }
}
```

Recorded call `07-project-references` found this compiler-confirmed occurrence.

```kotlin
is QueryStepSyntax.Concat -> ExactQueryStage.Concat(step.input, stage)
```

Arbitrary-field joins and a general-purpose `MAP` have no supported contract. [Composition contracts](/reference/composition) defines legal row forms.

## Choose the relationship search domain

`EXPAND_RELATION` defaults to workspace expansion. An unbounded `WALK` also defaults to workspace expansion.

With an explicit walk depth, the default is the retained seed's scope. An explicit `expansionScope` overrides either default before the scan.

```json
{
  "type": "EXPAND_RELATION",
  "relation": "REFERENCES",
  "expansionScope": {
    "type": "SOURCE_DOMAIN",
    "sourceSets": ["main"],
    "directory": "query/contract",
    "includeSubdirectories": true,
    "sourcePolicy": "PRODUCTION_ONLY",
    "generatedSources": "EXCLUDE"
  }
}
```

This current source-domain example does not change the recorded counts. A later `WHERE` cannot reduce work in the native scan.

## Read source around an occurrence

Copy the issued `candidateSelector` from an occurrence into `candidateRef`.
Select its structural region independently of the text view.

For an exact declaration, copy its issued `ref` into `candidateRef`.
Use `CALLABLE_BODY` to select its callable body.
Exact focus reads restore the original authority and reject stale references without reacquisition.

```json
{
  "request": {
    "type": "READ_SOURCE",
    "candidateRef": "<issued candidateSelector>",
    "region": "ENCLOSING_CALLABLE_BODY",
    "text": {"type": "EXCERPT", "maxLines": 20}
  }
}
```

`ENCLOSING_DECLARATION`, `ENCLOSING_CALLABLE_BODY`, and `ENCLOSING_CLASS_BODY` select the smallest strict enclosing region of that kind.
`CALLABLE_BODY` and `CLASS_BODY` select the nearest matching body, which can belong to the anchor itself.
`ANCHOR` keeps the exact anchor, and `FILE` selects its file.
A structural owner must contain the full focus.
A window across sibling declarations cannot select just its first callable.

Omission or `null` selects `ANCHOR` and `COMPLETE` text.
`EXCERPT` returns at most `maxLines` around the anchor start, clipped to the selected region.
Its default is 40 lines, and its range is 1 to 1000 lines.
`WINDOW` defaults to five lines before and after the anchor, clipped to the selected region.
A window includes the full anchor span, so a multi-line anchor can produce more text than these line counts.
An oversized view withholds text and reports an explicit limitation.

The response keeps the structural region selector separate from the text selector.
A window selector identifies an excerpt and does not prove complete declaration text.
For more context, copy the issued region selector into `candidateRef` and request `COMPLETE` text.
For a selector without text, use `"text": {"type": "NONE"}`.
Source re-entry keeps the original source scope and rejects stale snapshots.
It does not replay query stages.

## Read produced output or retained rows

Use `RESUME` for an issued output continuation. Use `READ_RESULT` for rows from an identified retained result.

```json
{"request":{"type":"RESUME","continuation":"<issued output continuation>"}}
```

```json
{"request":{"type":"READ_RESULT","result":"<issued symbol-result reference>"}}
```

```json
{"request":{"type":"READ_RESULT","result":"<result C>","output":{"type":"BINDING_ROWS"}}}
```

Recorded calls `08-read-a` and `09-read-c` returned ten symbols and one pair. Both kept their original identities.

### Reject an unproven absence claim

`DIFFERENCE` and `ANTI` need complete right coverage. The right producer has to finish its work. A missing match in a prefix cannot prove absence.

Recorded call `10-incomplete-right` supplied incomplete right coverage. Both absence operations returned this historical rejection.

```json
{
  "status": "rejected",
  "rejection": {
    "type": "execution-rejected",
    "reason": "right-input-incomplete"
  },
  "next_action": "correct_request"
}
```

Current complete-only execution can reject before an incomplete answer becomes reusable. If resources run out, that still does not prove absence.

If the epoch changes, start fresh producing queries. [Staleness](/reference/staleness) defines reuse, and [Results](/reference/responses) defines independent row and evidence positions.
