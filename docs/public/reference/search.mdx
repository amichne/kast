Start with one declaration, read its source, and use its exact reference to trace affected uses. Your [connected agent](/reference/integrations) writes the query.

## 1. Find a declaration and inspect its source

To find a declaration, substitute its name and directory in this prompt:

```text wrap
Use Kast to find submitOrder under checkout in main. Show matching signatures, locations, and coverage. Stop so I can choose the exact function.
```

Select the declaration by signature and file. Ask the agent to read its source. Keep the exact reference for later queries.

For a Kotlin interface, use `declarationKinds: ["CLASS"]`. The `CLASS` request family includes supported class-like declarations, interfaces, and objects. Returned symbols use `kind: "classlike"`. Requests reject `INTERFACE` and `CLASSLIKE` as kind values.

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "CacheManager",
      "declarationKinds": ["CLASS"],
      "scope": {
        "type": "PACKAGE",
        "packageName": "example.cache",
        "includeSubpackages": false,
        "sourceSetNames": ["main"]
      }
    },
    "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION", "SIGNATURE"]}
  }
}
```

To find an interface method, use `declarationName: "execute"` and `declarationKinds: ["FUNCTION"]` in the same package. Examine the signature's qualified identity to select `example.cache.CacheManager.execute` from its overrides. An exact name can match several overloads and owners.

Exact-name discovery uses name indexes and a supplemental declaration scan to prove completeness within the admitted scope. Before discovery, apply the directory, package, source-set, and declaration-kind constraints that you know. An exact name alone does not limit how many source files the completeness scan visits.

`AT_LOCATION` selects the nearest containing named declaration. An offset inside a method's generic parameter list selects that method. An offset on `manager.execute(...)` selects the enclosing declaration. It does not resolve the `execute` token to the interface method.

To establish that relationship, select the exact method. Request `REFERENCES` or `CALLERS` in the intended search domain. Use occurrence evidence to identify the use site.

Offsets and returned ranges use UTF-16 code units. Byte offsets and line numbers do not identify those positions. After edits, recalculate offsets from the current file.

| Evidence | Why it matters |
| --- | --- |
| Signature | Distinguishes overloads. |
| Location | Identifies the repository and declaration. |
| Coverage | Reports whether the requested search finished. |
| Exact reference | Carries the selected identity into the next request. |

## 2. Trace the selected declaration

To trace a function, interface method, or type, ask:

```text wrap
Use the exact Kast reference we selected to TRACE affected uses across the workspace. Show signatures, locations, occurrence evidence, and completion. Keep the result for follow-up reads.
```

The agent must pass the issued reference unchanged. In this example, replace the placeholder with the `ref` from the previous response:

```json
{
  "request": {
    "type": "RUN",
    "source": {"type": "SYMBOL_REFS", "symbolRefs": ["<issued ref>"]},
    "steps": [{"type": "TRACE", "expansionScope": {"type": "WORKSPACE"}}],
    "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION", "SIGNATURE"]},
    "retention": "RETAIN",
    "executionBudget": {"maxElapsedMs": 30000}
  }
}
```

`TRACE` covers references, implementations or overrides, direct callers, and one further caller layer. A type trace also covers the type's direct functions and properties. Kast groups declarations and keeps occurrence evidence. The topology is fixed. `TRACE` must be the final step and use `SYMBOLS` output.

This example requests 30 seconds for the trace. The host can admit less time. Read the returned execution budget. All branches share the elapsed grant.

Discovery scope selects the seed. `WORKSPACE` lets the trace reach clients in other modules. If the question excludes those destinations, choose `SOURCE_DOMAIN`. `RETAINED_SEED` limits expansion to the selected capability's scope.

A later filter cannot reduce native search work. See [Query forms](/reference/api#apply-only-the-steps-you-need) for expansion controls.

## 3. Read completion and choose recovery

Every `RUN` uses the fixed `COMPLETE_ONLY` policy for a complete compiler-static answer. If proof is incomplete, Kast returns `COMPLETION_UNPROVEN`. The rejection includes its finite cause and recovery evidence when available.

A saved preview contains established facts. It does not prove completion. Use its result reference with `READ_RESULT` to inspect the evidence. For a completed answer, the same action can present more rows.

`RESUME` accepts issued output continuations. The internal runner owns semantic page continuation. A historical checkpoint or result cursor cannot authorize execution.

`TRACE` gathers incoming paths before it groups results. Budget exhaustion returns a completion rejection with proof that Kast can keep. A larger timeout request does not remove host ceilings.

For direct callers or implementations, use one `EXPAND_RELATION`. For a graph with a specified depth, use `WALK`. Examine its hop evidence before a conclusion. [Query forms](/reference/api) describes both forms.

If `WALK.maximumDepth` and `WALK.expansionScope` are omitted or null, `WALK` exhausts the reachable graph across the workspace. Discovery scope does not restrict those destinations.

If the question needs a limit, set the depth or destination scope explicitly. Keep `COMPLETE_ONLY`. Resource exhaustion leaves proof incomplete. Later output filters do not reduce native enumeration work.

Calls inside lambdas keep their separate ownership. A static callback path does not prove runtime execution. See [Callback evidence](/reference/callbacks) for ownership and activation limits.

## Start from remembered text

```text wrap
Use Kast to find functions containing the word retry under checkout in main. Show a matching line for each function, then let me choose one to inspect or trace.
```

Use one case-sensitive ASCII word that starts with a letter or underscore. Kast rejects phrases, substrings, qualified literals, and regular expressions. A word match explains how Kast found the declaration. Use a relation query to establish callers. Unsupported containers or a stopped scan leave coverage incomplete.

## Keep the investigation current

Pass issued references unchanged. If a reference is stale or saved state is unavailable, search again. Edits, IDEA restarts, and retention expiry can invalidate saved work.

A new opaque reference with the same signature and location does not alone prove a source change. When Kast reacquires an exact handle, read `reference_acquisitions`. Keep each response's semantic basis.

Signature and location help select a declaration. The exact handle supplies authority. Continuations and source snapshots need their original basis. [Read-limit diagnostics](https://github.com/amichne/kast/blob/main/docs/hosted-read-configuration.md#read-the-evidence) explains the bounded epoch-movement signals.

Read [What an answer proves](/reference/evidence-boundaries) before a conclusion. Use [Results](/reference/responses) for progress or [Combine query results](/reference/query-pipelines) for composition with saved results.
