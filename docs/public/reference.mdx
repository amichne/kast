Kast turns compiler-resolved Kotlin facts into evidence that an agent can inspect and reuse. Its contracts preserve declaration identity, source state, scope, and proof limits.

<span id="understand-the-mechanisms" />

## Related architecture

| Mechanism | What Kast establishes |
| --- | --- |
| [Program tracing](/reference/program-tracing) | Calls, callback routes, and transfers inside functions, with evidence for each supported hop. |
| [Staleness](/reference/staleness) | The state a read needs, fresh authority for exact references, and rejection of obsolete retained evidence. |
| [Lifecycles](/reference/lifecycles) | The owners of requests, connections, workspace preparation, and daemon startup or retirement. |

The compiler-static model does not establish runtime execution or path feasibility. Missing proof returns a finite rejection with available evidence.

## Client contracts

MCP, Tool RPC, and hosted App Server carry canonical operation documents through distinct client lifecycles.

| Client | Contract authority |
| --- | --- |
| [Direct MCP](/reference/mcp-catalog) | Installed `tools/list` entries and input and output schemas. |
| [Tool RPC](/reference/rpc-catalog) | Installed `catalog`, process commands, and reply variants. |
| [Hosted App Server](/reference/compatibility) | The conversation's provider catalog and admitted client protocol. |

The shared tools are `query_symbols`, `check_diagnostics`, `add_declaration`, and `replace_body`.

Direct MCP and Tool RPC expose `health_check`. Hosted App Server exposes `workspace_lifecycle` for separate project actions.
