## Try three changes

- **Change one line:** the list still holds email drafts, but a new expression creates a different customer as the recipient.
  The separate call inside `draftWelcomeEmail` remains in source; this list no longer uses it.
- **Find the other use:** one call supplies an email draft's recipient; the other supplies a customer directly to a list.
  These are separate call contexts, not one runtime object splitting in two.
- **Remove one rule:** the code stays the same. Without the reviewed rule for `map`, the output-element connection is not established.
  That does not prove that no connection exists.

A search for `Customer` finds text in all these examples. The connections explain why the answers differ.
