Check host admission, schema compatibility, and evidence lifetime separately.

Passing one boundary does not establish another.

## Supported host

| Boundary | Current policy |
| --- | --- |
| Platform | macOS on Apple silicon |
| Repository | On-disk Kotlin Gradle repository |
| IDEA and bundled Kotlin plugin | Both in the `262` release line; patch builds may differ |
| JBR | Java 25 bundled with the selected IDEA |
| Native acceptance baseline | IDEA `262.10315.125`, Kotlin `262.10315.125-IJ` |

- Other `262` builds are admitted by policy without the same native acceptance evidence.
- Other release lines, Linux, Intel macOS, and other languages are unsupported.
- Runtime evidence retains the complete observed build identities.
- Protocol, schema, and artifact-integrity checks remain exact.

## Installed client contracts

| Connection | Discover the installed tools |
| --- | --- |
| Direct MCP | Call `tools/list` in the client session. |
| Tool RPC | Run `kast-tool-rpc-complete catalog` from the selected repository. |
| Codex App Server | Use the provider catalog supplied for the connected conversation. |

Use the catalog and schemas from the installed release. After an upgrade, let
the client discover them again. [Connect an agent client](/agent-harnesses)
compares these paths; the [MCP](/reference/mcp-catalog) and
[RPC](/reference/rpc-catalog) pages list the direct tools.

<Note>
  The Codex App Server integration remains a preview, and full Desktop UI
  compatibility remains unqualified. On the tested macOS host, Codex 0.154.0
  started as Kast's managed upstream; 0.156.0 published a socket alias Kast
  could not verify and was rejected. A 0.156.0 CLI connected to the 0.154.0
  upstream through Kast.
</Note>

See the [source-backed compatibility record](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md)
for the tested boundary.

## Upgrade a matched installation

1. Run the [installer](/start) for the selected release.
2. Restart IDEA so the matched plugin loads.
3. Restart the client or rediscover its tool catalog.

The installer verifies control and plugin payloads before activation.

Repository source and unrelated JetBrains state remain unchanged.

Do not reuse metadata from a different installation.

Use [Troubleshooting](/troubleshooting) when startup or repository admission fails.

## Refresh evidence after changes

Compatible schemas do not keep a reference alive indefinitely.

Search again after saved-source changes, imported-model changes, owner replacement,
or stale-reference rejection.

Never reinterpret a token to fit new evidence.

[Evidence outcomes](/concepts/evidence-boundaries) explains each semantic status.
