Kast lets an agent find Kotlin declarations, follow compiler-resolved relationships,
read source, check diagnostics, and plan an approved declaration change in your
open IntelliJ project.

## What do you need to do?

| Task | Start here | You get |
| --- | --- | --- |
| Connect a Kotlin repository | [Install and connect](/start) | A working agent tool catalog |
| Find a class, function, or property | [Search declarations](/search) | Separate matches, compiler signatures, and reusable references |
| Follow callers or implementations | [Compose a query](/query-pipelines) | Related declarations from an ordered query |
| Decide what an answer proves | [Read a response](/reference/responses) | Status, coverage, item failures, and the next action |
| Add a declaration | [Plan and apply a change](/change) | A file preview, exact-plan approval, and verification evidence |
| Integrate your own agent host | [Harness contract](/agent-harnesses) | Installed schemas and executable bindings |

## Make one useful request

After [setup](/start), ask your agent to find a declaration by its simple name.
For a class named `OrderService`, the tool input is:

```json
{"class_name":"OrderService","name_match":null,"scope":null}
```

`kast.search_classes` searches exact, case-sensitive names in the imported `main`
and `test` source sets by default. `null` is an explicit default; keep all three
fields. Use your project's declaration name when trying this example.

Read the returned semantic status before the matches. A **complete** search can
establish absence within its scope. A **qualified** search carries limits that
must accompany the answer. A **rejected** search needs the reported problem
resolved before it can answer the question.

## Keep the compiler evidence

A result's `symbol_ref` is the reusable identity. Copy it into later tools;
`name`, file location, and a printed signature help a person understand the match
but cannot replace that reference. [Inspect a symbol result](/reference/symbols)
for the fields, signature variants, and reuse rules.

Semantic reads use saved, indexed project state. Open the repository in IDEA,
finish import and indexing, and save edits before asking again. An unavailable
host returns a blocker; a search does not open or import the project for you.
