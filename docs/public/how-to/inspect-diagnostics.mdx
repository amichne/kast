Use this guide to see the problems that IDEA reports for a source path.

You need a connected client and a saved, indexed IDEA project for the exact repository. Check that the installed catalog exposes `check_diagnostics`.

1. [Select one existing path.](#1-select-the-path)
2. [Request its diagnostics.](#2-request-the-diagnostics)
3. [Read coverage before the diagnostic list.](#3-read-the-result)

## 1. Select the path

Choose a workspace-relative file or directory. Use `.` explicitly for the workspace root.

Start with the smallest path that covers your question. The request for a file under `src/main/kotlin` has this form:

```json
{
  "relativePath": "src/main/kotlin/tutorial/KastTutorial.kt"
}
```

Replace the example path with an existing path. The example shows an input, not a recorded result.

## 2. Request the diagnostics

Ask your agent:

```text wrap
Use Kast check_diagnostics for src/main/kotlin/tutorial/KastTutorial.kt. Show each problem's location and the response's reported scope and coverage. Do not change source.
```

For a directory, the call covers supported files in that directory and its subdirectories.

## 3. Read the result

Read the reported scope and coverage before the diagnostic list. Keep each diagnostic's location and severity with its message.

If coverage is incomplete, an empty list does not prove that the requested scope contains no problems.

If IDEA reports a trust, import, save, or indexing blocker, resolve it in the selected project.

<span id="4-establish-the-result-of-a-change" />

## 4. Prove the result of a change

After you change source, repeat the scoped diagnostic request. Run your project's build and tests for the behavior that changed.

IDEA diagnostics do not prove a successful project build. [Diagnostic entry](/reference/models/diagnostic) defines the result fields.

[Troubleshooting](/reference/troubleshooting) covers setup and state failures.
