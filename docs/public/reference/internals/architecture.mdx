<span id="bounded-execution-keeps-progress" />

Kast gets facts about source from the IDEA project for one exact repository. Adapters carry them to the agent. They keep the source state and proof limits with the facts.

<span id="authority-stays-with-the-program" />

## Who proves each fact

IDEA supplies the imported Gradle model. It also supplies the bundled Kotlin compiler analysis and indexes. Indexes find candidates. Compiler evidence proves their meaning.

Each domain owns exact checks for declarations and relationships. The query protocol runs those reads. It keeps their stated limits.

1. The agent chooses the question; the transport carries it.
2. IDEA admits the exact workspace and current read state.
3. Domain services prove compiler facts. The query keeps completion and limits with the evidence.
4. The agent interprets that scoped evidence and chooses its next action.

Control owns the installed adapters and coordinates their work. Host owns the IDEA plugin and project admission. The components pass contract checks before a semantic call.

<span id="execution-and-presentation-have-separate-limits" />

## Limits on work and output

`CanonicalQueryProtocol` dispatches public actions. It also owns internal semantic continuation. It keeps one question and one execution grant throughout a run.

Discovery tracks files left to visit and its active source positions. A filtered page with no rows can still advance the run.

`QueryStateStore` owns retained rows and output state. Output reads use the authority it issues. They keep the original coverage.

Public `RESUME` and `READ_RESULT` do not replay semantic work. A retained preview cannot strengthen completion proof.

<span id="read-state-constrains-reuse" />

## State needed for reuse

Workspace admission records the exact root, Host, read epoch, and committed source state. Kast checks content and compiler identity again. These checks prove the facts needed for each request.

An exact reference can get fresh authority under its identity policy. Retained evidence needs its original state and lifetime.

Saved records keep source identities and how facts were derived. They hold no live PSI or compiler objects. Their stored form cannot replace current native authority.

<span id="tracing-within-and-between-functions" />

## Tracing code

Relationship domains prove references and calls through the compiler. Callback flow keeps each anonymous owner. It also keeps supply, formal mapping, aliases, forwarding, and call sites.

Value impact tracks supported transfers from exact producers. It keeps the supplied representation models. Reading more output keeps the original investigation ledger.

If proof is incomplete or not supported, Kast reports a specific cause. [Program tracing](/reference/program-tracing) describes the supported claims.

<span id="runtime-ownership" />

## Who owns runtime state

Workspace preparation opens IDEA and reads its status. Hosted App Server workspace lanes coordinate semantic requests. They also settle uncertain writes.

When a service starts or stops, it checks installation ownership and readiness identity. Lifecycle fences guard those transitions. A client registration does not prove those facts.

[Lifecycles](/reference/lifecycles) connects these owners. [Staleness](/reference/staleness) describes the state each read needs.

[The source map](/reference/source-map) links current owners and focused tests. OpenWiki gives source-bound context. It does not replace these contracts.
