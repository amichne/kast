Kast exposes a live, one-hop compiler relation through `relation.read` and a
bounded multi-hop graph workflow through `topology.build` and `traversal.run`.
Both retain the exact selector and workspace generation that admitted the
question.

## Publish before traversing

<Steps>
  <Step title="Resolve an exact starting symbol">
    Use `kast symbol discover`, then `kast symbol inspect --candidate`, to
    obtain an exact, generation-bound selector and compiler evidence.
  </Step>

  <Step title="Read one compiler-confirmed hop">
    ```console
    kast relation read \
      --selector '<exact-selector>' \
      --relation callers \
      --limit 50
    ```

    Use the direct read for current-generation references, callers, callees,
    implementations, inheritors, overrides, or type uses. Complete and
    qualified results preserve compiler provenance and explicit coverage.
  </Step>

  <Step title="Build complete topology">
    ```console
    kast topology build
    ```

    The endpoint enumerates the admitted source roots, extracts semantic
    topology through IntelliJ, and publishes a durable snapshot only when the
    current generation is still valid. An eligible unchanged snapshot is
    reused instead of extracted again.
  </Step>

  <Step title="Traverse with explicit bounds">
    ```console
    kast traversal run \
      --selector '<exact-selector>' \
      --relation references \
      --maximum-depth 3 \
      --maximum-results 50
    ```

    Traversal reads only the eligible durable snapshot. It never starts hidden
    compiler work and keeps depth, result, work, time, and byte limits attached
    to the outcome. The wire result normalizes repeated symbols and proof
    identities into compact `nodes`, `edges`, and `proofs` tables. Full compiler
    signatures are fetched only when needed through `symbol_inspect` (the
    façade over `symbol.inspect`).
  </Step>
</Steps>

## Follow a workspace generation

Topology snapshots and selectors belong to one semantic generation. A
successful hosted apply publishes a newer generation in the same endpoint, so
the prior selector and snapshot cannot silently answer for the changed source.
After verification publishes the topology delta, resolve a fresh selector and
traverse the resulting generation without restarting IntelliJ.

A cold Project restart is deliberately different: Kast advances the semantic
generation because layout metadata cannot prove source content stayed unchanged
while the Project was closed. Run `kast topology build` once after reopening.
The build verifies the exact current candidates and reports `reused` when it can
rebind the unchanged durable snapshot to the new generation. Selectors from
before the restart remain stale.

<Info>
  A complete traversal supports only the requested relation, direction, root,
  depth, and result bound. A qualified result keeps its reached bound visible;
  stale or unavailable topology rejects.
</Info>

## Locate slow phases

Ready endpoints forward `kast.topology.build` and `kast.traversal.run` span
trees asynchronously to the private OTLP JSON Lines file reported by
`kast product inspect`. Child spans distinguish snapshot eligibility and reads,
candidate enumeration, extraction, revalidation, publication, snapshot open,
and traversal expansion. Only closed outcome classes and non-negative file or
record counts are exported; repository paths and symbol selectors are excluded.
