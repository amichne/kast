# Kast 1.0.0 readiness

`kast container` now uses the native CLI to run commands in a mounted Git worktree.
The candidate remains unqualified for 1.0.0.
This report covers local changes after the recorded source revision.
It grants no image publication, release promotion, or merge authority.

## Current command and runtime

Normal use needs the native Kast executable, Colima on macOS, and a prepared native image.
The host needs no Docker CLI, uv, Python, Java, or desktop IDEA for this command.
Colima supplies its bundled `nerdctl` client and containerd through the separate `kast-native` profile.
The image contains its own runtime tools, including Python for workspace setup.

`ContainerDispatch` owns syntax and literal task arguments.
`ContainerRuntime` owns image selection and container startup.
`ContainerPlan` admits the retained image, user, mounts, network mode, and workspace identity before a task starts.
Unknown commands, invalid names, and incompatible retained containers reject.
`status` starts no VM or container.

The `--image` option accepts an immutable registry reference or a local image digest.
A new workspace without that option selects the local image for the native architecture.
Later calls without that option keep the image from the retained workspace.
The native path accepts the v3 development layout.
The separate OCI base image does not satisfy that layout.

The checkout command `mise exec -- kast-container build --checkout /path/to/kast` remains a source-build tool.
It still needs Docker, uv, and the repository toolchain.
The installed command no longer delegates tasks to that Python tool.
See the [container guide](../../packaging/container/README.md) for image transfer and command syntax.

## Source and cache behavior

`ContainerWorkspace` reads Git metadata without a host Git process.
The container mounts the worktree at its original absolute path.
A linked worktree also receives its external Git metadata at the original path.
Guest edits and build outputs therefore change local files directly.

The retained container keeps its IDEA profile and indexes.
A private volume at `/opt/kast/state/home/.gradle` serves both shell builds and IDEA imports.
It keeps Gradle dependencies, wrapper distributions, and build-cache entries when the build cache is enabled.
The command neither mounts the host's live Gradle cache nor supplies a shared dependency seed.

A task name separates private runtime state and caches for one worktree.
Names share that worktree's source files and build outputs.
Separate Git worktrees supply independent edits and build outputs.
Concurrent host and container builds in the same worktree remain outside the qualification scope.

The guest helper grants trust to one exact workspace.
Each repeated command admits that exact grant again before the child starts.
An incompatible grant rejects instead of expanding trust.
These mechanisms describe cache and runtime reuse. They do not establish a startup or build-time improvement.

## Historical evidence

Commit `5ce521d4b32b1b461a94b7817d48192a9cebfdb7` exposed the earlier Python launcher and corrected the installer's retired `plugin codex` call.
The installer calls `install codex` and preserves its exit status.
At that revision, 64 installer cases, 43 container cases, and 377 management tests passed.
Native compilation and the product gate also passed for that revision.
Those results do not qualify the current native coordinator.

The earlier ARM64 Docker trial used copied workspaces and a disposable image derived from `sha256:93783a4d2e08f3dd16c2553b87a1996db826a89a2e41315b6468f52796713a5f`.
It covered separate task copies, retained edits, offline network rejection, and `kast --version`.
It did not cover mounted worktrees, containerd, compiler queries, or guest components from the current source.
The old copied-workspace simulation no longer exists because its runtime owner retired.

## Release prerequisites

| Outcome | Remaining evidence |
| --- | --- |
| Install Control without desktop IDEA | A public bootstrap for container use without a desktop Host prerequisite. |
| Start without a Kast checkout | Published immutable v3 images and an authenticated default image selection. No public v3 image was published. |
| Qualify both architectures | Fresh ARM64 and x86_64 images from the release source, with compiler queries and rejection cases. |
| Qualify host behavior | Fresh installations on multiple supported hosts, with linked worktrees and retained state. Other OCI runners need separate adapters. |
| Delegate agent work | A real agent task, private authentication, a visible edit, and a compiler result for that edit. |
| Qualify cancellation and retirement | Early-registration cancellation, transport loss, detached descendants, and explicit container and volume retirement. Direct-process signals and retained-container restart passed locally. |
| Support a performance claim | Comparable cold and warm runs with fixed source, commands, toolchains, and cache state. |
| Freeze 1.0.0 contracts | Reviewed syntax, schemas, exit codes, supported platforms, compatibility policy, and upgrade recovery. |
| Promote tested bytes | Exact-source product qualification, terminal CI results, and promotion of those same artifacts. |

A passing source gate does not satisfy these release prerequisites.
