## 1. Connect your agent

<Tabs sync={false}>
  <Tab title="Codex">
    The installer offers the Kast plugin in Codex by default. If you accepted it, restart Codex and select your Kotlin repository or worktree.

    If you skipped plugin installation, run:

    ```shell
    kast plugin codex
    ```

    Restart Codex after installation. Review and trust its session context hook in Codex. Use [integration options](/reference/integrations) for startup requirements and compatibility commands.
  </Tab>
  <Tab title="Copilot">
    ```shell
    kast connect copilot
    ```

    Restart Copilot to load Kast. Start Copilot from your Kotlin repository or worktree.
  </Tab>
  <Tab title="Pi">
    ```shell
    kast connect pi
    ```

    Restart Pi to load Kast. Start Pi from your Kotlin repository or worktree.
  </Tab>
</Tabs>

## 2. Request a declaration

Select the exact Kotlin repository or worktree in the agent. Keep IDEA open with that project imported.

The plugin's MCP session starts IDEA preparation for projects with `settings.gradle.kts`. Semantic calls wait for preparation and report blockers.

<Prompt description="Use Kast to find a Kotlin function in this repository. Show its name and source location. Report a setup problem if you cannot." actions={["copy"]}>
Use Kast to find a Kotlin function in this repository. Show its name and source location. Report a setup problem if you cannot.
</Prompt>

A Kast result identifies the declaration and its source location in the selected project. Trust, import, or indexing blockers need recovery before the next query.

The request is an example, not a recorded native run. A listed catalog alone does not establish semantic readiness.
