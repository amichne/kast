The installed MCP process uses stdio from the client's repository directory. After negotiation, `tools/list` defines the installed names, `inputSchema`, and `outputSchema`.

| Tool | Purpose |
| --- | --- |
| `query_symbols` | Declarations, source, relationships, and composition. |
| `check_diagnostics` | IDEA diagnostics for a path. |
| `health_check` | Workspace binding and readiness. |
| `add_declaration`, `replace_body` | Targeted source changes. |

Hosted `workspace_lifecycle` is separate and absent from direct MCP.

## Call and result

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {"name": "health_check", "arguments": {}}
}
```

For queries, use `query_symbols` and its [arguments](/reference/api).

The JSON-RPC result carries `content`, `isError`, and admitted `structuredContent`. For semantic tools, `structuredContent` is the canonical operation document, preserving status, references, coverage, failures, and recovery evidence.

Inspect `isError` and the semantic status. Invocation failures can lack a structured document. `health_check` has its own readiness schema.

Decode the [wrapper](/reference/models/mcp-tool-call-result) and tool-specific [generated result](/reference/schemas) separately. OpenAPI `/callables/…` labels organize documentation; they are not HTTP endpoints.
