Names are useful for finding possibilities. They are not stable identities for
aliases, overloads, generated declarations, or modules that use the same simple
name.

Kast makes identity a visible refinement:

<Steps>
  <Step title="Discover without overclaiming">
    ```console
    kast symbol discover --mode name --query PricePolicy --limit 25
    ```

    Discovery can search by name, source location, file structure, or bounded
    text. Its results are candidates because the query may intentionally match
    more than one declaration. Each candidate carries enough context for the
    next boundary.

    This is the place to widen or narrow a search. Do not infer exact ownership
    from display text.
  </Step>

  <Step title="Inspect one candidate">
    Select the `candidateSelector` from the intended discovery item:

    ```console
    kast symbol inspect --candidate '<candidate-selector>'
    ```

    Inspection succeeds only when that candidate still identifies one symbol
    in the same root, scope, and semantic generation. The result carries its
    `exactSelector` together with exact compiler evidence, proving the
    candidate-to-exact refinement in one operation.
  </Step>

  <Step title="Reuse an exact selector">
    ```console
    kast symbol inspect --selector '<exact-selector>'
    ```

    The evidence is compiler-grounded and tied to the selector that
    requested it. If the declaration moved with a newer generation, Kast
    closes the request instead of resolving a convenient current match.
  </Step>
</Steps>

<Tip>
  Reuse the exact selector only for current hosted symbol operations in the
  same workspace generation. Rediscover after the generation moves.
</Tip>
