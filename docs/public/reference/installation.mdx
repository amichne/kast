Use the installed `kast` CLI to update Kast and its IDEA plugin.
The normal setup path tracks the latest published development build with `--channel main`.

1. [Examine the prerequisites.](#before-you-install)
2. [Select and preview a build.](#1-install-the-selected-release)
3. [Examine the loaded Host.](#2-load-the-plugin-and-inspect-state)
4. [Ask a question in your project.](#3-establish-a-semantic-connection)

## Before you install

Use an Apple silicon Mac and a Kotlin Gradle project.
Use IntelliJ IDEA `262.*` with its bundled Kotlin plugin and Java 25 JBR.
Your project's JDK does not replace the IDEA runtime.

Install uv 0.12.9 or later. Use Python 3.12 or 3.13.
The task service can download Python and pinned dependencies on its first run.

Save your project work before an update.

## 1. Install the selected release

List the published builds:

```shell
kast versions
```

The catalog includes the five newest selectable main builds.
Each main entry shows its revision, version, and platform targets.

Preview the latest development build:

```shell
kast upgrade --channel main --dry-run
```

A successful preview returns `PLANNED`.
It admits the selected artifacts without installation changes or an IDEA restart.

Apply the selected channel:

```shell
kast upgrade --channel main
```

Kast uses a compatible reload when the running Host permits it.
If IDEA needs a normal restart, permit that restart explicitly:

```shell
kast upgrade --channel main --restart-ide
```

A necessary restart without that option returns `RESTART_REQUIRED` before installation changes.
If IDEA is already stopped, Kast can install the selected build without starting IDEA.
Read the [update outcome](/reference/management#lifecycle-result-contract) before you start another session.

### Select another IDEA installation

Supply the exact IDEA app path:

```shell
kast upgrade --channel main --idea-home "/Applications/IntelliJ IDEA.app" --restart-ide
```

The selected IDEA installation and profile determine which Host Kast updates.
An unsupported custom-profile restart rejects before installation changes.

### Pin a published build

Use one selector per command: `--channel`, `--version`, or `--commit`.
A version selector uses an exact published release version.
A commit selector uses a published main revision or its unique displayed 12-character prefix.
Copy the revision from `kast versions`.

Replace `VERSION` or `MAIN_REVISION` with your selected value:

```shell
kast upgrade --version VERSION
kast upgrade --commit MAIN_REVISION
```

Either exact selector records a pin.
An unqualified `kast upgrade` rejects a pin with `PINNED_BUILD` before installation changes.
To track development builds again, use `kast upgrade --channel main`.

## 2. Load the plugin and inspect state

Examine installation and loaded Host evidence separately:

```shell
kast status --json
```

`installedBuild` describes the files on disk. `applicationHost` describes the admitted running IDEA process and its loaded Host.
`updatePolicy` describes future selection. `unresolvedTransaction` reports unfinished installation work.
Status starts no Java process and requests no Host lifecycle action.

An installed build does not prove that IDEA loaded that Host.
A loaded Host does not prove project readiness or semantic completion.

Use [agent setup](/reference/integrations) to install the selected agent's guidance.
If an update reports `HARNESS_REFRESH_REQUIRED`, repeat that setup before a fresh agent session.

## 3. Prove a semantic connection

Start IDEA when the outcome is `INSTALLED_NOT_RUNNING`.
Start a fresh agent session in the intended Kotlin repository or worktree.
Ask [a question about your code](/start#3-ask-about-your-code).

A successful installation does not prove a semantic answer.
Keep the returned scope and completion evidence with that answer.
Use [Manage Kast](/reference/management) for update outcomes and recovery.
