`request.type` selects the semantic action for `query_symbols`. Its source, stages, output, and scope define the question for Kast to answer.

Use the installed catalog for your release. [Generated schemas](/reference/schemas) define exact fields and discriminators. They also define which choices can be combined.

<a id="choose-an-action" />

## Actions

| Action | Necessary input | Behavior |
| --- | --- | --- |
| `RUN` | `source` | Evaluate optional `steps` in order. Select `output` and optional `retention`. |
| `RESUME` | Issued output `continuation` | Show the produced output that is left. Do no semantic work. |
| `READ_RESULT` | Issued `result`. Optional `cursor` | Show retained rows without semantic work. Match the output to the retained row type. |
| `READ_SOURCE` | Issued `candidateRef` | Read an exact anchored occurrence or anonymous body. See [callbacks](/reference/callbacks#read-the-exact-anonymous-source). |

`RUN` produces a new answer. `RESUME` and `READ_RESULT` show produced evidence. They do no new semantic work.

`READ_SOURCE` uses an issued `candidateRef` to select an anchored occurrence or anonymous body. An exact symbol reference belongs to a different input family.

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "QueryStepSyntax"
    }
  }
}
```

Omitted output selects symbol names and locations. `retention: "RETAIN"` keeps the result for later reads or composition.

Every public `RUN` uses `COMPLETE_ONLY` within `COMPILER_RESOLVED_STATIC_V1`. If you supply a completion selector, Kast rejects the input.

The runner drains internal semantic pages under one grant. If proof is missing, it returns `COMPLETION_UNPROVEN` with available evidence.

## Sources

| Source | Purpose |
| --- | --- |
| `SEARCH_DECLARATIONS` | Find a simple declaration name. Match exact case by default. Ask for fuzzy matching explicitly. |
| `SEARCH_TEXT` | Find one case-sensitive ASCII identifier word. Return the exact containing declarations and match context. |
| `ALL_DECLARATIONS` | List supported Kotlin declarations, including nested ones. Order them by file path and source offset. |
| `AT_LOCATION` | Nearest containing named declaration at a workspace-relative `file` and UTF-16 `offset`. |
| `SYMBOL_REFS` | Exact references from previous results. |
| `RESULT` | Retained rows, optionally selected by their issued row IDs. |
| `IMPACT` | Trace producer values through supported Kotlin transfers and supplied reviewed models. |

By default, discovery searches the workspace and its subdirectories in `main` and `test`. Set directory, package, source-set, and kind limits to narrow seed discovery.

Those seed limits do not restrict the destinations of later relationship reads. `expansionScope` controls that distinct domain.

<Accordion title="Source-specific admission rules">
`SEARCH_DECLARATIONS` uses exact case-sensitive names by default. Explicit fuzzy matching changes which names it selects. It does not prove a unique identity.

`SEARCH_TEXT` accepts one ASCII identifier word. It starts with a letter or underscore. Kast rejects phrases, substrings, qualified literals, and regular expressions.

`ALL_DECLARATIONS` includes supported nested Kotlin declarations. It does not scan libraries directly. It keeps the admitted limits on declaration families.

`AT_LOCATION` selects the nearest containing named declaration. An offset on a call expression selects its container rather than its target.
</Accordion>

## Ordered stages

| Step | Meaning |
| --- | --- |
| `WHERE` | Filter compiler-confirmed visibility or literal `NAME`, `KIND`, or `FILE`. Comparisons: `EQUALS`, `NOT_EQUALS`, `STARTS_WITH`, `ENDS_WITH`. |
| `DISTINCT_SYMBOLS` | Keep the first row per canonical identity at this pipeline position. |
| `EXPAND_RELATION` | One hop through `REFERENCES`, `CALLERS`, `CALLEES`, `IMPLEMENTATIONS`, `INHERITORS`, `OVERRIDES`, or `TYPE_USES`. |
| `WALK` | Exhaust the reachable graph with omitted or null `maximumDepth`. An explicit depth limits reach. Breadth-first by default. |
| `TRACE` | Put this bounded investigation last. Return the seed, direct callable members for types, reference owners, implementations or overrides, and direct callers. Add one further caller layer. Select `SYMBOLS`. |
| `CONCAT` | Append `input`, keeping order and duplicates. |
| `UNION`, `INTERSECT`, `DIFFERENCE` | Compare saved symbol rows in `right` by canonical identity. Difference needs complete coverage of that input. |
| `JOIN` | `INNER` pairs named cells. `SEMI` keeps matches. `ANTI` needs complete coverage of `right` to prove absence. |
| `PROJECT_BINDING` | Select one named symbol cell before further symbol steps. |

Each stage consumes rows of the kind produced by the stage before it. A stage after composition acts on the combined stream.

`WHERE` cannot reduce native scan work already done. Apply known discovery limits and native expansion scope before that semantic work.

<a id="trace-an-interface-or-adapter" />

### TRACE topology

Put `TRACE` last and use `SYMBOLS` output. It groups results by canonical identity. It keeps relation and occurrence evidence.

Its topology is fixed. It includes the seed, reference owners, implementations or overrides, and direct callers. For type seeds, it adds direct callable members.

One further caller layer includes the owners and callers found. Imported type uses keep their own occurrence evidence, apart from ordinary code references.

Kast finds members from source and compiler evidence. It does not invent a call edge from a class to a member. It does not invent a named caller for a type.

`TRACE` supports bounded static investigations of interfaces and adapters. It does not prove a full runtime graph.

<a id="choose-the-relationship-search-domain" />

### Relationship search domains

| Scope | Meaning |
| --- | --- |
| `WORKSPACE` | Workspace expansion. Default for `EXPAND_RELATION` and for `WALK` with omitted or null `maximumDepth`. |
| `RETAINED_SEED` | Scope carried by each seed. Default for `WALK` with explicit `maximumDepth`. Acquire an `AT_LOCATION` seed for exact-file scope. |
| `SOURCE_DOMAIN` | Exact imported `sourceSets`, source policy, generated-source policy, and optional workspace-relative directory. |

If scope is omitted or `null`, Kast uses the action's default. Explicit expansion scope applies before the relation scan.

`SOURCE_DOMAIN` needs `sourcePolicy` and `generatedSources`. Its `includeSubdirectories` default is `true`.

<Accordion title="Traversal extent and completion">
An omitted or null `WALK.maximumDepth` requests the reachable graph and defaults to workspace expansion. Its evidence records `EXHAUSTIVE` extent.

An explicit depth includes nodes at that depth. It does not expand from those nodes. The evidence records `THROUGH_DEPTH` and `maximum_depth`.

A complete traversal needs complete one-hop reads at each required node. If resources run out, Kast cannot silently reduce the requested extent.
</Accordion>

<a id="choose-the-result-you-need" />

## Outputs

| Output | Evidence |
| --- | --- |
| `SYMBOLS` | Identity and kind, plus selected `NAME`, `LOCATION`, `SIGNATURE`, or bounded committed `SOURCE`. |
| `OCCURRENCES` | Relation facts and use sites, including file-scoped imports and aliases. |
| `TRAVERSAL_RECORDS` | Relation facts with hop depth. |
| `BINDING_ROWS` | Named cells from an inner join. |
| `VALUE_PATHS` | Track producer sites and transfers. Keep model use, how values changed form, terminals, and proof still needed. |
| `IMPACT_WITNESS` | Retained impact sections from a complete-only `IMPACT` run or `READ_RESULT`. |

Explicit symbol `fields: []` selects identity and kind alone. `SOURCE` adds a bounded slice of committed source.

File-scoped occurrences keep imports and aliases. They cannot act as declaration endpoints for later graph expansion.

<a id="investigate-value-impact" />

## Value impact inputs and qualifications

`IMPACT` traces exact producer calls with `KOTLIN_FORWARD_V1`. State the seeds, declarations, domain, flow, and reviewed models in its input.

| Input | Requirement |
| --- | --- |
| `seeds` | Issued `enclosing` and producer `callable` references, plus UTF-16 `start` and `end` covering the whole constructor or function call. A nested or qualified selection must resolve to that same compiler invocation. |
| `declarations` | Pair modeled callable references with identity claims. Kast checks those claims again. |
| `flow` | `KOTLIN_FORWARD_V1`. |
| `domain` | Explicit expansion scope. |
| `models` | Reviewed representation rules or rules for modeled interfaces. `[]` supplies none. |
| Optional `requestedSites` | State the enclosing identity, range, and role. An argument site also identifies its invocation, callable, and zero-based declared formal parameter index. Named-argument source order does not change that index. |

Native reads prove call and site identity. Supplied models prove what a representation means or how a modeled callable behaves.

Public requested sites and model boundary sites select native work through `enclosing`, `range`, and `role`. Kast supplies retained `executionOwner`, `valuePath`, and `callStack` evidence. These input sites do not accept those retained fields.

`IMPACT` accepts no transformation steps. `VALUE_PATHS` shows paths. `IMPACT_WITNESS` shows a section after the original investigation completes.

<Accordion title="Kotlin transfer qualifications">
Under normal completion, a final try or catch value can supply its try expression. The compiler proves that transfer. Catch fallback values keep their own producers.

Non-final expressions do not supply that result. Returns keep return transfers. Throws do not supply normal branch values.

A transfer across `finally` keeps `FINALLY_UNSUPPORTED`. Mutable or cyclic flow keeps proof still needed. So does flow that is not supported.

Strict completion needs all original paths. It needs all proof rules from the original ledger to be met. Selected preview paths cannot replace that ledger.
</Accordion>

<a id="read-retained-witnesses" />

### Retained witness sections

<Accordion title="Witness sections and requested-site states">
`READ_RESULT` supports `PRODUCERS`, `MODELS`, `NATIVE_READS`, `READ_REJECTIONS`, `FINDINGS`, and `SITE_ACCOUNTING`.

`FINDINGS` shows one compact row for each original path. It keeps producer, destination, representation, model provenance, terminal, and proof still needed.

`VALUE_PATHS` with cursor `pathOrdinal` and `maxResults: 1` expands that path. Its `pathRowId` stays attached to the original result.

A complete investigation can first return a retained preview with no rows. Use its issued result reference and row cursor to read the stored paths. An empty preview alone does not mean that no paths were found.

A full path row can exceed the default byte allowance. If `READ_RESULT` reports `RESULT_TOO_LARGE`, an explicit `budget.maxReturnedBytes` can raise the presentation allowance within the configured limits. It does no new semantic work and cannot discharge an unresolved obligation. A qualified path remains qualified after its full row is read.

| State | Meaning |
| --- | --- |
| `REACHED` | Links original paths by ordinal and row ID, keeping separate scope exits. |
| `EXCLUDED` | Keeps proven scope-exclusion witnesses. |
| `RELATIONSHIP_UNPROVEN` | Keeps identity and adds `REQUESTED_SITE_RELATIONSHIP`, preventing semantic completion. |

A requested-site identity alone does not prove a producer relationship. If its state is `RELATIONSHIP_UNPROVEN`, the run cannot reach semantic completion.

Before the ledger is final, witness reads return `RESULT_FIELD_UNAVAILABLE`. Rejection evidence uses `EVIDENCE_ONLY`. It grants no semantic replay.
</Accordion>

## Defaults and limits

Omitted or null budget fields use the default settings and ceilings. The admitted grant can lower requested values.

Set the boolean `verbose` at the root. Its default is `false`. Compact output keeps semantic limits, exact references, and recovery evidence.

[Program tracing](/reference/program-tracing) explains path evidence. [Results](/reference/responses) defines presentation. [Limits](/reference/limits) defines resource and state failures.
