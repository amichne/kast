# Product brief

## Description

Kast gives coding agents source relationships from IntelliJ IDEA's compiler analysis. Developers use those relationships to investigate Kotlin code and continue their existing tasks.

## Primary audience

Kotlin developers who already use Codex, Copilot, or Pi. The first-use path follows the release selected by the stable installer. Check the published artifact before changing prerequisites or commands. The reviewed stable release is v0.50.2 at this draft's source baseline, 96e4c4bb3d1b9185869e4f0c73e9f3d7c95bfb6a.

## Jobs to be done

1. Decide whether Kast fits the developer's project.
2. Install Kast and connect the selected agent on one page.
3. Ask a useful question about the developer's own code.

## Motivation

The first useful answer is the demonstration. Do not make a developer study value identity, retained references, completion rules, or lifecycle mechanics before asking a question. Keep those requirements in agent instructions, result evidence, and reference documentation.

## Navigation and ownership

Guides contains four pages: Overview, Set up, Examples, and Help. Keep Architecture and Reference visible and searchable. Move explanations, controlled exercises, integration management, and task contracts into those tracks without changing their URLs. The setup page owns the normal installation-to-first-result path. Agent connections covers changes to an existing connection. Use the shared deeper-reading snippet for optional links. Edit generated contracts through their generator.

## Claims and limits

Kast supplies evidence. The agent interprets it. Do not promise automatic tool selection, universal language or library support, or complete results for every question. Keep required compatibility, restart, and trust actions visible. Keep source-analysis limits with results and their reference. An unfinished query does not prove absence. Source evidence does not prove runtime execution or a successful build. Do not present main-only or developer-channel behavior as stable behavior.

## Visuals

Use the existing site components. Keep the value explorer as an optional explanation. Label authored illustrations and recorded results according to their actual evidence. A future first-use recording must identify its release and environment. Do not invent a successful transcript or present elapsed playback time as query latency.
