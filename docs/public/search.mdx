Ask your agent to use Kast to find a declaration by name. For example:
**“Use Kast to find OrderService, then show its callers.”**

The examples below show the tool inputs for direct calls or harness integration.

<Note>
  Every search uses the session workspace's saved, indexed IntelliJ state.
</Note>

| Intent | Tool |
|---|---|
| Known class-like declaration name | `kast.search_classes` |
| Known function or method name | `kast.search_functions` |
| Unknown/mixed kinds, properties or type aliases | `kast.search_declarations` |
| Compiler diagnostics for a file or directory | `kast.check_diagnostics` |
| Enumeration, returned references or ordered transformations | `kast.query_symbols` (deferred) |
| Passive host and workspace readiness | `kast.health_check` |
| Explicit read-only semantic probes | `kast.validate_workspace` |

`health_check` takes `{}` and reports the bound workspace, saved/indexed state,
and host capabilities. It does not establish that semantic answers are correct.

To validate the installation against known code, supply explicit probes:

```json
{
  "declaration": {
    "kind": "class",
    "name": "OrderService",
    "file": "services/orders/src/main/kotlin/com/example/orders/OrderService.kt"
  },
  "diagnosticPath": "services/orders/src/main/kotlin/com/example/orders/OrderService.kt"
}
```

`validate_workspace` discovers the declaration, inspects its exact identity,
reads source, and scans IDE diagnostics. A relation probe additionally accepts
`kind`, `source: {file, name}`, and `target: {file, name}`. Every stage returns
`passed`, `failed`, or `unverified` with the underlying Kast result as evidence.
Missing probes and incomplete scans stay `unverified`.

## Find your first declaration

Call `kast.search_classes` with:

```json
{"name":"OrderService"}
```

Send that input to the hosted `kast.search_classes` tool in the connected session.

Use these request rules:

- Use `function_name` with `search_functions`.
- Omit default controls for exact, case-sensitive matching under recursive directory `.`.
- Expect the default source sets to be exactly `main` and `test`.
- Use a package scope when a simple declaration name needs qualification.
- Set `"name_match":"fuzzy"` explicitly because Kast never retries fuzzily.

Each match retains its name, location, signature, completeness evidence, and
opaque `ref`.

Matching overloads remain separate.

Copy `ref` verbatim into subsequent requests. The token retains its original
scope and requires admission by the owning host. Candidate and exact references
remain distinct families; no token spelling establishes compiler authority.

Canonical equality remains internal. To collapse repeated declarations, request
an explicit `distinct_symbols` query step. The public API does not expose an
equality key.

### Search properties or mixed kinds

For a property or an unknown declaration kind, call `search_declarations`:

```json
{
  "declaration_name": "retryCount",
  "declaration_kinds": ["property"]
}
```

Omitting `declaration_kinds` includes `class`, `function`, `property`, and
`type_alias`.

Empty or duplicate selections reject.

Constructor discovery is not advertised.

## Narrow the search

A directory scope uses paths relative to the session workspace root:

```json
{
  "function_name": "submitOrder",
  "scope": {
    "relative_directory_path": "services/orders",
    "source_set_names": ["main"]
  }
}
```

A package scope instead uses semantic Kotlin package names:

```json
{
  "name": "OrderService",
  "scope": {
    "package_name": "com.example.orders",
    "include_subpackages": false
  }
}
```

Use either directory or package scope, with paths relative to the repository.
Omitting `source_set_names` selects `main` and `test`; other source sets must belong
to the imported Gradle model. Generated and library sources are excluded from
live discovery. Scope restricts discovery subjects; later relationship expansion
can reach other declarations.

Use the **Tool contracts** tab for the complete input schemas.

## Check diagnostics separately

Call `kast.check_diagnostics`:

```json
{"relative_path":"src/main/kotlin/orders/OrderService.kt"}
```

A path may name a file or directory.

- Use `.` for the workspace root.
- Omit `max_diagnostics` to return at most 100 entries.
- Use a positive limit up to 1000.
- Do not treat this request as a project build.
- Keep the host's diagnostic scope policy separate from logging detail.

## Use the result

1. Read the outer `status`, then the semantic outcome in `document`.
2. Inspect each match's `kind`, `name`, `location`, and `signature`. Keep overloads separate.
3. Retain `ref` verbatim for a follow-up query or change plan.
4. Read `failures` and any `qualification` before making a completeness claim.

[Read a response](/reference/responses) explains the result layers.

[Symbol results](/reference/symbols) explains the compiler fields.

Use [Query pipelines](/query-pipelines) for callers, implementations,
enumeration, or returned-reference input.

Query expansion returns declarations.

Use `read_relations` for individual use-site facts.

<Accordion title="Why did a search miss a saved edit?">
  - Save the file.
  - Let IDEA finish indexing.
  - Follow the typed blocker when the host is unready.
  - Repeat discovery when a reference is stale.
</Accordion>
