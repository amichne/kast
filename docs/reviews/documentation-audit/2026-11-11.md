# Documentation currentness decisions

## Scope and baseline

This remediation started at `91df506023ddfb9842dc7e34f33c802fa9ae214c`.
The earlier reconnaissance used `aa550bd1b0dff38eb492d20df0658bb62cf44512`.
The later baseline has 447 Claims, all digest-current, across 65 canonical concepts.
Neither count proves that every sentence is true.

The user accepted reviewed associations as an alternative to generated pages.
The user also selected blocking Claim checks, declaration or test citations, missing source-owner evidence, and a five-day review limit.

## Enforcement owners

- `docs/tooling/markdown/evidence-native.ts` uses locked OpenWiki `0.9.0`.
  Its assessment does not finalize pages or change verification dates.
- `docs/tooling/knowledge_check.py` combines canonical currentness, published-Claim citation checks, and review-age checks.
  `verifyKnowledgeClaims` is a required source guard and a documentation CI command.
- `docs/tooling/claim_evidence.py` requires a cited range containing a named declaration, or a test-file citation containing an executable test declaration.
  Kotlin PSI, Python AST, and the TypeScript parser supply syntax evidence.
  Comments and string contents do not become declarations.
- `docs/tooling/publication.py` rejects a review baseline more than five days older than the candidate HEAD commit timestamp.
  The comparison does not use the wall clock.
  An unchanged candidate therefore keeps the same result.

A declaration citation does not prove that its Claim follows from the declaration.
A test citation does not prove that the test ran or passed.
Currentness, syntax, source review, compiler semantics, and installed behavior remain separate evidence.

## Host refresh and remaining limits

`kast-knowledge-refresh` defaults to a read-only plan.
An explicit run creates an owned clone and worktree from fetched `origin/main`.
It uses the selected Pi or Codex host and the locked OpenWiki integration.
It retains a structured stage outcome and an unverified candidate, without automatic commits, pushes, or publication.
Final Git-scope inspection is not a sandbox and does not prove the absence of transient effects.

The command can print a daily 09:00 launchd recipe.
No schedule is installed by the runner.
Activation must wait until the command exists on the scheduled checkout.
An ephemeral cloud host needs an authorized startup invocation or a separate durable scheduler.
No background model run or scheduled host wake is claimed as observed behavior here.
