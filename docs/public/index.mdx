## The working model

The agent still decides what to investigate and what to do. Kast narrows the parts that do not need to remain guesses.

<Steps>
  <Step title="Ask a real code question">
    Start from the behavior, declaration, or relationship you care about. You do not need to know Kast's request schema first.
  </Step>
  <Step title="Resolve evidence, not just candidates">
    Kast uses the selected IntelliJ IDEA project to establish exact declarations and semantic relationships. Names and text can help discovery; they do not become compiler proof.
  </Step>
  <Step title="Carry the proof forward">
    Returned references, retained results, coverage, and limitations constrain the next operation. A later step should refine established knowledge rather than reconstruct it from prose.
  </Step>
</Steps>

<Info>
  A successful tool call is not automatically a complete semantic answer. Kast distinguishes complete, qualified, and rejected outcomes so an agent can keep useful facts without inventing certainty.
</Info>

## What gets stronger as you go

| Depth | What you know | What becomes possible |
| --- | --- | --- |
| Discover | Candidate code in a declared scope | Choose the declaration worth refining |
| Identify | Exact compiler-backed declaration identity | Reuse the issued reference instead of matching the name again |
| Relate | Confirmed callers, implementations, references, or type uses | Explain why the code matters and what a change may affect |
| Retain | Results plus their coverage and unfinished work | Compose investigations or resume bounded execution without discarding limits |
| Change | An exact admitted target and supported mutation | Apply a narrow edit and inspect its verification receipt |

This progression is the core invariant: **stronger evidence should narrow the next step, not disappear between tool calls.**

## Know the boundary

Kast does not replace the agent's judgment and does not claim arbitrary refactoring support. Its current source changes are declaration insertion and supported block-body replacement. A verified bounded edit or a clean diagnostic result is not proof of whole-project behavior.

The current installation targets Kotlin Gradle projects on Apple silicon macOS with IntelliJ IDEA `262.*`. Kast prepares the selected project when semantic work needs it and reports readiness blockers instead of returning a misleading empty answer.
