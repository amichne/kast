The Kast installation includes one plugin for Claude Code and Codex. It holds the Kast skill, a session hook, and the Kast MCP server.
`kast agent` runs your agent's own plugin commands. Kast writes no agent configuration.

## Before you start

[Install Kast](/start). Your agent must find the `kast` command on its `PATH` or in `~/.local/bin`.

<span id="2-declare-kast-in-agents-toml" />

## 1. Install the plugin

<Tabs>
  <Tab title="Claude Code">
    ```shell
    kast agent install claude
    ```

    The skill appears as `kast:kast`.
  </Tab>
  <Tab title="Codex">
    ```shell
    kast agent install codex
    ```

    Codex skips a new hook until you trust it. Run `/hooks` in a session, then review the Kast session hook.
  </Tab>
</Tabs>

The plugin applies to all your projects. Outside a Gradle project, the session hook adds nothing to the session.

Add `--without-mcp` to install only the skill and hook. Run the command again without it to add the MCP server.

Another marketplace named `kast` stops the command with `MARKETPLACE_FOREIGN`, and nothing changes. The output names the command that removes it.

<span id="3-apply-the-configuration" />

## 2. Start a new session

Start a new agent session in your project to load the plugin.

## Work with your agent

Describe your task as usual. The skill tells your agent when a Kast query gives a better answer than a text search.
The agent can read the installed CLI contract with `kast describe`.

The first explicit semantic request grants trust to the exact workspace root and prepares its Host. This applies to the CLI and to MCP.
Use Kast only in a workspace whose build code you trust. Plugin installation, the session hook, and `tools/list` do not grant trust or start a Host.
Each result applies to its stated worktree, source state, and scope.

The [MCP contract](/reference/mcp-catalog) describes the server's tools and replies. The [CLI reference](/reference/cli) describes the command forms.

<span id="refresh-the-skill-after-an-upgrade" />

## Refresh after an upgrade

An upgrade can change the plugin.

- Claude Code reads the plugin from the installation. Start a new session.
- Codex keeps a copy. Run `kast agent install codex` again, then start a new session. `kast upgrade` does not do this.

A changed hook needs a new review in Codex.

## Remove the plugin

<Tabs>
  <Tab title="Claude Code">
    ```shell
    kast agent remove claude
    ```
  </Tab>
  <Tab title="Codex">
    ```shell
    kast agent remove codex
    ```
  </Tab>
</Tabs>

`kast uninstall` does not change agent configuration. Remove the plugin first.

## Connect another agent

For an agent without a Kast plugin, export the skill and register the MCP server.

From your repository root, export the skill:

```shell
kast install skill
```

Kast writes the skill to `.agents/skills/kast`. Many agents read that directory. Keep it in Git to share it with your team.
Use `--output` to select another parent directory, and `--json` to print one structured result.

Register this stdio MCP server as your agent's documentation describes:

```shell
kast --internal-entrypoint=mcp
```

If your agent cannot find `kast`, use the absolute path that the installer printed.

`kast install skill` never overwrites an existing skill:

- An identical skill returns `ALREADY_INSTALLED` and writes nothing.
- A different or incomplete skill returns `SKILL_EXISTS` and leaves the directory unchanged.

To refresh an exported skill after an upgrade, remove it with `rm -rf .agents/skills/kast` and export it again.
Do not combine an exported skill with the plugin. Your agent would list the Kast skill twice.

Recovery: [Help](/troubleshooting).
