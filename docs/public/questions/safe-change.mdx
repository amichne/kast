The hosted writer admits one mutation intent: `add-declaration`. The other
canonical change intent shapes remain in `kast --schema`, but this endpoint
rejects them instead of widening its source-write authority.

## Run the complete lifecycle

Start with an exact selector and a complete topology snapshot for its current
workspace generation. Then keep the same endpoint open through the mutation:

<Steps>
  <Step title="Plan from complete semantic evidence">
    ```console
    kast change plan \
      --intent add-declaration \
      --target '<exact-selector>' \
      --declaration 'fun added(): String = "value"'
    ```

    `change.plan` is pure. It binds the intended declaration, source preimage,
    relation evidence, traversal evidence, diagnostics, and prior semantic
    lease into one durable plan identity.
  </Step>

  <Step title="Apply, publish, and verify the successor generation">
    ```console
    kast change apply --plan '<plan-identity>'
    ```

    A complete apply means the physical write is durable, the same workspace
    owner has published a proven newer generation, and verification has checked
    the planned semantic obligations. Success carries the verified receipt;
    there is no successful-but-unverified public state. Selectors from the
    prior generation are stale immediately.
  </Step>
</Steps>

## Recover a post-write failure

If source may have changed but Kast cannot durably issue the application
identity or verified receipt, the apply request rejects as `recovery-required`.
The live endpoint immediately withdraws mutation authority.

```console
kast change recover --plan '<plan-identity>'
```

A `PriorState` or `RolledBack` result restores a clean mutation boundary:

1. Publish a successor generation for the physical recovery.
2. Re-audit the durable journal.
3. Install fresh mutation state in the same endpoint.

You can then resolve a current selector, rebuild topology, and plan again
without restarting. Unresolved recovery remains qualified as manual recovery
required and cannot regain writer authority.

<Warning>
  Do not treat transport success, a physical file write, or a durable plan as
  verified semantic success. Only a complete `change.apply` with its verified
  receipt closes the normal lifecycle.
</Warning>

Endpoint restarts preserve durable plans, applications, receipts, topology,
and recovery evidence, but neither the normal lifecycle nor successful
recovery requires a restart.

If the target source changed outside Kast after planning, `change.apply`
rejects as `content-changed` and publishes that targeted divergence as a newer
workspace generation. Rediscover and resolve before attempting another plan.
