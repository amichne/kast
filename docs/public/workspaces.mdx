Use the `kast` command to inspect or change your installation. Use your connected agent for semantic questions about the repository.

## Inspect the installation

```shell
kast status
```

Read recorded registrations and live observations separately. A registration names the installed integration. It does not establish a live process or a ready workspace.

## Upgrade

Before an upgrade, save your work. Wait for active calls to finish, then run:

```shell
kast upgrade
```

Upgrade stops owned services and interrupts sessions. After the upgrade, restart IDEA and connected agents. Start new calls and sessions.

## Stop and reinstall

Before you stop Kast, close the selected IDEA instance. Close the affected agent connections, then run:

```shell
kast stop --json
kast reinstall --json
```

`stop` fences calls and automatic restart. It disables the coordinator and waits up to 30 seconds for recorded calls and MCP sessions. The payload, configuration, and registrations stay in place.

To force retirement of recorded tool processes, use `kast stop --force --json`. Before a signal, Kast examines PID start time, main class, and installed library digests.

If IDEA still runs, the command returns `REJECTED` with `HOST_RESTART_REQUIRED`. Quit IDEA, then repeat the command. A shutdown rejection keeps the fence and prevents payload replacement.

`reinstall` examines shutdown, installs the recorded version, starts the coordinator, and restores integrations. If coordinator activation fails, Kast restores the fence. It returns `REINSTALLATION_PENDING` with the failed stage.

Before another recovery try, examine `kast status --json`. After success, reload the agents. Kast never replays writes.

The published installer also resumes a valid shutdown from `kast stop` after installation completes. Routine installation retires the previous service before it examines the state to keep. Transient live entries and a stopped service's saved configuration do not block replacement.

If service retirement, state retention, or payload activation fails, Kast tries to restart the previous service. The result reports the recovery outcome.

When the next request needs a workspace, an existing tool session reexamines a previously unavailable or incompatible Host or plugin. After a Host update, restart IDEA to load it. Recovery still needs a compatible installed contract and readiness for the exact project before dispatch. Recovery does not replay semantic execution.

Preparation lookup history has a fixed limit. Retries can retire older terminal records while they preserve held results and their original observations. Current roots and pending work remain protected.

After Kast retires a lookup record, a lookup returns `UNKNOWN_OPERATION`. That result cannot distinguish an expired identifier from an identifier that Kast never issued.

<Accordion title="Lifecycle result contract">
  JSON stdout reports one `type`: `STOPPED`, `REINSTALLED`, `REJECTED`, or `REINSTALLATION_PENDING`. Stage observations use stderr. Rejected and pending results use exit code 1.

  The schema is `installation/share/kast/schema/management-lifecycle.schema.json`. Older payloads without fence capability reject before effects. To upgrade those payloads, use the published installer.
</Accordion>

## Force reset

<Note>
  Force reset erases installed state. Erased data has no rollback.
</Note>

```shell
kast uninstall --force --json
kast reinstall --force --json
```

Reset bypasses old ownership checks. It fences startup, records a recovery location, and moves the directory aside before it retires scoped Kast processes. Shared IDEA and Gradle processes remain under your control. If process retirement fails, Kast keeps the old contents and reports `recoveryPath`.

Force reset removes legacy `$HOME/.kast` state, historical `.kast-*` artifacts under `$HOME/.local/share`, and the public command. Stable lock files stay in place.

Force reinstall selects the latest release from the saved stable or developer channel. It installs Control and Host and repairs valid recorded connections.

Success returns `RESET_REINSTALLED`, the new version, service `generation`, and public `command`. The command path is `$XDG_CONFIG_HOME/kast` or `$HOME/.local/bin/kast`. After installation, restart IDEA and affected agents.

The public installer uses the same reset with `--force`. Developer installation requests this reset automatically. The installer examines the downloaded archives before reset.

An older selected release can use newer recovery code. The installer examines its checksum and keeps the selected installation version. `--dry-run` preserves files and registrations.

<Accordion title="Reset scope and results">
  Reset unlinks symlinks without a read of their targets. It rejects deletion of filesystem roots, HOME, and HOME's ancestors. Reset keeps process identity evidence and stops scoped processes before erasure.

  The exterior lock serializes cleanup. If process retirement fails, Kast keeps the old payload and reports `recoveryPath`. Installation starts after reset completes. Success needs a qualified payload and a ready service.

  An installation failure returns `RESET_REJECTED`. A readiness failure returns `RESET_REINSTALLATION_PENDING`.

  JSON variants are `REMOVED`, `RESET_REINSTALLED`, `RESET_REINSTALLATION_PENDING`, `RESET_RETAINED`, `RESET_RECOVERY_REQUIRED`, and `RESET_REJECTED`.
  Unsuccessful results exit with code 1. The lifecycle schema defines these variants.
</Accordion>

## Change agents

```shell
kast connect pi
kast disconnect copilot
```

Multiple agents can connect to Kast. After disconnect, restart the agent to unload its integration. See [connection recovery](/agent-harnesses#recover-an-existing-connection).

## Uninstall

```shell
kast uninstall
```

If uninstall fails, read the ownership and recovery failures before another try.

## Explicit workspace control in the hosted App Server

Hosted App Server supplies `workspace_lifecycle` to inspect, present, release, or close a selected project. Direct MCP and Tool RPC omit this tool. Before a project action, examine the installed schema and approval requirements. Disconnect, release, and close produce separate effects.
