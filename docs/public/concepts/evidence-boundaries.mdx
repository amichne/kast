Use a Kast answer only for the question its evidence supports. Start with the
[response walkthrough](/reference/responses) for field-by-field decoding; this
page explains the claims you can make afterward.

## Keep the scope in the claim

“Nothing matched” needs a scope: repository, source sets, directory or package,
name matching, and any transformations. A complete search of `main` and `test`
does not establish absence in every imported source set.

| Evidence | Supported claim |
| --- | --- |
| Complete result, no relevant item failures | The operation met its admitted completeness contract. |
| Empty complete search | No match was found within the admitted scope. |
| Qualified result | These results were established, with the attached coverage limitations. |
| Empty qualified search | No match was returned; absence is unproven. |
| Rejection | No successful semantic answer was established. |

Per-item failures remain relevant even when other items succeed. Keep them next
to the result instead of describing the entire input set as resolved.

## Distinguish identity from presentation

A candidate is discovery evidence. An exact symbol retains a compiler identity.
A source name, location, or signature string helps a person understand a result;
it cannot replace an admitted reference. Copy references unchanged and let the
runtime re-admit them. [Symbol results](/reference/symbols) shows the variants.

## Bind evidence to the observed source

Live reads retain the canonical repository root, original host incarnation,
content/model epoch, and saved committed content view. Published reads retain
published workspace evidence. Neither family can silently become the other.

A saved source edit, model change, or owner replacement may invalidate prior
references. Obtain a fresh reference through search when admission rejects a
stale value. Retrying a stale token with a rewritten name does not renew it.

## Separate verification from coverage

Scoped diagnostics answer a scoped diagnostic question; they are not a
whole-project build. A verified change receipt records the obligations discharged
for that exact change; it does not prove all future repository states.

A larger budget allows more work but cannot guarantee completeness. A timeout,
incomplete compiler observation, or uncertain effect must remain visible in its
typed outcome. For a mutation, follow [the recovery workflow](/change) before
assuming that a lost response means nothing was written.
