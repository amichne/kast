## Start from remembered text

This `SEARCH_TEXT` request illustrates current inputs. The historical recording predates text discovery.

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_TEXT",
      "word": "launchd",
      "declarationKinds": ["FUNCTION"],
      "scope": {
        "type": "DIRECTORY",
        "relativeDirectoryPath": "app-server",
        "sourceSetNames": ["main"]
      }
    },
    "output": {"type": "SYMBOLS", "fields": ["NAME", "LOCATION"]},
    "executionBudget": {"maxResults": 10}
  }
}
```

Text discovery returns the containing declaration and the line that matched. The match has a one-based line number and a UTF-16 range.

One ASCII identifier word is supported. A relation query must prove calls after discovery.

## Recorded caller walk

Call `15-caller-walk` started from `QueryPlanCompiler.exactStage`. It returned `QueryPlanCompiler.admit` at depth 1 within the requested two-hop graph.

```json
{
  "request": {
    "type": "RUN",
    "executionBudget": {"maxElapsedMs": 15000},
    "source": {
      "type": "SYMBOL_REFS",
      "symbolRefs": ["<exact function ref>"]
    },
    "steps": [
      {"type": "WALK", "relation": "CALLERS", "maximumDepth": 2}
    ],
    "output": {"type": "TRAVERSAL_RECORDS"}
  }

```

The recorded result had complete coverage and no continuation. Depth described the requested graph extent. It did not describe runtime stack depth.

## Interpretation limits

The recording is older than compact output and current complete-only execution. Its semantic continuation is historical. It is not how public `RESUME` works today.

New investigations need current handles and installed schemas. [Staleness](/reference/staleness) defines reuse, and [Program tracing](/reference/program-tracing) defines source-path claims.
