`tools.schema.json` owns the shared input definitions and metadata. It also owns the defaults used to normalize input. Each tool's `parameters.json` is generated from it.

Direct MCP exposes `health_check`. Hosted App Server exposes `workspace_lifecycle` for separate project actions.

The [generated OpenAPI document](https://raw.githubusercontent.com/amichne/kast/main/docs/public/reference/callables.openapi.json) links inputs and tool results. It also links transport wrappers and model definitions.

Its `/callables/...` labels identify documentation sections. They are not HTTP endpoints.

## What a schema check proves

A tag selects the fields for an action. Required default values and type tags stay explicit in encoded output.

Passing a schema check proves the shape of the data. It does not prove that the workspace is ready. Check current identity and semantic completion on their own. Check authority to change source too.

Use [Query forms](/reference/api) to choose which inputs belong together. [Lifecycles](/reference/lifecycles) names each next owner.

## Examples and replies

Some samples are valid inputs. Others use inputs that Kast rejects. Their references are placeholders. They carry no live workspace authority.

Examples do not prove that a native tool ran. They do not report current compiler facts. A live response belongs to the source and workspace that the query examined.
