The public management verbs are `install`, `status`, `stop`, `versions`, `upgrade`, and `uninstall`.
Semantic commands use the same installed managed runtime across CLI, MCP, and tool RPC.
See [installation limits](/reference/installation) for the current implementation and native acceptance status.

<a id="inspect-the-installation" />

## 1. Check the installation

```shell
kast status --json
kast status --workspace /absolute/project/path --json
kast status --all --json
```

The default scope is the current workspace. `--workspace` selects an exact workspace; `--all` selects all recorded workspaces.
These selectors are mutually exclusive. Use `--all` outside a project to inspect the whole installation.
Status reads local evidence without starting Java, granting trust, repairing state, or contacting release servers.

| Field | Meaning |
| --- | --- |
| `installedBuild` | Recorded build identity on disk. |
| `product` | Exact installed product composition. |
| `updatePolicy` | Channel or pinned-build policy. |
| `unresolvedTransaction` | Unfinished installation work. |
| `workspaces` | Scoped workspace records, runtime digests, and Host observations. |
| `applicationHost` | For a managed product, unavailable with `WORKSPACE_SCOPED`; inspect `workspaces` instead. |

Observations have a `state` of `VERIFIED` or `UNAVAILABLE`, with a `value` or `reason`.
An unavailable observation is not proof of absence. A loaded Host is not proof of semantic readiness.

<a id="upgrade" />

## 2. Update

Save work in your agent before changing the installation. Preview selection, then apply it:

```shell
kast versions
kast upgrade --channel preview --dry-run
kast upgrade --channel preview --json
```

Use `stable` for stable builds. `main` is a compatibility alias for `preview`.
An [exact version or commit](/reference/installation#pin-a-published-build) creates a pin.
An unqualified upgrade follows the recorded channel, but rejects a pin with `PINNED_BUILD`.

```shell
kast upgrade --repair --json
```

Repair selects the exact installed product. It does not resolve a newer channel head or replace only one component.
The installer composes immutable vendor bytes with exact components and uses the existing replacement journal.
Running owned work can end during replacement. A subsequent explicit request prepares the selected workspace generation.

## 3. Read the result

Keep the structured result, its failure code, and any recovery evidence.
Progress belongs on stderr; `--json` selects structured stdout.
A completed installation is not a claim that a workspace imported successfully or that a query completed.
Read `kast status --all --json`, then run one useful query in the intended workspace.

If the result reports `HARNESS_REFRESH_REQUIRED`, repeat your [agent installation command](/reference/integrations#refresh-guidance-after-a-core-change).
Keep `--mcp` if you selected MCP. Start a fresh agent session.
Do not replay an interrupted source change: inspect source and its [change receipt](/reference/change#read-the-receipt) first.

## 4. Resolve unfinished recovery

Use this after a recovery-required result or a nonempty `unresolvedTransaction` observation.

1. Keep the failure output and the selected product identity.
2. Correct the reported permission, ownership, or storage problem.
3. Repeat the management operation and inspect its result before another selection.

Recovery uses the existing transaction record to finish or undo the selected composition.
Unknown or damaged records fail closed. Do not delete journals or mix component archives to bypass admission.
Restored files do not prove that a Host runs again. Status and a useful query establish separate facts.

## Stop workspace Hosts

```shell
kast stop --json
kast stop --workspace /absolute/project/path --json
kast stop --all --json
```

Stop is temporary and scoped. The next explicit semantic request can restart the Host.
There is no persistent disable or resume command. A passive hook does not restart it.
Stopping Kast does not authorize termination of unrelated IDEA or Gradle processes.
An active lease can reject a stop as busy; preserve the result and retry only after the active work settles.

## State for removed workspaces

Request admission and upgrade retirement can reclaim private state for a workspace root that no longer exists.
Cleanup requires the exact retired Host generation, no active query lease, and settled `.kast` evidence.
It does not delete a repository or an external Gradle home.
An interrupted deletion keeps an exterior `.removing-ID.json` receipt for recovery. Do not remove that receipt manually.
These are source-level rules; native cleanup qualification remains pending.

<span id="uninstall" />

## Remove Kast

```shell
kast uninstall
```

The removal contract covers owned installation bytes, workspace state, and agent registrations after process retirement.
Repositories, external Gradle homes, and foreign registrations remain outside that scope.
If ownership or retirement cannot be proved, keep the recovery output instead of deleting paths manually.
Native removal acceptance remains part of the qualification work; this guide is not evidence that it passed.
