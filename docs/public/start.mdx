Get one Kotlin repository answering semantic questions through the included Codex
integration. You need macOS on Apple silicon, an on-disk Kotlin Gradle repository,
IntelliJ IDEA in the `262` release line with its bundled Kotlin plugin and Java 25
JBR, and a `codex` executable on `PATH`.

<Steps>
  <Step title="Install the matched release">
    Run:

    ```shell
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh)"
    ```

    The installer verifies and installs Kast and its IDEA plugin. It does not
    install IDEA. If prompted, add `~/.local/bin` to `PATH`.
  </Step>
  <Step title="Prepare IDEA">
    Restart IDEA to load the plugin, open your repository, and wait for Gradle
    import and indexing to finish. Save edited files. Reads use the existing
    saved project; they do not start an import or isolated worker for you.
  </Step>
  <Step title="Connect from the repository root">
    ```console
    cd /path/to/kotlin-repository
    kast codex
    ```

    This enrolls the workspace, qualifies the installed catalog, and starts the
    included integration. A separate App Server enable command is unnecessary.
  </Step>
  <Step title="Ask for a declaration">
    Ask the agent to find a class or function that exists in your project. It
    should use `kast.search_classes` or `kast.search_functions`. Expand the tool
    result and check its semantic status, matches, and `symbol_ref` values.

    Continue with [Search declarations](/search) or [Read a response](/reference/responses).
  </Step>
</Steps>

## Setup alternatives

<AccordionGroup>
  <Accordion title="Choose among multiple IDEA installations">
    ```shell
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh)" \
      -- --idea-home "/Applications/IntelliJ IDEA.app"
    ```

    The build baseline is IDEA `262.10315.125` and Kotlin plugin
    `262.10315.125-IJ`. Other `262` builds are admitted by policy; recorded native
    acceptance is limited to the baseline. See [Compatibility](/reference/compatibility).
  </Accordion>
  <Accordion title="Connect Codex Desktop">
    Quit any running Desktop instance, then run `kast codex desktop` from the
    repository root. Kast launches Desktop with its installed App Server façade;
    the façade connects to the same persistent broker as the terminal integration.
    Closing Desktop leaves the broker running. Full Desktop UI compatibility
    remains unqualified in the [compatibility record](https://github.com/amichne/kast/blob/main/app-server/docs/compatibility.md).
  </Accordion>
  <Accordion title="Use an explicit Codex executable or another harness">
    Set `CODEX_EXECUTABLE` to an absolute executable path if `codex` is not on
    `PATH`. For another agent host, consume `kast --schema` as described in the
    [harness contract](/agent-harnesses).
  </Accordion>
  <Accordion title="Uninstall Kast">
    ```shell
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/amichne/kast/main/install.sh)" \
      -- uninstall
    ```

    Uninstall removes Kast-owned commands, installations, runtime state,
    configuration, and services. Repositories and unrelated JetBrains state remain.
  </Accordion>
</AccordionGroup>

If tools are absent or the first request rejects, use [Troubleshooting](/troubleshooting).
For source changes, complete the separate broker-trust step in [Change source](/change).
