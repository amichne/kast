Choose an action, source, steps, and output for `query_symbols`. It can run a query, present produced output, read saved rows, or read anchored source. Use the [generated schema](/reference/schemas) for exact variants. For agent prompts, use [Find and trace code](/search).

## Choose an action

The action selects the operation and its necessary input:

| Action | Necessary input | Behavior |
| --- | --- | --- |
| `RUN` | `source` | Evaluate optional `steps` in order. Select `output` and optional `retention`. |
| `RESUME` | Issued output `continuation` | Present remaining produced output without semantic execution. |
| `READ_RESULT` | Issued `result`. Optional `cursor` | Present retained rows without semantic execution. Output must match the retained row type. |
| `READ_SOURCE` | Issued `candidateRef` | Read an exact anchored occurrence or anonymous body. See [callbacks](/reference/callbacks#read-the-exact-anonymous-source). |

```json
{
  "request": {
    "type": "RUN",
    "source": {
      "type": "SEARCH_DECLARATIONS",
      "declarationName": "QueryStepSyntax"
    }
  }
}
```

Without an output, the query returns symbol name and location. To save results for later use, set `retention: "RETAIN"`. Pass issued handles unchanged. Replace placeholders with current references.

Every `RUN` uses complete-only execution within `COMPILER_RESOLVED_STATIC_V1`. The runner drains semantic pages under one grant. Unsupported or unproven answers return typed rejections. `RUN` accepts no completion selector. Output is compact by default.

## Choose an input

Choose the source that matches the evidence you already hold:

| Source | Purpose |
| --- | --- |
| `SEARCH_DECLARATIONS` | Simple declaration name. Exact, case-sensitive matching by default. Fuzzy matching is explicit. |
| `SEARCH_TEXT` | One case-sensitive ASCII identifier word. Exact containing declarations and match context. |
| `ALL_DECLARATIONS` | Supported Kotlin declarations, including nested declarations, ordered by file path and source offset. |
| `AT_LOCATION` | Nearest containing named declaration at a workspace-relative `file` and UTF-16 `offset`. |
| `SYMBOL_REFS` | Exact references from previous results. |
| `RESULT` | Retained rows, optionally selected by their issued row IDs. |
| `IMPACT` | Producer values through supported Kotlin transfers and supplied reviewed models. |

Discovery accepts a directory or package scope. By default, it searches the workspace recursively in `main` and `test`. Set relationship destinations separately from discovery scope.

For `SEARCH_TEXT`, supply a letter or underscore, then letters, digits, or underscores. Kast rejects phrases, substrings, qualified literals, and regular expressions. A text match explains discovery. A relation query establishes calls.

`ALL_DECLARATIONS` enumerates supported Kotlin classes, functions, properties, and type aliases. It does not support direct library enumeration. Before a completeness claim, examine the restrictions and progress.

## Apply only the steps you need

Steps run in their supplied order. Choose the smallest sequence that answers your question:

| Step | Meaning |
| --- | --- |
| `WHERE` | Filter compiler-confirmed visibility or literal `NAME`, `KIND`, or `FILE`. Comparisons: `EQUALS`, `NOT_EQUALS`, `STARTS_WITH`, `ENDS_WITH`. |
| `DISTINCT_SYMBOLS` | Keep the first row per canonical identity at this pipeline position. |
| `EXPAND_RELATION` | One hop through `REFERENCES`, `CALLERS`, `CALLEES`, `IMPLEMENTATIONS`, `INHERITORS`, `OVERRIDES`, or `TYPE_USES`. |
| `WALK` | Exhaust the reachable graph with omitted or null `maximumDepth`. An explicit depth limits reach. Breadth-first by default. |
| `TRACE` | Terminal bounded investigation returning the seed, its direct callable members, reference owners, implementations or overrides, direct callers, and one further caller layer. Select `SYMBOLS`. |
| `CONCAT` | Append `input`, preserving order and duplicates. |
| `UNION`, `INTERSECT`, `DIFFERENCE` | Compare saved symbol rows in `right` by canonical identity. Difference needs complete coverage of that input. |
| `JOIN` | `INNER` pairs named cells. `SEMI` keeps matches. `ANTI` needs complete coverage of `right` to establish absence. |
| `PROJECT_BINDING` | Select one named symbol cell before further symbol steps. |

Steps after composition apply to the combined stream. Queries do not support arbitrary-field joins or a general-purpose `MAP`. See [Combine query results](/query-pipelines) for set and join examples.

### Trace an interface or adapter

After you select an exact interface or method, use `steps: [{"type": "TRACE"}]` with `SYMBOLS` output. `TRACE` must be terminal. It groups facts by canonical symbol identity and keeps each compiler relation connection and original reference observation.

Imports, type references, and code references keep distinct evidence. Their combined count does not represent a call count.

For a class or interface seed, source inventory and compiler refinement establish direct callable members. The fixed investigation includes:

- Implementations or overrides.
- Callers of callable seeds and discovered callable targets.
- Reference owners.
- One further caller layer from discovered owners and callers.

Member calls through inferred receiver types remain eligible. Members keep exact declaration references. Source inspection establishes membership without a serialized class-to-member relation edge. A type seed does not gain an invented named caller edge.

The trace supplies bounded static evidence for interface and adapter questions. It does not establish an exhaustive runtime graph. To constrain native expansion, supply `expansionScope` on `TRACE`. Each component keeps its domain and incomplete coverage in the answer.

### Choose the relationship search domain

Set `expansionScope` to control native search before enumeration. A later `WHERE` filters returned rows without a reduction in native search work.

| Scope | Meaning |
| --- | --- |
| `WORKSPACE` | Workspace expansion. Default for `EXPAND_RELATION` and for `WALK` with omitted or null `maximumDepth`. |
| `RETAINED_SEED` | Scope carried by each seed. Default for `WALK` with explicit `maximumDepth`. Acquire an `AT_LOCATION` seed for exact-file scope. |
| `SOURCE_DOMAIN` | Exact imported `sourceSets`, source policy, generated-source policy, and optional workspace-relative directory. |

Omission or `null` selects the operation's default. For `SOURCE_DOMAIN`, supply `sourcePolicy` and `generatedSources`. `includeSubdirectories` defaults to `true`. For `IMPACT.domain`, supply an explicit scope.

Observations keep requested and effective domains, coverage, and proven exclusions. [Callback observations](/reference/callbacks) keep anonymous ownership. Excluded callbacks remain outside the named edges.

Without `maximumDepth`, or with a null depth, `WALK` exhausts the reachable relation graph in its declared expansion domain. It defaults to workspace expansion. The result carries `extent: {"type": "EXHAUSTIVE"}`.

An explicit `maximumDepth` includes nodes at that depth but does not expand them. The evidence carries `extent: {"type": "THROUGH_DEPTH", "maximum_depth": N}`. Complete coverage needs complete one-hop reads at every necessary node.

Result, work, and time limits can pause internal evaluation without a change to the original extent. Terminal incomplete reads leave the walk incomplete. Explicit expansion policies remain part of the completion question.

## Choose the result you need

The output selects the evidence shape. Match it to the pipeline's row type:

| Output | Evidence |
| --- | --- |
| `SYMBOLS` | Identity and kind, plus selected `NAME`, `LOCATION`, `SIGNATURE`, or bounded committed `SOURCE`. |
| `OCCURRENCES` | Relation facts and use sites, including file-scoped imports and aliases. |
| `TRAVERSAL_RECORDS` | Relation facts with hop depth. |
| `BINDING_ROWS` | Named cells from an inner join. |
| `VALUE_PATHS` | Producer sites, transfers, model applications, representation history, terminals, and obligations. |
| `IMPACT_WITNESS` | Retained impact sections from a complete-only `IMPACT` run or `READ_RESULT`. |

For symbols, explicit `fields: []` requests only the necessary identity and kind. File-scoped occurrences identify use sites. Walks cannot expand them as declaration endpoints.

## Investigate value impact

`KOTLIN_FORWARD_V1` tracks supported Kotlin value transfers. A final try or catch value can supply the enclosing try expression. This transfer needs a compiler-confirmed value type and a try without `finally`.

Each transfer keeps the enclosing try range, branch range, `TRY_BODY` or indexed `CATCH_BODY` alternative, and `NORMAL_COMPLETION` condition. Catch fallback values have their own producers. The paths describe static provenance. Runtime path feasibility needs separate evidence.

Non-final branch expressions do not supply the try result. Explicit returns remain return transfers. Throws do not produce normal branch results. A transfer across a try with `finally`, including an explicit return, keeps `FINALLY_UNSUPPORTED`. Keep that obligation and the independent qualifications with partial paths.

For `IMPACT`, supply `seeds`, `declarations`, `domain`, `flow`, and `models`. Omit transformation steps. Select `VALUE_PATHS` for paths or `IMPACT_WITNESS` for a section from the completed investigation. The fixed `COMPLETE_ONLY` policy applies to both. To inspect the result later, save it with retention.

| Input | Requirement |
| --- | --- |
| `seeds` | Issued `enclosing` and producer `callable` references, plus UTF-16 `start` and `end` covering the whole invocation. |
| `declarations` | Modeled callable references paired with identity claims for fresh revalidation. |
| `flow` | `KOTLIN_FORWARD_V1`. |
| `domain` | Explicit expansion scope. |
| `models` | Reviewed representation rules or rules for modeled interfaces. `[]` supplies none. |
| Optional `requestedSites` | Enclosing identity, range, and role. Argument sites also identify invocation, callable, and formal parameter index. |

Native reads establish invocation and site identity. Supplied models define the meaning of representations and modeled interfaces. Unsupported transfers, rejected reads, and unresolved obligations keep their qualifications.

If a work limit stops the run, completion rejects. Kast can keep empty `VALUE_PATHS` with `EVIDENCE_ONLY` accounting. Before ledger finalization, witness reads return `RESULT_FIELD_UNAVAILABLE`. Saved reads preserve the original qualifications and historical checkpoint. They do no further semantic work.

Strict completion needs every original path and discharged obligations from the original ledger. Missing evidence, incomplete path selection, or unresolved obligations returns `INVESTIGATION_UNPROVEN` with details for that case. Budget rejection keeps original accounting when storage permits it. Cyclic path expansion and mutable or unsupported native flow remain unproven.

### Read retained witnesses

To inspect an `IMPACT_WITNESS`, use `READ_RESULT` with a section:

- `PRODUCERS`
- `MODELS`
- `NATIVE_READS`
- `READ_REJECTIONS`
- `FINDINGS`
- `SITE_ACCOUNTING`

`FINDINGS` returns one compact row per original path. Each row contains producer, destination, representation, model provenance, terminal, and obligations. To expand the evidence, select `VALUE_PATHS` with cursor `pathOrdinal` and `executionBudget.maxResults: 1`. The row keeps `pathRowId`.

`SITE_ACCOUNTING` returns requested sites in original order. Each site keeps its admission grants and observed work:

| State | Meaning |
| --- | --- |
| `REACHED` | Links original paths by ordinal and row ID, preserving separate scope exits. |
| `EXCLUDED` | Keeps proven scope-exclusion witnesses. |
| `RELATIONSHIP_UNPROVEN` | Preserves identity and adds `REQUESTED_SITE_RELATIONSHIP`, preventing semantic completion. |

Site identity alone does not establish a producer relationship. Pages of saved witnesses keep unresolved obligations without more semantic reads. `EVIDENCE_ONLY` does not establish a completed investigation.

## Defaults and limits

If you omit a budget, Kast uses configured defaults and ceilings. Omission does not permit unlimited execution. A budget does not change the requested scope or output shape.

Every public tool accepts a root-level boolean `verbose`. Omission or `false` selects compact output and keeps semantic limitations. Use [Results](/reference/responses) to interpret continuation, coverage, and recovery.
