`kast.query_symbols` handles ordered pipelines. This example filters functions before finding their callers:

```json
{
  "source": {
    "type": "all_declarations",
    "declaration_kinds": ["function"],
    "scope": null
  },
  "steps": [
    {"type":"filter_visibility","visibilities":["public"]},
    {"type":"expand_relation","relation":"callers"}
  ],
  "return_fields": ["name","location","signature"]
}
```

Sources are `search_declarations`, `all_declarations` and `symbol_refs`. Steps are `filter_visibility`, `expand_relation` and `distinct_symbols`. Their order is meaningful: filtering before expansion selects callers of public functions; filtering after expansion selects public callers. Discovery sources deduplicate canonical symbols after compiler refinement. Kast preserves the order of explicit steps; use `distinct_symbols` to deduplicate downstream results. Diagnostics are a separate tool.

`steps: null` and `steps: []` both mean no transformations. `return_fields: null` selects name and location; `return_fields: []` requests mandatory identity and kind only. Duplicate projection fields reject.

To reuse a result, copy its `symbol_ref` verbatim into `source: {"type":"symbol_refs","symbol_refs":["<returned token>"]}`. Schema admission does not authenticate a token. The original owner re-admits its workspace, lifetime, epoch and scope. Do not construct or shorten references. Use `read_relations` for occurrence-oriented relation facts, including use-site locations; query expansion returns related declaration symbols.


## Continue an ordered pipeline

Omit `continuation` or use `null` to start. If a qualified result returns a
non-null `continuation`, repeat the same source, steps, and return fields with
that token. Append the returned page in order. The checkpoint retains unfinished
relation expansion, pending output and each distinct stage's seen identities;
resuming does not rerun an already emitted prefix.

`distinct_symbols` preserves the first occurrence of each canonical symbol at
that stage, including the connections carried by that occurrence. Later
occurrences do not add connections to an earlier result. Use `read_relations`
when you need occurrence coverage rather than distinct declarations.

A null continuation means there is no resumable suffix. Read `terminal_reason`:

| Reason | Meaning |
| --- | --- |
| `upstream-incomplete` | A provider or discovery stage retained incomplete coverage without resumable state. |
| `output-item-too-large` | One indivisible projected item or failure exceeds the query execution output budget. |
| `checkpoint-capacity-exceeded` | The unfinished state exceeds the configured checkpoint capacity. |
| `no-progress` | The execution could not prove a progressing checkpoint. |

The transport separately checks actual encoded response bytes. If no response
prefix fits, the request rejects with `RESULT_TOO_LARGE` instead of returning a
qualified page with a terminal reason.

A token belongs to one project, source snapshot and exact query. Changed queries
reject; expired, evicted or stale checkpoints reject. Rediscover after source or
model changes. Tokens are opaque and cannot be reconstructed. The
[read-limit settings](https://github.com/amichne/kast/blob/main/docs/hosted-read-configuration.md)
include checkpoint bytes, store entries, aggregate bytes and lifetime.

Read qualification and item failures on every page. For a `query_symbols`
`expand_relation` step, source-set restrictions select discovery subjects and do
not restrict expansion destinations. Specialist `read_relations` and
`traverse_relations` retain the exact subject selector's admitted scope. An incomplete
upstream result remains incomplete after its buffered output has drained.

## Traverse a large graph

`traverse_relations` exposes `traversal.run`. Include
`"strategy": {"type": "breadth_first"}` in tool requests; the direct CLI decoder
also supplies this strategy when omitted. It finishes a node's resumable relation
before moving to the next node. Select
`bounded_fan_out` with `maximumEdgesPerNode` to visit deeper nodes after at most
that many returned edges per node. This deliberately retains incomplete coverage
for truncated expansions; it does not establish absence in omitted subtrees.

Traversal pages expose cumulative `progress`: `checkpointSequence`, `totalReads`,
`totalEdges` and `maximumDepthReached`. A resumable page must advance its
checkpoint. `no-progress` is terminal. Operational time budgets renew per request;
the subject, relation, scope, strategy and maximum depth remain bound to the
continuation. Restart traversal after upgrading from a token format that lacks
these progress and strategy witnesses.

Use [Symbol results](/reference/symbols) to distinguish related declarations from
occurrence-oriented `connections`. Use [Read a response](/reference/responses)
before interpreting an empty pipeline result.

Elapsed time is an observation, while a read's time allowance is an admitted
grant. If scheduling or provider work overruns that grant, traversal retains the
actual elapsed time and proven facts, stops further reads, and qualifies the
page with `time-limit-reached`. It resumes only when unfinished work remains;
an exhausted overrun is terminal. An over-budget page cannot claim completion.

## Keep semantic bounds separate from page budgets

`execution_budget` grants elapsed time, provider work, returned results and
encoded bytes for one request. A continuation can request a larger grant without
changing the semantic query. Relation `limit`, traversal `maximumResults`, and
source `entityLimit` bound returned page capacity; traversal `maximumDepth` and
`strategy` define the requested exploration and remain bound to its continuation.
A larger page grant does not increase depth or erase a provider omission.

`source_read` selects a source `region` and an `entities` projection separately.
For `entities.type: "matching"`, `containment: "direct"` considers direct children;
`containment: "descendants"` also walks nested elements in that region. The
`filters` choose declarations, parameters, calls or references. This source
structure choice is separate from recursive directory/package discovery.

A relation read preserves individual occurrences, including multiple call sites
between the same declarations. Query expansion returns declarations and retains
its connection evidence; `distinct_symbols` changes declaration cardinality.
Traversal reports bounded reachability with its depth, scope, strategy and
coverage qualifications. It does not guarantee which edits will break callers or
which tests must run.
