Does the returned email draft contain the customer that `createCustomer` produced, or a different customer?
The declared type alone cannot answer this question. Both customers have the type `Customer`.

This is an authored source illustration, not a live Kast result or a record of execution.

## Read the source path

```kotlin
data class Signup(val name: String?)
data class Customer(val name: String?)
data class WelcomeEmail(val recipient: Customer)

fun Signup.createCustomer(): Customer =
    Customer(name = name)
fun Signup.draftWelcomeEmail(): WelcomeEmail =
    WelcomeEmail(recipient = createCustomer())
fun prepareEmails(signups: List<Signup>): List<WelcomeEmail> =
    signups.map { signup ->
        signup.draftWelcomeEmail()
    }
```

`createCustomer` returns a customer. `draftWelcomeEmail` puts that result in the draft's `recipient` field.
The callback passed to `map` returns the draft. A separate reviewed rule connects that callback result to a possible output list element.

The customer remains inside the draft. It does not become the draft or the list.
This source path does not prove that the list contains an element at runtime. For example, the input list can be empty.

## Try three changes

- **Change one line:** the list still holds email drafts, but a new expression creates a different customer as the recipient.
  The separate call inside `draftWelcomeEmail` remains in source; this list no longer uses it.
- **Find the other use:** one call supplies an email draft's recipient; the other supplies a customer directly to a list.
  These are separate call contexts, not one runtime object splitting in two.
- **Remove one rule:** the code stays the same. Without the reviewed rule for `map`, the output-element connection is not established.
  That does not prove that no connection exists.

A search for `Customer` finds text in all these examples. The connections explain why the answers differ.
