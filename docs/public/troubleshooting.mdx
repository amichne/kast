Start with the reported result. Select the failing boundary before changing
runtime state. For response field names, see [Read a response](/reference/responses).

## Choose the next action

| Symptom | First action |
| --- | --- |
| Tools are missing | Check `kast app-server status` and the selected catalog. Confirm `KAST_ENABLE_APP_SERVER` is enabled. |
| Outer `status: rejected` | Preserve `diagnostic.boundary` and `diagnostic.reason`; collect status below. |
| The document rejects | Follow its finite reason. Open the intended IDEA project or correct the named input as appropriate. |
| The answer is qualified | Read limitations and item failures. Narrow scope or relation expansion before increasing bounds. |
| A reference is stale | Search again and reuse the new token unchanged. |
| A change response is lost or uncertain | Keep the plan ID and durable records; follow [Change recovery](/change#recover-an-interrupted-change). |

## Collect status from the same repository

```console
cd /path/to/kotlin-repository
kast
kast app-server status
```

Bare `kast` is passive: it does not start, repair, or synchronize the runtime.
Keep its product version, semantic authority and repository-root observation.
Run `kast ide status` to inspect the existing project endpoint. App Server status adds exact paths for
`serviceLog`, `launchEnvironment`, `savedConfiguration`, and `workspaceRegistry`.

If startup itself fails, `kast codex` writes a finite reason to stderr.
`KAST_DEBUG=1` enables bounded launch-stage output alongside the service log.

## Resolve the common boundaries

<AccordionGroup>
  <Accordion title="The Codex integration cannot start">
    Verify `kast` and `codex` in the launching environment and run from the
    intended Kotlin Gradle root. If set, `CODEX_EXECUTABLE` must be absolute and
    executable. `KAST_ENABLE_APP_SERVER` must be `0` or `1`.

    Validate `KAST_APP_SERVER_TOOLS` against `kast --schema`: it must contain
    exact, non-empty, unique names. Recreate an obsolete catalog using the
    matched broker and executable. Do not bypass admission with handwritten
    definitions. See [Harness configuration](/agent-harnesses#configuration-and-migration).
  </Accordion>
  <Accordion title="The IDE host is unavailable or source is unready">
    Open the exact repository in the compatible IDEA installation, ensure the
    Kast plugin is loaded, finish import and indexing, and save edited files.
    Search does not open a project or run an import as a hidden prerequisite.
    Follow the reported host or source reason if readiness still rejects.
  </Accordion>
  <Accordion title="A search is incomplete">
    Inspect `qualification.limitations` and `failures[]`. A smaller directory,
    explicit source set, or narrower discovery before expansion can reduce work.
    Change a bound only through the admitted configuration or request schema;
    increasing it does not guarantee complete coverage.
  </Accordion>
  <Accordion title="The broker reports WORKSPACE_RECOVERY_REQUIRED">
    The workspace is blocked, including recovery calls. Replace the broker while
    retaining its invocation journal and thread store, then request fresh
    exact-plan recovery approval. Retain the IDE's durable change records.
    Replacement does not undo an effect or permit replay of an attempted plan.
    Follow the [change workflow](/change#recover-an-interrupted-change).
  </Accordion>
</AccordionGroup>

## Advanced runtime maintenance

These controls concern the installation-owned broker. IDEA owns the project,
Gradle import and semantic index lifecycle.

<AccordionGroup>
  <Accordion title="Repair installation-owned broker state">
    `kast codex` already recovers stale or malformed owned readiness as part of
    ordinary launch. Only use the following reset when the diagnosed problem
    calls for discarding owned state:

    ```console
    kast app-server repair --destructive
    ```

    This retires the active installation's launchd label, deletes its runtime,
    cache, broker and workspace-registry state, then re-enrolls the workspace and
    starts clean. It discards broker invocation evidence; it does not rebuild IDEA indexes.
    Do not use it as recovery for an uncertain source change whose records must
    be retained. It does not follow symlinks inside the owned state tree.
  </Accordion>
  <Accordion title="A change store rejects">
    Keep the complete `HOST_REJECTED.detail` value. Database admission, plan
    storage, receipt storage and plan lookup are distinct stages. `CORRUPT_RECORD`
    and `VERSION_UNSUPPORTED` are preserved rather than reported as generic I/O.
    Retain the durable records and the exact plan identity when investigating.
  </Accordion>
  <Accordion title="A retired start or stop command rejects">
    Kast no longer launches a second IntelliJ workspace. Open the repository in
    IDEA with the Kast plugin, finish import and indexing, save edited files,
    and inspect `kast ide status`. Configure IDEA's own memory and Gradle settings
    through that host when diagnosing an import or indexing problem.
  </Accordion>
</AccordionGroup>

## Report a reproducible defect

Include the Kast version and source revision; observed macOS architecture, IDEA,
Kotlin plugin and JBR versions; outer diagnostic; semantic status and finite
reasons; and the passive status report. Add a minimal reproduction. Remove host
paths or source your organization treats as sensitive before sharing.

Broker activity records contain bounded identities and completion states rather
than tool arguments or source. Apply your host's retention policy to trace files.
Report security issues through [private vulnerability reporting](https://github.com/amichne/kast/security/advisories/new).
