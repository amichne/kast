Kast exposes a live, one-hop compiler relation through `relation.read` and a
bounded multi-hop graph workflow through `topology.build` and `traversal.run`.
Both retain the exact selector and workspace generation that admitted the
question.

## Publish before traversing

<Steps>
  <Step title="Resolve an exact starting symbol">
    Use `kast symbol discover`, then `kast symbol inspect --candidate`, to
    obtain an exact, generation-bound selector and compiler evidence.
  </Step>

  <Step title="Read one compiler-confirmed hop">
    ```console
    kast relation read \
      --selector '<exact-selector>' \
      --relation callers \
      --limit 50
    ```

    Use the direct read for current-generation references, callers, callees,
    implementations, inheritors, overrides, or type uses. Complete and
    qualified results preserve compiler provenance and explicit coverage.
  </Step>

  <Step title="Build complete topology">
    ```console
    kast topology build
    ```

    The endpoint enumerates the admitted source roots, extracts semantic
    topology through IntelliJ, and publishes a durable snapshot only when the
    current generation is still valid. An eligible unchanged snapshot is
    reused instead of extracted again.
  </Step>

  <Step title="Traverse with explicit bounds">
    ```console
    kast traversal run \
      --selector '<exact-selector>' \
      --relation references \
      --maximum-depth 3 \
      --maximum-results 50
    ```

    Traversal reads only an eligible durable snapshot; it starts no hidden
    compiler work.

    The result retains:

    - Depth, result, work, time, and byte limits.
    - Deduplicated `nodes`, `edges`, and `proofs` tables.

    Fetch full signatures only when needed through `symbol_inspect`, the façade
    over `symbol.inspect`.
  </Step>
</Steps>

## Follow a workspace generation

**Bottom line:** snapshots and selectors belong to one semantic generation.

After a successful hosted apply:

- The same endpoint publishes a newer generation.
- Prior selectors and snapshots become stale.
- Resolve a fresh selector before traversing again.

No IntelliJ restart is required.

A cold Project restart always advances the semantic generation because layout
metadata cannot prove closed-Project source stability.

After reopening:

1. Run `kast topology build`.
2. Kast verifies the current candidates.
3. An unchanged durable snapshot reports `reused` and binds to the new
   generation.

Selectors from before the restart remain stale.

<Info>
  A complete traversal supports only the requested relation, direction, root,
  depth, and result bound. A qualified result keeps its reached bound visible;
  stale or unavailable topology rejects.
</Info>

## Locate slow phases

`kast product inspect` reports the private OTLP JSON Lines file used by ready
endpoints.

Topology and traversal spans identify:

- Snapshot eligibility, reads, and publication.
- Candidate enumeration, extraction, and revalidation.
- Snapshot open and traversal expansion.

Only closed outcomes and non-negative counts are exported. Repository paths and
symbol selectors are excluded.
