The bundled plugin exposes one task MCP server over stdio.
Codex, Copilot, and Pi use the same task catalog.
The client starts the process in the exact repository or worktree.
The server uses the installed Tool RPC without changes to its binary or wire shapes.

## Catalog

`tools/list` supplies each task's name, description, input schema, and effect annotations.
The installed task schema governs the session.

| Task | Purpose |
| --- | --- |
| `find` | Discover declarations with known name, kind, directory or package, and source sets. |
| `callers`, `callees`, `implementations`, `inheritors`, `overrides` | Read one-hop declaration relationships. |
| `references`, `type_uses` | Read individual occurrence evidence. |
| `trace` | Trace the fixed affected-use topology. |
| `walk` | Keep traversal records through an explicit depth. |
| `source` | Read source under an issued reference. The default region is `ANCHOR`. |
| `result`, `resume` | Recover retained results or produced output. |
| `diagnostics` | Read compiler diagnostics for a relative path. |
| `schema`, `raw` | Inspect and call advanced existing operations. |

Raw tool names are not separate tools in this catalog.
For source changes through `raw`, supply `write:true` and preserve the user's authorization.
The installed catalog still admits the underlying request and effect.

Discovery does not prove IDEA readiness or semantic completion.
Use the first useful task instead of a readiness probe.
Read the bundled Kast skill for exact selection, destination scope, source regions, and recovery rules.

## Call and result

`tools/call` selects a task and its input object.
This example finds a declaration in the selected source sets:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "find",
    "arguments": {"name": "OrderRepository", "kind": "interface", "directory": "src", "source_sets": ["main"]}
  }
}
```

The interface kind searches the CLASS family. Examine the returned declaration before an interface claim.
Select the exact owner, signature, receiver, and location before a relationship call.

The reply keeps the original RPC JSON in `content[].text` and its decoded value in `structuredContent`.
The outer RPC `type` remains intact. The document keeps its status, evidence, and recovery fields.
A qualified or rejected RPC outcome sets `isError:true` without removing the document.
Local input, catalog, or process failures use `ACCESS_REJECTED` with their stage and reason.

Decode both the MCP wrapper and the RPC outcome.
A successful exchange does not prove that the semantic answer is complete.
Cancellation stops the child, but submission or effects can remain uncertain. Never retry automatically.
